## Commands

### `tempo_follower.set_enabled`

**Tempo Follower**. Permission: `edit`. Contexts: `global`.

Switches Follow, as the Control Bar's toggle does: on, Beatlayer listens to the audio input channel and the song's tempo follows what it hears, once it is sure of it. The followed tempo becomes the set's tempo, with no undo step of its own, and takes a tempo envelope's place as a hand move does. EXT is switched off and disabled while it's on, MIDI clock out goes on, Link takes the tempo, and Tap Tempo and Phase Nudge are refused. Refused, with the reason, while the input can't be reached, and `on` left out switches to the other state. Follow starts off and isn't kept: it isn't part of the set. `tempo_follower.state` reports it.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `on` | boolean or null | no | Whether it's on; left out, it switches to the other state. |

Result: [`FollowSwitched`](README.md#followswitched).

### `tempo_follower.state`

**Tempo Follower Status**. Permission: `read`. Contexts: `global`.

Reports Tempo Follower: whether Follow is on, whether the Control Bar shows its toggle, the input channel it listens to, whether it can run and, if not, why, the tempo the song follows, the tracker's confidence and beat phase, and how many blocks of input were dropped. Changes nothing. Switch it with `tempo_follower.set_enabled`.

Default keys: none.

Arguments: none (send `{}`).

Result: [`TempoFollowerState`](README.md#tempofollowerstate).
