## The behaviour

Almost every mixer and device control in Live can be automated, including the song tempo: a control whose value changes along the song's timeline is *automated*, and follows a *breakpoint envelope* — a line of breakpoints with straight or curved segments between them, drawn over the track. Automation is what plays while the song runs. Changing an automated control's value by hand takes it back from its envelope: the control keeps the value the hand gave it, until the Control Bar's Re-Enable Automation button, or Re-Enable Automation in the control's own context menu, puts it back under its envelope. Deleting a control's automation leaves the control's value where it is, constant along the timeline.

This spec covers automation in the document, in the engine, and in the Arrangement: which parameters can have envelopes, the edits that change them, what the engine plays while the song runs, what a hand move does, and the Arrangement's automation lanes — showing them with Automation Mode, drawing and dragging breakpoints, and the device and parameter choosers (R13 to R16). The Main track's Song Tempo envelope is [musical time](musical-time.md)'s, with its own commands. Automation *recording* (Automation Arm, and Session clips' automation) comes with Arrangement Record and Session view. A curved segment follows Beatlayer's own law (R12).

## Rules

- **R1.** A track's automation is one envelope per parameter: a control of its mixer (Volume, Pan, or the Track Activator), the level of one of its sends to a return track, or any parameter of a device in its chain; an audio track's can also name a sound setting of its audio clips ([warp-modes.md](warp-modes.md) R28, R31). An envelope is a list of breakpoints, each a position in ticks, a value in the parameter's own units, and the bend of the segment starting at it, in position order and with no two at one position. (S2, S6, S8)
- **R2.** The value between two breakpoints follows the straight line, or the segment's curve when its bend isn't 0 (R12); before the first breakpoint the first one's value holds, and after the last the last one's. (S2, S9)
- **R3.** While the song plays, an envelope drives its parameter: the parameter's value on each frame is the envelope's value for that frame, exactly, so a ramp reaches its target on the frame its breakpoint falls on, and nothing glides. A parameter with no envelope, or one whose envelope is overridden, follows its control. (S1, S4, S6, S8)
- **R4.** An envelope's frames are held back by its node's latency, as a parameter change sent for a song frame is, so automation acts on the audio it is meant for. (S7)
- **R5.** Moving a control that has an envelope by hand turns that envelope off, as one undo step with the move: the control's value overrides the envelope, and the envelope itself stays as it is. `automation.re_enable` turns every overridden envelope in the song back on, and `automation.re_enable_for` turns one parameter's back on; either is one undo step, and neither changes anything when nothing is overridden. A control whose envelope went heads back to what the control asks for. (S1, S6)
- **R6.** `automation.delete` removes all of a parameter's automation — its envelope and every breakpoint on it — and leaves the control's value where it is; the control glides to that value, as it does for any control move (S8). `automation.delete_breakpoint` removes one breakpoint, so the segments either side of it become the one starting at the breakpoint before it (curved by that breakpoint's bend); when it was the last one, the parameter's envelope goes with it. (S1, S3, S6)
- **R7.** Every one of these is a registered command — `automation.set_breakpoint`, `automation.set_curve`, `automation.move_breakpoint`, `automation.delete_breakpoint`, `automation.delete`, `automation.re_enable`, `automation.re_enable_for` — with a schema, a description written for a model, and a permission class, run headless through `Shell::run` with the track and parameter spelled out, and each is one undo step. A position before 1.1.1, a value that isn't a number, a parameter the track doesn't have, a move onto another breakpoint, a bend outside −1 to 1, and a segment that starts at no breakpoint (or at the last one, which has none after it) are refused. (S6)
- **R8.** The Control Bar's Re-Enable Automation button is live, lights while any of the set's automated controls is overridden, and pressing it runs `automation.re_enable`; assistive technology reads its name, its state, and what it does. (S1, S5, S6)
- **R9.** The set saves every envelope: the parameter it drives, its breakpoints with each segment's bend where it isn't straight, and whether it drives the parameter. A set saved before WP-2.12 loads with no automation; an envelope that drives its parameter doesn't write that flag. A loaded envelope that breaks a rule (a position before zero, two breakpoints at one position, positions out of order, a value that isn't a number, a bend outside −1 to 1, or a parameter the track doesn't have) doesn't load. (S6)
- **R10.** The read path on the audio thread allocates nothing, takes no lock, and its work per block is bounded by the block's frames: a node reads each automated parameter's value from the envelope the compiler sent it, frame by frame, and the value depends on the frame alone, so a render is the same in any block size. (S6)
- **R11.** An envelope names a parameter of the track it's on: a device that leaves its track, by being deleted or by moving to another track, loses its envelopes, and nothing else on the track's automation changes. (S6)
- **R12.** A segment is curved by a signed bend, from −1 to 1, stored on the breakpoint at the segment's start; 0 is the straight line. Between the two breakpoints the value is `from + (to − from) · t^(2^bend)`, `t` running from 0 at the segment's start to 1 at its end, so the value always stays between the two breakpoints' values and reaches each at its own position. `automation.set_curve` sets a segment's bend, as holding Alt/Option while dragging the segment does (S3); a bend of 0 straightens it again, as the same drag with a double-click does. The shape is Beatlayer's own law. (S3, S6, S10)
- **R13.** Automation Mode (`arrangement.automation_mode`; A, the button above the track headers, View ▸ Automation Mode; S-ENV-001, M-VIEW-036) shows the arrangement's automation lanes: while it's on, every unfolded track shows its automation lanes — its main lane over its own lane (R24) and the lanes of its own under it (R25) — and an envelope is drawn there as breakpoints joined by straight or curved segments, the vertical axis the parameter's value and the horizontal axis time. Automation Mode is view state: it changes nothing in the set and isn't an undo step. (S2, S5)
- **R14.** Each automation lane shows one parameter, chosen by the lane's device chooser — the track mixer, one of the track's devices, or None — and its parameter chooser, a control of that device: `Volume`, `Pan`, `Track Activator` or a send for the mixer, or one of a device's automatable parameters. `arrangement.show_automation` sets it, as the choosers do; a track's main lane shows its volume until the choosers pick another, and None draws no envelope while the lane and its choosers stay. The choice is view state: it changes nothing in the set and isn't an undo step — except for a plug-in parameter, where choosing one adds it to the device's configured list ([clap-hosting](clap-hosting.md) R5). For a plug-in device the parameter chooser lists the parameters its panel is configured to show, then any temporary entry a parameter moved in the plug-in's own window adds (dropped when another parameter is moved). (S2, clap-hosting R5)
- **R15.** With Draw Mode off (which is all Beatlayer has in the arrangement), an automation lane is edited by mouse, each gesture one of automation's commands and one undo step however many frames its drag lasts (R7): clicking a breakpoint runs `automation.delete_breakpoint`; clicking a segment runs `automation.set_breakpoint` there, at the line's own value, so the segment keeps its shape; double-clicking off a segment runs `automation.set_breakpoint` there at the clicked value; dragging a breakpoint runs `automation.move_breakpoint` to the pointer's position and value, holding Shift for finer values (S-ENV-002) and Cmd (Alt on Windows) to bypass snapping (S-ENV-006); holding Alt/Option while dragging a segment runs `automation.set_curve` with the bend the drag gives, and Alt/Option double-clicking a segment runs `automation.set_curve` with bend 0, straightening it (S-ENV-003). (S3)
- **R16.** ~~Beatlayer gives a lane 43 points and puts its device and parameter choosers in the track header column at the lane's row. Several lanes per track (S5), and Live's overlay of an envelope on the clip lane before it's moved to its own, aren't built; a track has one lane at a time. (S5)~~ Withdrawn: a track's main lane draws over its clips and its other envelopes go in lanes of their own (R24 and R25, WP-6.57).
- **R17.** Automation Arm (`arrangement.automation_arm`; the Control Bar's button beside Arrangement Record, L-CTRL-015) is view state: it changes nothing in the set and isn't an undo step. While it is on and the transport records and plays, moving a control that automation can drive (a track's Volume, Pan, Track Activator or send, or a device's parameter) by any command notes the move at the playhead's position; a run of moves of one control, until its drag is released (or, for a command run alone, until recording stops), is a touch. When recording stops, the touches are written into the envelopes as one undo step, `Record Automation`: each touch replaces the envelope's breakpoints from its first move up to its release with a breakpoint per move, no thinning, and, when the parameter had breakpoints, adds a breakpoint at the release that returns to the old envelope's value there, so the old envelope resumes; with none, the last value written holds. Every envelope written drives its parameter again. With Automation Arm off, or the transport not recording, nothing is noted, unless a Session clip has taken a track over: then moves are noted whether or not Automation Arm is on ([session-to-arrangement](session-to-arrangement.md) R5). A Session recording's moves go into its Session clips, not these envelopes ([session-automation](session-automation.md) R1). (S1, S5, S6)
- **R18.** Arrangement automation recording has three modes: Touch, Live's (R17), the default; Latch; and Write (IMP-23; the names Beatlayer's own). The Automation Arm button's context menu (L-CTRL-015) lists the three in that order, the current one ticked, and choosing one runs `settings.set_automation_record_mode`. The mode is a preference kept between launches, not part of the set and not an undo step, read back by `settings.state` (`automation_record_mode`) and reported by `transport.state` beside Automation Arm. Automation Arm itself, and what it switches, are as R17 says. (S12)
- **R19.** In Latch, a touch starts at a control's first move, as in Touch, but releasing the control doesn't end it: the last value written holds from there until recording stops, replacing the envelope's breakpoints up to the stop, and a later move of the same control carries the touch on. At the stop, when the parameter had breakpoints, the old envelope resumes, its value one tick after the stop. (S12)
- **R20.** In Write, every control moved during a recording is written from where the recording started (the take's first frame: where Arrangement Record started playback, or the punch-in point) to where it stopped: the value the control had when the recording started holds until its first move, then its moves are written, then, as in Latch, its last value holds to the stop, where the old envelope resumes as R19 says. A control not moved keeps its envelope. (S12)
- **R21.** With the Arrangement loop on, when the playhead wraps to the loop's start a Latch or Write touch carries on from there with its last value, writing over what earlier passes wrote, until the control moves again or recording stops. In Touch a wrap ends a touch at its last move, and a move after the wrap starts a new one, as R17's touches do. (S12)
- **R22.** A recording in any mode is one undo step, `Record Automation`, and every envelope it writes drives its parameter again (R17). The mode applies to Arrangement recording only: a Session recording writes its clips' envelopes as [session-automation.md](session-automation.md) R3 and R4 say, whatever the mode. (S11, S12)
- **R23.** The modes add the Automation Arm button's context menu to the interface and nothing else, and with the mode at Touch a recording writes exactly what R17 says. What a mode writes is worked out on the main thread when recording stops, as R17's touches are, so nothing on the audio thread changes. (S12)

**The main automation lane and several lanes per track (WP-6.57)**

- **R24.** With Automation Mode on, each unfolded track's own lane is its main automation lane: it draws the envelope its choosers show over its clips, on the lane's height, with the choosers in the track's header, and that envelope is edited there with R15's gestures and [automation-editing.md](automation-editing.md)'s, its keys included, in the clips' bodies and the space between them; a clip's title bar keeps the clip's own gestures ([arrangement-editing.md](arrangement-editing.md)), as it does with Automation Mode off (the title bars are Beatlayer's own). This replaces R16's single lane under the track: a track's other envelopes go in lanes of their own (R25). (S13, S15)
- **R25.** The lane button in a track's header, or a lane's, moves the envelope its choosers show into an automation lane of its own, added under the track's lanes, which shows it with choosers of its own; the main lane then shows the next parameter in the choosers' order that has an envelope and no lane, or None (Beatlayer's own). With Alt (Windows) or Cmd (Mac) held, the button gives every automated parameter of the track that has no lane a lane of its own, in the choosers' order. The button is hidden while the choosers show None or a parameter that already has a lane. An automation lane is 43 points tall (Beatlayer's own, as R16's was). (S13, S14)
- **R26.** A lane's hide button removes that lane from view, its envelope still driving its parameter; with Alt or Cmd held it removes that lane and every lane after it on the track. Once a track has lanes of its own, a toggle in its header shows or hides them all; with the track's title bar selected, Left hides them and Right shows them, and Left on a selected lane selects the track's own lane and hides its lanes. Lanes and whether they show are kept per track and saved with the set (Beatlayer's own), and none of this is an undo step. (S13)
- **R27.** The device chooser marks with an LED each device, and the mixer, that has automation on the track, and its last entry, Show Automated Parameters Only, switches both choosers to list only automated parameters (view state, per lane; Beatlayer's own scope); the control chooser marks each automated control with an LED. (S13)
- **R28.** Right-clicking a lane's header opens its context menu: Show Automated Parameters Only (ticked while on), Show All Lanes and Hide All Lanes, then Clear All Envelopes, which deletes every envelope of the track, and Clear Envelopes of the device the lane shows, as `automation.clear_track` and `automation.clear_device`, `destructive`, one undo step each, read back by the query tool's track (`automation`). The view items and the order are Beatlayer's own. (S13)
- **R29.** With Automation Mode on, clicking a track's mixer control or one of its devices' parameters shows that parameter in the track's main lane, or selects the lane it already has (S14). A mixer control's or device parameter's context menu holds, after any items of its own (C-PAN, C-XFADE), Delete Automation (`automation.delete`, R6, enabled while the parameter has an envelope), Re-Enable Automation (`automation.re_enable_for`, R5, enabled while its envelope is overridden), Show Automation, which does what a click does and turns Automation Mode on, and Show Automation In New Lane, which gives the parameter a lane of its own as R25 says, or selects the one it has (C-XFADE-008, C-XFADE-009); the order of the first two is Beatlayer's own. (S1, S13, S14, S15)
- **R30.** A time selection covers any of a track's lanes, the main lane among them, and the edit commands and gestures of [automation-editing.md](automation-editing.md) R1 to R19 act on every envelope it covers, several lanes being edited at once (manual 25.5.7, [automation-editing.md](automation-editing.md) R5). Up and Down move the selection through a track's lane and then each of its shown lanes ([automation-editing.md](automation-editing.md) R20). (S13)
- **R31.** Options ▸ Snap Automation to Grid (M-OPT-015), ticked while on, decides whether breakpoints made or moved with the mouse snap to the editing grid: on, as R15 and [automation-editing.md](automation-editing.md) R3 say; off, they land where the pointer is, snapping only to their neighbours' positions, and Cmd (Alt on Windows) makes them snap to the grid for that drag. It's on in a new install, kept between launches (`settings.set_snap_automation_to_grid`, `edit`, read back by `settings.state` as `snap_automation_to_grid`), and isn't an undo step; the editing grid's own Snap to Grid (Cmd-4) still turns all snapping off. What it does, its default and where it's kept are Beatlayer's own. (S13, S15)
- **R32.** The lanes are view commands an agent reaches: `arrangement.show_automation` takes a lane (the main lane or a lane's number); `arrangement.add_automation_lane`, `arrangement.remove_automation_lane`, `arrangement.show_automation_lanes` and `arrangement.show_automated_only` are `read`, as view state; `arrangement.state` reports each track's lanes, their parameters, whether they show, and the filter. (S6)
- **R33.** A set saved before lanes of their own loads with every track showing its main lane only, its choosers on what R14 gave it. (S6)
