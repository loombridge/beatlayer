## Commands

### `arrangement.automation_arm`

**Automation Arm**. Permission: `read`. Contexts: `global`, `arrangement`.

Switches Automation Arm, the Control Bar's button beside Arrangement Record: while it's on and the transport records, moving a control (a track's volume, pan, mute, or send, or a device's parameter) writes its values into that parameter's envelope at the playback position, replacing what was there over the range written, and the envelope resumes where the control is released. The whole recording is one undo step, made when recording stops. Changes only the view until then.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `on` | boolean or null | no | On or off. Left out, the switch toggles. |

Result: [`ArrangementState`](#arrangementstate).

Switches Automation Mode: while it's on, every track shows an automation lane under its lane, with the device and parameter choosers that pick the parameter it shows, and its envelope is drawn and edited there. ### `arrangement.consolidate`

**Consolidate**. Permission: `destructive`. Contexts: `arrangement`.

Joins the material in a range on each selected track into one new clip per track, replacing the clips it covers: the time selection, or the span of the selected clips (`clips`, or `tracks` with `start` and `end`). Clips the range's edges cross are split there first and the parts inside replaced; a track with no clip in the range gets nothing, and the new clips are selected. On an audio track the new clip plays a file rendered offline from what the clips played over the range, before the track's devices and mixer, normalised with the clip gain making up for it, mono when its channels are equal; on a MIDI track it holds every note the range played, with each repetition of a looped clip written out, and the source clips' clip envelopes. Cmd-J (Ctrl-J) and Edit ▸ Consolidate run it on the selection. It's destructive, since it deletes the clips it replaces, so an agent asks first.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-ARR-002 | `Cmd+J` | `Ctrl+J` | `arrangement` | Consolidate the selection into one clip | runs it |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `clips` | array or null | no | Whole clips to act on. Give either `clips` or a span of time, not both. |
| `end` | [`Position`](README.md#position) or null | no | Where the span ends, after `start`. Left out, the time selection's end. |
| `lanes` | array or null | no | The lanes a span of time covers, each a track's own lane or one of its take lanes (the comping spec, R27). Left out, the lanes of the time selection, or `tracks`' own lanes. |
| `start` | [`Position`](README.md#position) or null | no | Where the span starts. Left out, the time selection's start. |
| `tracks` | array or null | no | The tracks a span of time covers. Left out, the selected tracks. |

Result: [`ConsolidateResult`](README.md#consolidateresult).

The result's `scene` is the new scene.

### `arrangement.create_fade`

**Create Fade**. Permission: `edit`. Contexts: `arrangement`.

Makes fades and crossfades from the Arrangement's selection, as Create Fade (Cmd-Option-F) does, on the selected audio clips (`clips`) or the time selection on its audio tracks (`tracks`, `start`, `end`). With a span of time: a clip whose start the span holds, and not its end, gets a fade-in from its start to the span's end; a clip whose end it holds, and not its start, gets a fade-out from the span's start to its end; two audio clips that meet inside the span get a crossfade over it; a clip the span holds whole, or holds neither edge of, is left as it is. With clips, each boundary where two of them meet gets a 4 ms crossfade, 2 ms each side, whatever the Create Fades on Clip Edges setting. Each fade is kept within its clip's limits, so a span longer than a clip allows makes the longest fade there is. One undo step, named Create Fade or Create Crossfade. Refused where the selection gives no fade. Read the result back from the clips' `data` with the query tool: `fade_in`, `fade_out`, their curves, `fade_in_before` and `fade_out_after`.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-ARR-008 | `Cmd+Option+F` | `Ctrl+Alt+F` | `arrangement` | Create a fade or crossfade from the selection | runs it |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `clips` | array or null | no | Whole clips to act on. Give either `clips` or a span of time, not both. |
| `end` | [`Position`](README.md#position) or null | no | Where the span ends, after `start`. Left out, the time selection's end. |
| `lanes` | array or null | no | The lanes a span of time covers, each a track's own lane or one of its take lanes (the comping spec, R27). Left out, the lanes of the time selection, or `tracks`' own lanes. |

### `arrangement.set_crossfade`

Shows or hides the return tracks' rows in the Arrangement's lanes, as View > Arrangement Track Controls > Return Tracks does. Switches unless `on` says which. Changes only the view; the returns play as before, and the mixers' own Return Tracks section is a switch of its own.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `on` | boolean or null | no | On or off. Left out, the switch toggles. |

Result: [`ArrangementState`](#arrangementstate).

### `arrangement.show_take_lanes`

**Show Take Lanes**. Permission: `read`. Contexts: `arrangement`, `take-lanes`.

Shows or hides the take lanes of `tracks` (or the selected tracks) under their main lanes, as the track header's Show Take Lanes item and the Show/Hide Take Lanes toggle do; left without `on`, they toggle. Showing take lanes switches Automation Mode off, which hides them. With `title_bars`, the tracks' title bars are selected too and the take lane headers are let go, as Left does from a take lane's header. Never an undo step; changes only the view.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-COMP-001 | `Cmd+Option+U` | `Ctrl+Alt+U` | `arrangement` | Show the take lanes | runs it |
| S-COMP-007 | `Left` | `Left` | `take-lanes` | Go from a take lane to its track's main lane and fold the take lanes | fixes `on` = `false`; fixes `title_bars` = `true` |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `on` | boolean or null | no | Show (true) or hide (false) their take lanes. Left out, they toggle, taking the first track's new state. |
| `title_bars` | boolean | no | Also select the tracks' title bars and leave the take lanes' headers, as Left does from a take lane's header. |
| `tracks` | array or null | no | The tracks. Left out, the selected tracks. |

Result: [`ArrangementState`](#arrangementstate).

### `arrangement.split`

**Split**. Permission: `edit`. Contexts: `arrangement`.

Splits clips at positions: `clips`, or every clip on `tracks`, at each of `at` that falls inside them. Left out, it splits at the time selection's start and end, or at the insert marker, the selected clips or the clips on the selected tracks, as Cmd-E (Ctrl-E) does. Each part plays exactly what it played before, so the song sounds the same; the parts can then be moved, deleted, or copied on their own. The parts split off are listed in `created`.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-ARR-001 | `Cmd+E` | `Ctrl+E` | `arrangement` | Split the clip at the selection or insert marker | runs it |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `at` | array or null | no | Where to split. Left out, the time selection's start and end, or the insert marker. |
| `clips` | array or null | no | The clips to split. Left out, the clips on `tracks`. |
| `lanes` | array or null | no | The lanes whose clips are split, each a track's own lane or one of its take lanes (the comping spec, R27). Left out, `tracks`' own lanes, or the lanes the time selection covers. |
| `tracks` | array or null | no | The tracks whose clips are split. Left out, the selected clips, or the clips on the selected tracks. |

Result: [`EditResult`](README.md#editresult).

### `arrangement.zoom`

**Zoom Arrangement**. Permission: `read`. Contexts: `arrangement`.

Zooms the Arrangement View's time axis by `factor` around `anchor`: 2 shows half as much time, 0.5 twice as much. The + and - keys zoom by 2 around the selection, the insert marker, or the middle of the view. Changes only the view, never the set; turns Optimize Width off.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-ZOOM-003 | `Plus` | `Plus` | `arrangement` | Zoom the time ruler in | fixes `factor` = `2.0` |
| S-ZOOM-004 | `Minus` | `Minus` | `arrangement` | Zoom the time ruler out | fixes `factor` = `0.5` |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `factor` | number | yes | How much closer to look: 2 shows half as much time, 0.5 twice as much. From 1/64 to 64. |
| `anchor` | [`Ticks`](README.md#ticks) or null | no | The position that stays put on screen. Left out, it's the middle of the time selection if it's in view, otherwise the insert marker if that's in view, otherwise the middle of the view. |

Result: [`ArrangementState`](#arrangementstate).
