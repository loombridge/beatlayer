## The behaviour

MIDI clock keeps a drum machine, a sequencer or another program in time with Beatlayer, or Beatlayer in time with one of them. The host sends a Timing Clock 24 times per quarter note, so its rate is the tempo, and Start, Stop and Continue to run the transport; Song Position Pointer says where in the song to continue from, in sixteenth notes.

Sending: an output port with Sync on gets the clock while the song plays. Each clock is written by the engine for the frame its position falls on, stamped for the moment that frame is heard, and handed to the MIDI output thread ahead of time, so the clock is as steady as the platform's scheduled MIDI output, whatever the block size. Each such port has three options: a sync delay in milliseconds, the clock type (Song, which sends Song Position Pointer and Continue whenever the play position changes, or Pattern, which only sends Start at the next bar), and how a resync is sent when the Control Bar's Resync External Hardware button is pressed.

Following: an input port with Sync on brings the EXT switch to the Control Bar and makes Options ▸ External Sync available. With EXT on, Beatlayer plays at the incoming clock's tempo, estimated from the clocks' arrival times and smoothed against jitter, starts, stops and continues with the host, and locates to its Song Position Pointer, wrapped into the Arrangement loop when the loop is on. Two lamps beside EXT flash for sync received (upper) and sent (lower).

This spec covers MIDI clock in both directions. The ports, their Track, Sync and Remote switches, and the way input reaches the engine are [MIDI I/O](midi-io.md)'s; the scheduled output that carries the clock out is [external devices](external-devices.md) R4 and R5's.

## Rules

### An output's sync options (WP-7.11)

- **R1.** An output port whose Sync switch is on has a disclosure triangle beside its name in the ports table (L-SET-014); open, it shows three rows under the port's row: MIDI Clock Sync Delay (a number box in milliseconds), MIDI Clock Type (a chooser: Song, Pattern) and Hardware Resync (a chooser: Stop and Start, Start Only, Don't Resync). With Sync off the triangle and the rows are gone, and the values are kept. (S3, S12)
- **R2.** The options are kept in the preferences with the port's switches, by direction and name ([MIDI I/O](midi-io.md) R3), so they apply whenever the port is seen. A port seen for the first time starts at 0 ms, Song, and Stop and Start. The delay runs from −100 to 100 ms in steps of 1 ms. They're set through `midi.set_port` (`sync_delay_ms`, `clock_type`, `hardware_resync`) and read back through `midi.ports`. (S3; Stop and Start is the manual's default; the delay's range and the other starting values are Beatlayer's own)

### Sending clock (WP-7.11)

- **R3.** While the song plays, each open output with Sync on receives a Timing Clock at every 24th of a quarter note counted from 1.1.1, each for the frame its position falls on: through the tempo map, so across a tempo change or inside a ramp each clock keeps its own position's frame; or, while Beatlayer follows an outside tempo, through the followed tempo ([transport](transport.md) R24). While the song is stopped no clock is sent. (S1, S2, S11; sending none while stopped is Beatlayer's own)
- **R4.** Every sync message is stamped for the moment its frame is heard at the audio interface's output plus the port's MIDI Clock Sync Delay, and handed to the MIDI output thread ahead of that moment through the scheduled output ([external devices](external-devices.md) R4, R5), never from a timer: the clock's spacing is the output backend's scheduling accuracy, whatever the block size. A negative delay sends the message earlier than its frame is heard; the engine writes messages that far ahead, using the tempo it plays at, so none is stamped for a moment already past. A message that is late all the same is sent at once and counted ([external devices](external-devices.md) R5). (S3, S10, S13)
- **R5.** With MIDI Clock Type Song: a start at 1.1.1 sends Start, then the first clock on 1.1.1's frame. A start anywhere else, and Continue Playback, send a Song Position Pointer naming the first sixteenth note at or after the position, then Continue, then the first clock on that sixteenth's frame. While the song plays, every change of the play position (a locate, a jump to a locator, a quantised jump, the Arrangement loop's wrap) does the same at the frame of the change. While stopped, a move of the insert marker sends the Song Position Pointer alone. Stop sends Stop. A position past the pointer's 14-bit range sends its highest value, 16,383 sixteenths. (S3, S11; the rounding to the next sixteenth and the range are Beatlayer's own)
- **R6.** With MIDI Clock Type Pattern: no Song Position Pointer or Continue is sent. A start sends Start at the next bar line at or after where playback starts, just before that bar line's clock; clocks run from the start of playback. A change of the play position while playing sends nothing. Stop sends Stop. (S3; jumps sending nothing is Beatlayer's own)
- **R7.** Messages for one frame leave in the order R5 and R6 give them (Song Position Pointer, then Start or Continue, then the clock), with the same stamp. (S11; Beatlayer's own)
- **R8.** During a count-in ([metronome](metronome.md) R5) nothing is sent; Start or Continue go out where the transport starts after it. (Beatlayer's own)
- **R9.** Clock out follows whatever tempo the song plays at: the tempo map's, an incoming clock's with EXT on, or a Link session's ([Link](link.md) R3), and is sent while EXT is on and while Tempo Follower is on. (S8)

### Resync (WP-7.11)

- **R10.** Show Resync Button, a switch in the second section of Settings ▸ Tempo & MIDI (L-SET-014), off on a new install and kept in the preferences, shows the Resync External Hardware button in the Control Bar while it's on. (S3, S12; off at first is Beatlayer's own)
- **R11.** The button, and `transport.resync_external_hardware`, send each open output with Sync on its own Hardware Resync choice: Stop and Start sends Stop then Start; Start Only sends Start; Don't Resync sends nothing. While the song plays they go out at the next bar line, just before that bar line's clock, so the hardware starts again in step on the bar; while it's stopped the button does nothing. (S3; the bar line and doing nothing while stopped are Beatlayer's own)

### The sending lamp, and real time (WP-7.11)

- **R12.** The lower of the sync lamps beside EXT (R15) lights for 100 ms each time a quarter note's clock (every 24th) leaves for a port; `sync.state` reports it whether or not the lamps show. (S2, S7; the 100 ms is Beatlayer's own)
- **R13.** Clock messages are written on the audio thread into the queue to the MIDI output thread without allocating, locking or blocking; a full queue drops the message and counts it. An offline render sends no clock ([external devices](external-devices.md) R8). (S13)

### Receiving clock (WP-7.12)

- **R14.** An input port with Sync on and MIDI Sync Type MIDI Clock ([MIDI Timecode](midi-timecode.md) R1) sends its Timing Clock, Start, Continue, Stop and Song Position Pointer messages to sync, never to tracks ([MIDI I/O](midi-io.md) R5, R9), each stamped on the MIDI system's thread with its arrival time and carried to the audio thread on a lock-free queue, as track input is ([MIDI I/O](midi-io.md) R13 to R15). Its Sync Delay (a number box in milliseconds, −100 to 100, 0 for a port seen for the first time, in the input's own sync options under a triangle as R1's) is kept and set as R2's are, with `midi.set_port`'s `sync_delay_ms`. (S5, S6; the range is Beatlayer's own)
- **R15.** While any input has Sync on, the Control Bar shows the EXT switch, in the tempo group at its left, with the pair of sync lamps beside it, the upper for sync received and the lower for sync sent (R12); Options ▸ External Sync (M-OPT-007) is enabled and ticked while EXT is on. Both run `transport.set_external_sync`. Whether EXT is on is kept in the preferences. With no input on Sync, EXT and its lamps are hidden, the menu item is disabled, and EXT is off. While Tempo Follower is on, EXT and External Sync are disabled. (S5, S7, S8, S12; keeping it in the preferences and the place in the tempo group are Beatlayer's own)
- **R16.** The upper lamp lights for 100 ms each time a quarter note's worth of clocks (every 24th since the last Start, Continue or Song Position Pointer, or since clocks began) arrives at a sync input, whether EXT is on or not. Clocks that R18 sets aside don't count. (S5, S7; the 100 ms is Beatlayer's own)

### Following an incoming clock (WP-7.12)

- **R17.** With EXT on, Beatlayer plays at the incoming clock's tempo instead of the tempo map's ([transport](transport.md) R24): the Tempo field (L-CTRL-005) shows it, to two decimals, and can't be changed while clocks arrive; tempo automation isn't played and stays in the set as it is; every clip tempo leader plays as a follower ([warping](warping.md) R55). With several sync inputs, the first that delivers usable clocks after EXT goes on leads until it falls silent (R21). (S5, S8, S9; the choice among inputs is Beatlayer's own)
- **R18.** The tempo comes from the clocks' arrival times, smoothed so that jitter in their arrival doesn't reach the tempo. Beatlayer fits the clocks' times against their count with a second-order loop, as the engine's block clock does ([MIDI I/O](midi-io.md) R16), whose bandwidth follows the tempo (one tenth of the quarter-note rate). A clock arriving less than half or more than one and a half of the expected interval after the one before is set aside as a glitch: counted, not fitted, and the count of clocks advanced by as many 24ths as its time gives. The results a test checks: from clocks at a steady 120 BPM with each arrival moved at random by up to ±1 ms, the followed tempo is within 0.1 BPM of 120 after two quarter notes and the Tempo field's two decimals change by no more than 0.05 BPM from one second to the next; after a step from 120 to 130 BPM it's within 0.5 BPM of 130 after one quarter note; through a ramp from 120 to 140 BPM over eight bars it's never more than 1 BPM from the incoming rate after the first two quarter notes. (S10; the method and every number are Beatlayer's own)
- **R19.** Beatlayer follows the clock's position, not only its tempo: while it plays, its song position at each clock is the position of the last Start, Continue or Song Position Pointer plus a 24th of a quarter note per clock since. Where the two differ, it closes the difference by playing each block up to 2 % faster or slower than the followed tempo, and jumps to the clock's position only when they differ by more than a sixteenth note. (S5; the numbers are Beatlayer's own)
- **R20.** Placement: each sync message counts at the moment it arrived plus the input's Sync Delay, and Beatlayer places its own playback so that the frame for a clock's position is heard at that moment: it makes up for its own fixed latency (the block that input waits for, [MIDI I/O](midi-io.md) R15, and the audio interface's output latency) by playing ahead on the followed tempo. A positive Sync Delay makes Beatlayer's playback later against the clock, a negative one earlier. (S6; making up for Beatlayer's own latency is Beatlayer's own)
- **R21.** With no usable clock for 500 ms, the clock counts as silent: the upper lamp stays dark, and a playing song plays on at the last followed tempo until clocks come again, when R19 follows their position from where Beatlayer is. (Beatlayer's own)

### Start, stop and song position from the host (WP-7.12)

- **R22.** With EXT on: Start plays from 1.1.1, from the frame R20 gives the first clock after it; Continue plays from the song position, as Continue Playback does ([transport](transport.md) R6), from the first clock after it; Stop stops, keeping the position, as Stop while playing does ([transport](transport.md) R3). A Song Position Pointer while stopped locates there, moving the insert marker and the song position ([transport](transport.md) R7); with the Arrangement loop on, a position at or past the loop's end is wrapped into it (the loop's start plus the distance past the start, modulo the loop's length), and a position before the loop's start is taken as it is. With EXT off, these messages only light the lamp. (S5, S11; positions before the loop and the wrap's arithmetic are Beatlayer's own)
- **R23.** With EXT on, Beatlayer's own Play, Stop and Continue Playback still act on its transport, at the last followed tempo, or the set's own before any clock has come; the host's next Start, Continue or Stop takes over again. (Beatlayer's own)
- **R24.** Switching EXT off (or the last sync input off) plays on from the next block at the tempo the map gives at the play position, keeping the song position's beat ([transport](transport.md) R26); tempo automation plays again and the clip tempo leaders lead again. (S5)

### Commands, readback and assistive technology (WP-7.11, WP-7.12)

- **R25.** Every action is a registered command with a schema, a description and a permission class, run by ID through the agent API: `transport.set_external_sync` (`edit`, as a kept preference), `transport.resync_external_hardware` (`read`, as the transport's commands are: it changes nothing in the set or on disk), `midi.set_show_resync_button` (`edit`, a preference), and `midi.set_port`'s sync options (`external`, as the switches are). `sync.state` (`read`) reports whether EXT is available and on, the leading input, whether usable clocks arrive, the followed tempo, whether clock is being sent, both lamps, and the counts (clocks received, set aside as glitches, sent, sent late); `transport.state` reports `external_sync`. Each command that isn't `read` names its readback. (S13)
- **R26.** Estimating the tempo and following it run on the audio thread over a fixed number of past clocks held in storage made with the engine, without allocating, locking or blocking. (S13)
- **R27.** In the accessibility tree the EXT switch is a switch named External Sync, its state on or off; the Resync External Hardware button a button of that name; the sync lamps two indicators named Sync Input and Sync Output, their value lit or dark. (Beatlayer's own names, but External Sync and Resync External Hardware, which are the manual's)
- **R28.** Tempo Follower, when it comes, turns EXT off and disables it while it's on; clock out goes on. (S8)
