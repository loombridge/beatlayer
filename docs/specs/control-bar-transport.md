# The Control Bar's transport: Play, Stop, and the position, loop, tempo, and time-signature fields

- **Status:** partial (R1 to R23 each have a passing test; the Link and EXT parts of R20 and R21 come with their own packages; R24 to R26 are WP-9.13's)
- **Work packages:** WP-1.18; WP-7.31 (Tap Tempo and Start Transport With Tap Tempo, R18 to R23); WP-9.13 (the Tempo Follower toggle, R24 to R26)
- **Parity-matrix row:** Views and workflow: Control Bar, Status Bar; Interface placement and key bindings
- **Checked against:** Live 12.4.3, through the UI parity reference recorded on 10 October 2026, and the Live 12 reference manual as that reference and [transport.md](transport.md) record it; for R18 to R23, the Live 12 reference manual (online edition), read 23 October 2026 (chapter 2, section 2.3.9; chapter 9, section 9.1.2; chapter 36, section 36.17; chapter 42, section 42.20).

## The behaviour

The Control Bar's transport section is where a person drives the transport that WP-1.5 built in the engine ([transport.md](transport.md)): Play and Stop, the Arrangement Position fields that show and move the play position, the Loop Start and Loop Length fields and the Arrangement Loop switch between them, and, in the tempo group at the left, the Tempo field and the time signature's numerator and denominator. The Playback menu and the space bar reach the same transport, and so does an agent: every control runs a registered command, and the app runs those commands on the engine it plays the set through, so a click, a key, a menu item, and an agent's call reach one implementation.

The fields behave as Live's value fields do: click one and type a number, or drag it up and down, or step it with the arrow keys; Delete and a double-click put back the default. A bar-beat-sixteenth value is three fields, and Period moves from one to the next while typing, so typing 3, Period, 3, Period, 1 and Return puts the insert marker at 3.3.1. The tempo and time signature are the song's, so changing them is an undoable document edit, one undo step each; the loop brace is the set's too (transport R16). The Arrangement draws the playhead the engine plays, and Follow keeps it in view.

The Tap Tempo button, at the left of the tempo group, sets the tempo from taps: tap it once a beat and the tempo follows from the second tap on, more steadily the longer the taps go on. With Start Transport With Tap Tempo on (a setting on the Record, Warp & Launch page and in Playback ▸ Options), taps while the song is stopped also start it: a bar of taps, four in 4/4, counts the song in, and playback starts at the tapped tempo where the next tap would fall. The button can be key- and MIDI-mapped like any button, so a footswitch can tap.

This spec covers the section's controls, the Playback menu's transport items, and how the app runs the engine behind them. The transport's own rules (what Play, Stop, Continue, a locate, and the loop do, on which frame) are [transport.md](transport.md)'s; the Arrangement View's drawing of the playhead and Follow's paging are [arrangement-view.md](arrangement-view.md)'s (R10, R13). It leaves to other packages: Arrangement Record, MIDI Arrangement Overdub, Automation Arm, Re-Enable Automation, Session Record, Punch-In and Punch-Out (Phase 2 and M3), the metronome (WP-2.15), the Quantization Menu and the scrub area (I-CLICK-012), which starts playback from a click with jumps during playback quantised by the global launch quantisation, so that until the Quantization Menu (L-CTRL-010) arrives in M3 a click there only resumes Follow (arrangement-view R10), tempo and time-signature changes along the arrangement (WP-2.20), and device interruptions (WP-1.13).

## Rules

- **R1.** Play (L-CTRL-014) runs `transport.play`: playback starts from the insert marker, and while the song plays it starts again from there (transport R1, R11). The button is lit while the song plays. (S1, S7)
- **R2.** Stop runs `transport.stop`: while playing it stops, keeping the play position; while stopped it returns the insert marker and the play position to 1.1.1, so a double-click stops and returns (transport R3, R4). (S1, S7)
- **R3.** Space runs `transport.play_stop` wherever the main window has the keyboard, the Control Bar included, except while a value is being typed (R10); the Playback menu's first item runs it too and reads Stop while the song plays and Play while it's stopped. Shift-Space, Option-Space (Ctrl-Space), Cmd-Shift-Space (Ctrl-Shift-Space), and Home run Continue Playback, Play From Insert Marker, Move Insert Marker To Playhead, and a locate to 1.1.1 as transport R19 binds them, and the Playback menu's items run the same commands. Return Play Position to 1.1.1 runs `transport.return_to_start`, a locate to 1.1.1 with no key of its own, as the menu shows none. (S2, S7)
- **R4.** The Arrangement Position fields (L-CTRL-013) show the bar, beat, and sixteenth of the playhead while the song plays and of the insert marker while it's stopped, by the song's time signatures, from 1.1.1 with no bar 0. Changing them runs `transport.locate` with the new position: the insert marker moves there, and while the song plays, playback jumps there (transport R7). (S1, S7)
- **R5.** The Loop Start fields (L-CTRL-016) show where the loop brace starts, as a bar, beat, and sixteenth; the Loop Length fields (L-CTRL-018) show its length as bars, beats, and sixteenths counted from 0 (a new set's reads 4.0.0), in the time signature at the brace's start. Changing either runs `transport.set_loop` with the new start and the length kept, or the new length and the start kept; the length never goes below a sixteenth. The Arrangement Loop switch runs `transport.set_loop_enabled` with the other state, and shows the set's. Each change is one undo step (transport R16, R17). (S1, S7)
- **R6.** The Tempo field (L-CTRL-005) shows the tempo where the Arrangement Position fields are, in BPM with two decimals. Changing it runs `song.set_tempo` with one constant tempo, from 20 to 999 BPM to the hundredth; each change is one undo step. While the song has tempo changes (WP-2.20), the field shows the tempo but can't set one over them. (S1)
- **R7.** The time signature is two fields (L-CTRL-007): the numerator, from 1 to 99, and the denominator, 1, 2, 4, 8, or 16. Changing either runs `song.set_time_signatures` with one signature throughout, keeping the other field's value; each field's edit is its own undo step. While the song has signature changes, the fields show the signature in force at the position (the playhead while the song plays, the insert marker while it's stopped), and changing either runs `song.set_time_signature_change` on the marker in force there; they show an automation LED in their upper left corner ([time-editing.md](time-editing.md) R33). (S1)
- **R8.** A value field steps by one unit of what it shows (a bar, a beat, or a sixteenth; 1 BPM; 1 for the numerator; the next allowed denominator) when Up or Down is pressed with the field focused, or a screen reader increments or decrements it; Shift with Up or Down steps the tempo by 0.01 BPM (the other fields have no finer unit). Dragging a field up or down steps it once every 3 points, in fine steps with Shift held, and a drag is one undo step however far it goes. Delete, or a double-click, returns the field's value to its default: 1.1.1 for the position and the loop's start, four 4/4 bars for the loop's length, 120 BPM, and 4 for either half of the signature. (S3, S4)
- **R9.** A digit typed into a focused field starts a typed value, which the field shows. Period or Comma moves on to the next field of a bar-beat-sixteenth value, and in the Tempo field is the decimal point; Backspace takes back the last character; Return sets the value, taking any of the value's fields not typed into from what they show; Esc drops it, and so does the focus leaving the value's fields. A typed value out of range is brought into range: a bar of 1 or more, a beat and a sixteenth that exist in that bar, a length of at least a sixteenth, a tempo from 20 to 999, a numerator from 1 to 99, and the largest allowed denominator at or below the one typed. (S1, S3)
- **R10.** While a value is being typed, the keys go to the field: the only shortcuts that run are a text field's, so Option-2 (Alt-2) types 2 and Space doesn't play. (S6)
- **R11.** Every control in the section is in the accessibility tree with a role, a name, and a value: the fields are spin buttons with their value, the whole value they're part of in their description, and increment and decrement for screen readers; Play is a button whose value says whether the song plays; Stop a button; the Loop switch and Follow toggles. Option-0 (Alt-0) moves the keyboard focus to the Control Bar, and with Use Tab Key to Move Focus on, Tab and Shift-Tab reach every control in the section; Return presses a focused button or switch. Capture MIDI is live: it runs `midi.capture` and is disabled until a note has been played ([capture MIDI](capture-midi.md) R1). Arrangement Record, MIDI Arrangement Overdub, Automation Arm, Session Record, and the Metronome are drawn in place, disabled, and say which package or milestone brings them; Tap Tempo is live (R18 to R23). Re-Enable Automation is live (the [automation](automation.md) spec, R8), and Punch-In and Punch-Out are live switches that run `transport.set_punch_in` and `transport.set_punch_out` ([recording](recording.md) R9). (S1, S5)
- **R12.** Every control in the section runs a registered command, so an agent reaches each through the agent API with the same effect: `transport.play`, `transport.stop`, `transport.locate`, `transport.set_loop`, `transport.set_loop_enabled`, `song.set_tempo`, `song.set_time_signatures`, and Follow's `arrangement.follow`. `transport.state` (read) reports what the section shows: whether the song plays, the play position and the insert marker in ticks and as the Arrangement Position fields read, the loop, the tempo and time signature, and whether the engine runs. (S9)
- **R13.** The app plays the set through the engine on the audio device: the shell registers the engine's transport commands and sends them to it, and sends the engine the document after every change, so it plays the set's tempo, loop, and tracks. While the audio engine is off, or no device is open, the transport's commands are refused with the reason, and the menu items that run them are disabled. The audio callback that runs the engine allocates nothing, takes no lock, and blocks on nothing. (S7, S9)
- **R14.** Before drawing each frame, the window takes the playhead the engine last published (transport R20), so the Arrangement's playhead and the Arrangement Position fields show where the engine was when the frame began: behind it by at most the frame's own time and an audio block. While the song plays the window draws every frame, and Follow pages the view with the engine's playhead (arrangement-view R10). (S7, S8)
- **R15.** The insert marker is the engine's. A click in the Arrangement, or a time selection there, moves it (arrangement-view R12) without moving the playhead, so playback carries on; every move of the engine's insert marker (the position fields, Home, a second Stop, Move Insert Marker To Playhead, an agent) moves the one the Arrangement draws. (S7, S8)
- **R16.** A new or opened set starts stopped at 1.1.1. When the audio device closes and opens again (a change on the Audio page, the engine switched off and on), the engine starts again with the set, the play position, and the insert marker where they were, stopped. (WP-1.13 handles interruptions)
- **R17.** `transport.state` also reports the record and punch state the Control Bar shows, which the set saves only in part: Arrangement Record (`arrangement_record`), whether a take is running (`take_running`: past the count-in and any punch-in point, until the punch-out point or the end of recording), whether the count-in is sounding (`counting_in`), Punch-In and Punch-Out, MIDI Arrangement Overdub, Automation Arm, the metronome, the recording under way (`recording`: its armed tracks and the frames dropped so far) and what the last recording came to (`last_recording`, recording R14). Every `transport.set_*` setting reads back there. The engine publishes `take_running` and `counting_in` with its other state each block, with nothing allocated or locked.
- **R18.** Tap Tempo (L-CTRL-004) taps on the mouse press, as a key or MIDI note mapped to it taps on its press, and each tap runs `transport.tap_tempo`. Taps make a run: a tap more than 3 seconds after the run's last (a beat at 20 BPM, the slowest tempo) starts a new run, and a tap less than 60 ms after it (a beat faster than 999 BPM) is ignored, as a bounce (both Beatlayer's own). Each tap is one beat of the time signature where the song is (a quarter note in 4/4, an eighth note in 6/8; Beatlayer's reading of the manual's once a beat). From a run's second tap on, every tap sets the song's tempo at once to the mean of the run's last eight intervals or fewer (Beatlayer's own), in quarter notes per minute as the Tempo field shows it (R6), to the hundredth and within 20 to 999 BPM. (S10, S11)
- **R19.** A tap's moment is the frame of the engine clock it came on: a click's, the moment the window received it, taken onto the engine clock as MIDI input is ([MIDI I/O](midi-io.md) R16); a mapped MIDI message's, its own timestamp. The intervals are measured between those frames, so the time a tap takes to reach the main thread doesn't change the tempo. (S10, S12; Beatlayer's own)
- **R20.** Start Transport With Tap Tempo is kept in the preferences, on in a new install, and switched by the Record, Warp & Launch page's row (L-SET-018) and by Playback ▸ Options ▸ Start Transport With Tap Tempo (M-PLAY-006c), ticked while on; both run `settings.set_start_transport_with_tap_tempo`. With it on and the song stopped, the tap that makes the run as many taps as the numerator of the time signature at the start position (four in 4/4, three in 3/4) starts the transport one beat after itself at the tapped tempo, on the frame where the next tap would fall, as Play does from where Play starts (the insert marker or the song start time, [transport.md](transport.md) R1, R21), so the run counts the song in. A Stop before that frame cancels the start; taps after it, until the song plays, keep setting the tempo and leave the start where it is. With it off, or while the song plays, taps only set the tempo. With Link on and another peer, the start waits for the session's phase as [Link](link.md) R7 and R9 say. (S10, S11, S12; starting one beat after the last tap is Beatlayer's own reading)
- **R21.** A run of taps is one undo step, named Tap Tempo, which holds the tempo of its last tap: each tap of a run amends the step while it's the newest one, and a tap after any other step starts a new one. The tempo is the song's, saved with the set, and goes to a Link session as [Link](link.md) R3 says. While the song has tempo changes (R6) or an incoming clock leads ([MIDI clock](midi-clock.md) R17), the button is disabled and says why, and `transport.tap_tempo` is refused with the reason. (S10, S12; the undo step is Beatlayer's own)
- **R22.** `transport.tap_tempo` (`edit`, since it changes the set's tempo) takes an optional `at`, the tap's frame on the engine clock, and taps now without one; its result gives the run's taps, the tempo it set (none after the first tap) and the frame a start waits for, if one does. `transport.state` reports the same under `tap_tempo` (the run's taps, its tempo, and `start_at`) beside the tempo it shows (R12), and `settings.state` reports `start_transport_with_tap_tempo`; `settings.set_start_transport_with_tap_tempo` (`edit`, a kept preference, not an undo step) reads back there. A run ends for `transport.state` when a new one would start (R18). (S9)
- **R23.** The Tap Tempo button is in the accessibility tree as a button named Tap Tempo, its description the run's tempo once it has one; Return presses it when it has the keyboard focus. It shows pressed while the mouse holds it. Live binds no key to it, and Beatlayer binds none (S12); it is key- and MIDI-mappable as a button ([map modes](map-modes.md) R11). (S10, S11, S12)

- **R24.** The Tempo Follower toggle (L-CTRL-003) sits in the tempo group after the Link toggle and before Tap Tempo, and shows only while Settings' Show Tempo Follower Toggle is Show ([tempo follower](tempo-follower.md) R1, R2). It reads Follow, is lit while Tempo Follower is on, and a click runs `tempo_follower.set_enabled`. (S13)
- **R25.** While Tempo Follower's input can't be reached, the toggle is greyed out and a click does nothing; its hover text and its description give the reason ([tempo follower](tempo-follower.md) R4). While it's on, the Tempo field shows the followed tempo and stays editable, a typed tempo being replaced by the next followed one. (S13; the Tempo field's behaviour is Beatlayer's own)
- **R26.** In the accessibility tree the toggle is a switch named Tempo Follower, its value on or off, its description the followed tempo or the reason it's greyed out; Return switches it with focus. (S13; the name is Beatlayer's own)
