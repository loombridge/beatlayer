## The behaviour

An audio clip's Warp switch decides how it meets the set's tempo. Off, it plays at its file's own speed, whatever the tempo, as every clip has played so far ([audio-clips.md](audio-clips.md) R2). On, it follows the set's tempo: its warp markers pin points in its file to beats, the audio between two markers is stretched or squeezed to fill the beats between them, and the song's tempo map turns those beats into time. A warped clip's Start and End markers and loop brace are beats, as a MIDI clip's are, and only a warped audio clip can loop. The warp mode decides how the audio is stretched (Re-Pitch changes its pitch with its speed; the others keep the pitch), and is [warp-modes.md](warp-modes.md)'s; this spec says which point of the file plays at each moment and how fast it runs.

Beatlayer analyses each file once, in the background, and keeps the result by the file's content hash in its own cache folder: its transients, which the Sample Editor shows as markers and offers as pseudo-warp markers, and its tempo and beats. When a file becomes a clip, the Record, Warp & Launch settings decide whether it's warped and looped, and auto-warp places its markers from that analysis. Commands in the Sample Editor's context menu fix what auto-warp guessed: Set 1.1.1 Here, the four Warp From Here commands, and Warp as x-Bar Loop. Quantize moves warp markers to the grid. An Arrangement clip can lead the set's tempo instead of following it, and Shift-dragging a warped clip's edge stretches it.

This spec covers the warp map and its commands in the document, how a clip player follows it through the tempo map, the analysis and its cache, transients and pseudo-warp markers, auto-warp and its settings, the warp commands, tempo leaders and followers, stretching in the Arrangement, audio quantise, and the warp map a browser preview plays through. It leaves to [warp-modes.md](warp-modes.md) the warp modes and their settings, clip Transpose and Detune, and the RAM and HiQ switches; to [audio-clip-editing.md](audio-clip-editing.md) Reverse, Crop and Consolidate; to [sample-editor.md](sample-editor.md) how the Sample Editor and the Audio Utilities panel draw all this and which mouse gestures and keys run its commands; to [browser.md](browser.md) when and how the browser previews; to [freeze-and-bounce.md](freeze-and-bounce.md) and [slice-to-midi.md](slice-to-midi.md) freezing, bouncing and slicing; and Render as Loop to export (WP-4.17).

The warp map is the clip's data, not a parameter: its markers and tempo are edited by command and saved with the set, one undo step per edit, and they aren't automated. Rule G2 applies to the warp modes' settings, which [warp-modes.md](warp-modes.md) makes automation and clip-envelope targets (WP-4.8). Analysis, decoding and building each clip's mapping happen off the audio thread, and the audio thread plays warped clips without allocating, locking or blocking.

## Rules

**The warp map in the document (WP-4.1)**

- **R1.** Every audio clip has a Warp switch (`clip.set_warp`, `edit`, one undo step, saved with the set, read back in the query tool's `clip` at `data.audio.warp`, with the map in `data.audio.warp_markers` and `data.audio.tempo` and the clip's own time signature in `data.audio.signature`). Off, the clip plays as [audio-clips.md](audio-clips.md) R2 says, at its file's own speed. On, it follows the set's tempo through its warp map (R12). A clip in a set saved before warping existed opens with Warp off and plays exactly as it did. (S1, S15)
- **R2.** A warped clip's warp map is a list of warp markers and the clip's tempo. Each marker pairs a time in the file (seconds, from 0 to the file's length) with a beat in the clip's contents (ticks, counted from the clip's 1.1.1, so a beat before it is negative); markers are in increasing order of both, no two share either, and a warped clip has at least one. Between two neighbouring markers the file's time maps to beats in a straight line, and that segment's tempo is the beats it spans per minute of the file it spans. After the last marker the file runs at the clip's tempo; before the first it runs at the first segment's tempo, or at the clip's tempo when there's only one marker. The clip's tempo is a tempo the tempo map accepts, 1 to 1,000 BPM. (S2, S5; the map past its first and last markers is Beatlayer's own)
- **R3.** Switching Warp on for a clip that has no warp map gives it the map auto-warp makes for its file, whatever the settings say, when the file's analysis is ready and finds a loop in a short sample (R32, R34) or beats in a long one (R35); otherwise it gets one marker at its Start marker on the clip's 1.1.1, with the set's tempo at the clip's start as the clip's tempo, so it goes on playing at the speed it did. Switching Warp off keeps the map in the clip, and switching it on again brings it back. Either way the clip keeps its place and length on the timeline. (S1; Beatlayer's own)
- **R4.** A warped clip's Start and End markers and loop brace are beats in its contents, shown in bars, beats and sixteenths; an unwarped clip's are seconds in its file ([audio-clips.md](audio-clips.md) R3). Switching Warp converts them through the warp map, to the nearest tick when it goes on and exactly when it goes off, so each keeps its place in the audio. `clip.set_region` and `clip.set_loop` take positions in the form the clip shows and refuse the other form: their `ticks` argument says which form the caller means (false, the default, for seconds in the file; true for the ticks of a warped clip's contents), and must match the clip. A warped clip's positions are whole numbers of ticks. A warped clip carries a time signature of its own, the Clip View's Signature fields, as a MIDI clip does: none set means the song's signature at the clip's start. (S11, S15)
- **R5.** A warped clip's contents play as a MIDI clip's do: its Start marker's beat falls at the clip's start, and each tick after it plays the next tick of its contents, into its loop brace and round it while the loop is on, wrapping exactly in ticks. Trimming its left edge or splitting it moves its Start marker by the ticks the edge moved, wrapping inside the brace by whole lengths of it, so each part plays exactly what the whole did ([audio-clips.md](audio-clips.md) R16's warped case). (S11, S15)
- **R6.** `clip.insert_warp_marker` adds a marker at a beat of the clip's contents, at the file time the map already places there, so nothing moves; or at a time in the file, on the beat the map places it. A marker is named by its place in the map, the first being 0. Inserting where a marker is already changes nothing. (S2)
- **R7.** `clip.move_warp_markers` moves the named markers by the same number of ticks, each keeping its time in the file, so the audio either side of each stretches or squeezes to fit. `clip.shift_warp_marker` moves one marker's time in the file, keeping its beat, which moves the waveform under it. A move is refused, changing nothing, if a marker would pass or reach a neighbour that isn't moving with it, or leave the file. Moving the last marker's beat sets the clip's tempo to the new last segment's, so the audio after it carries on at the speed the segment before it has. (S2, S3, S6)
- **R8.** `clip.delete_warp_markers` deletes the named markers: the segments either side of each join into one straight segment between its neighbours. A deleted last marker leaves the audio after the new last one at the clip's tempo. Deleting a warped clip's only marker is refused. (S2; what follows a deletion at either end is Beatlayer's own)
- **R9.** The BPM field (`clip.set_segment_bpm`) shows and sets a segment's tempo. With a marker named, it is the segment that starts at it: a new tempo moves every later marker by the same number of ticks, so that segment alone changes and every later one keeps its tempo; for the last marker it is the clip's tempo. With no marker named, it shows the first segment's tempo (the clip's tempo when there's one marker), and a new tempo scales every segment's tempo and the clip's by the same factor, as ×2 and ÷2 do (R10). (S5; which segment the field shows, and how a new tempo reaches the markers, are Beatlayer's own)
- **R10.** ×2 and ÷2 (`clip.scale_tempo` with a factor of 2 or 0.5, or any factor the BPM field's scaling gives) multiply every segment's tempo and the clip's by the factor: each marker's distance in ticks from the first marker is multiplied by it (a segment's tempo is the beats it spans per minute of the file, R2, so a doubled tempo spans twice the beats), and the clip's Start and End markers and loop brace move with them about the first marker, so each keeps its place in the audio. The clip's place and length on the timeline don't change. (S5; the scaling about the first marker is Beatlayer's own)
- **R11.** Every warp map edit is one undo step, saved with the set, and read back in the query tool's `clip` at `data.audio.warp`; a warp field is written only when it differs from an unwarped clip's, so older sets load unchanged. The marker commands (`clip.insert_warp_marker`, `clip.move_warp_markers`, `clip.shift_warp_marker`, `clip.delete_warp_markers`) take a list of clips, `clips`: with more than one, every clip's file must be as long as the others' (the app shell checks it, since the document holds no media), and the edit is made to each in the same step, or to none if it's refused for one. A marker can't be put or shifted past the end of its file either, which the shell checks too. The marker edits, the BPM field and ×2 and ÷2 refuse an unwarped clip. (S5, S18; reading "the same length" as files of the same length is Beatlayer's own)

**Warped playback (WP-4.2)**

- **R12.** At each song frame a warped clip plays, the file position it plays is found from the song's tempo map and its warp map: the frame's tick (the tempo map), the contents beat at that tick (R5), the time in the file at that beat (the warp map), at the engine's rate. The player follows that position to within a hundredth of a frame wherever the tempo is constant or ramps (Beatlayer's own tolerance), and its rate — file frames per song frame — is what the clip's warp mode renders at ([warp-modes.md](warp-modes.md)): a segment whose tempo equals the set's runs at a rate of 1. (S1, S15, S18)
- **R13.** A warped clip keeps its beats where they are when the tempo changes: a new tempo, a ramp or tempo automation moves its audio with the beats, and its start and end stay on their ticks. A loop warped at 90 BPM plays every one of its bars on the song's bar lines at 120 and at 140 BPM. (S1, S15)
- **R14.** Only a warped audio clip loops: `clip.set_loop_enabled` refuses to switch an unwarped audio clip's loop on, in the Arrangement and in a slot, and switching a looped clip's Warp off switches its loop off in the same undo step. A looped unwarped clip from a set saved before warping existed keeps its loop and plays as it did; its loop can be switched off, and comes back on only with Warp. (S11; the older sets' clips are Beatlayer's own)
- **R15.** A launched warped Session clip plays its Start marker's beat on its launch frame ([launch-quantisation.md](launch-quantisation.md) R9) and runs on at the set's tempo, its loop wrapping on exact frames. (S1, S15)
- **R16.** A warped audio clip's linked clip envelopes play over its contents' beats, as a MIDI clip's do ([clip-envelopes.md](clip-envelopes.md) R2), so they follow its warp markers; an unwarped clip's play once from the clip's start, one tick per tick, as unlinked ones do. A brace that runs to the end of the file (no `loop_end`) is taken as the clip's length from its start for an envelope, as a MIDI clip's is. (S15; the unwarped case is Beatlayer's own)
- **R17.** The compiler turns each warped clip's warp map, under the song's tempo map, into a table from song frames to file positions, sent to the track's player as node data with its clip list: a warp edit sends new data and no new program, and a tempo change, which recompiles ([audio-clips.md](audio-clips.md) R12), sends every table again under the new map. The audio thread reads the table and plays the clip without allocating, locking or blocking, and a render is the same to the bit at any block size. A clip launched from a Session slot has no place in the Arrangement to tabulate for (R15): it follows the tempo map from its launch frame, frame by frame, through the same warp map. (S15, S18)
- **R18.** A warped clip streams from disk as an unwarped one does ([audio-clips.md](audio-clips.md) R17 to R21): its cues are the file positions its start, its loop's start and the Arrangement loop's start map to (a little before them, since the interpolator reads a few dozen frames before a position), and its stream reads far enough ahead that a clip running at up to four times its own speed (Beatlayer's own bound) underruns no more than one at its own speed. A streamed source only ever reads forwards: the player keeps the frames the interpolator reaches back over. (S15, S18)
- **R19.** A locate or an Arrangement loop wrap into a warped clip plays from the file position R12 gives for the frame it lands on, on that frame. (S15)

**Transients, pseudo-warp markers and the analysis cache (WP-4.3)**

- **R20.** Beatlayer analyses each audio file once, in the background, the first time a set uses it or the browser previews it: never on the audio thread or the compiler's. The analysis finds the file's transients with `bl-analysis`'s onset detection (spectral flux with adaptive peak picking, refined in the waveform) and, for WP-4.9, its tempo and beats (R30). Analysis never holds up playback: a clip whose warp map is set plays while its file is analysed, and its transients show when the analysis is ready. (S3, S8, S18)
- **R21.** The analysis is kept by the file's content hash in the user's cache folder, beside the peaks and never beside the sample (the one file Beatlayer writes beside a sample is the defaults file of R53, only when Save Default Clip is pressed): an `Analysis` folder in the same place as [waveform-peaks.md](waveform-peaks.md) R3's `Peaks` (`analysis` beside `peaks` on Linux). A later use of the same content, from any path or project, loads it instead of analysing again. An analysis file is used only if it's whole, of the current format version, and made from the media whose hash names it; a changed file is new media, never shown its old analysis; with no cache folder the analysis lives in memory for the session. Beatlayer never reads or writes `.asd` files. (S8, S18)
- **R22.** On drum loops generated in `tests/fixtures/gen/`, each hit's transient lands within 1 ms of the hit, with none missed and none doubled. The same file gives the same transients on every run and platform, to the frame. (S3, S18)
- **R23.** A clip shows its file's transients with its own edits applied: Insert Transient (`clip.insert_transient`; Cmd+Shift+I, S-SAMPLE-011; the Create menu) adds one at a time in the file, the Sample Editor's insert marker when the UI runs it; Delete Transient (`clip.delete_transients`; Cmd+Shift+Delete, S-SAMPLE-012; the Create menu) removes the selected transients, or those in the time selection, which the app names to the command by their times in the file, and which must be transients the clip has; Reset Transients (`clip.reset_transients`, the Sample Editor's context menu) removes the ones made by hand and brings back the detected ones that were deleted (bringing them back is Beatlayer's own). Each is one undo step and saved with the set as the clip's edits, times in the file, so the set shows the same transients on another machine once the file is analysed there. (S3, S14)
- **R24.** `clip.transients` (`read`) reports a clip's transients, as times in the file and as beats of its contents, with whether its file's analysis is ready; every transient edit reads back there. (S18)
- **R25.** Insert Warp Markers with a time selection (`clip.insert_warp_markers` over a range of the clip's contents; Cmd+I, S-SAMPLE-009, or the Create menu, with a selection) puts a warp marker at every transient in the range, or at its start and its end when it holds none; Cmd+I without a selection is R6 at the insert marker. One undo step. The command takes the clip's transients as an optional argument and the app fills them in from the clip's analysis, refusing the command until the analysis is ready. (S2, S3, S14)
- **R26.** Every transient that has no warp marker offers a pseudo-warp marker. Making it real is `clip.insert_warp_marker` at the transient's time in the file, with `pin_neighbours` (Cmd or Ctrl held) also inserting markers at the transients either side of it; dragging it is that insertion and R7's move, in one undo step; Shift-dragging it moves the transient (`clip.move_transient`), which changes no audio. `pin_neighbours` works on one clip, whose transients the app fills in as for R25. (S3)
- **R27.** A clip whose sample is replaced keeps its warp markers only when the new file is exactly as long as the old one, to the frame; otherwise it takes the warp settings a new clip of the new file gets (R33). Its transient edits belong to the old file and are dropped. (S12; dropping the edits is Beatlayer's own)
- **R28.** The real-time rules hold: analysis allocates freely but only on its own threads, and nothing it does waits on, or is waited on by, the audio thread. (S18)

**Tempo detection, auto-warp and the warp commands (WP-4.9)**

- **R29.** The Warp/Fades section of the Settings window's Record, Warp & Launch page holds, in Live's order: Loop/Warp Short Samples (Unwarped One Shot, Warped One Shot, Warped Loop, Auto; Auto in a new install), Auto-Warp Long Samples (on), Default Warp Mode (Beats, Tones, Texture, Re-Pitch, Complex, Complex Pro; Beats), then Create Fades on Clip Edges ([audio-clips.md](audio-clips.md) R22) and Warp recorded audio ([recording.md](recording.md) R13). Each is a preference, kept between starts, never in the set and never an undo step, set by `settings.set_loop_warp_short_samples`, `settings.set_auto_warp_long_samples` and `settings.set_default_warp_mode` and read back in `settings.state` under `warp`. (S7)
- **R30.** A file's analysis also holds its tempo, 40 to 240 BPM with a confidence from 0 to 1, and its beats, found by `bl-analysis`'s tempo method; on generated loops at steady tempos the tempo is within 0.5 BPM. (S6, S8, S18)
- **R31.** A file shorter than 60 seconds is a short sample and any other a long one (Beatlayer's own threshold). (S7)
- **R32.** Auto takes a short sample to be a loop when its analysis finds a steady beat (a confidence of 0.5 or more) whose tempo, with the sample taken as 1, 2, 4, 8 or 16 bars of 4/4, lies within 2 % of the tempo the sample's length gives; it treats it as Warped Loop then, and as Unwarped One Shot otherwise. (S7; the test is Beatlayer's own)
- **R33.** A clip made from a file — dropped from the browser, loaded with Enter, or imported — takes its warp settings in this order: the file's saved defaults (R42) when it has them, without auto-warp; for a short sample, Loop/Warp Short Samples: Unwarped One Shot leaves Warp and the loop off, Warped One Shot warps it (R34) with the loop off, Warped Loop warps it with the loop on over the whole file, and Auto chooses by R32; for a long sample, Auto-Warp Long Samples on auto-warps it (R35) with the loop off, and off leaves it unwarped. A new warped clip takes Default Warp Mode. A new warped clip lasts from its Start to its End marker in beats, a looped one its brace's length; an unwarped one lasts as long as its file plays at the set's tempo. (S4, S5, S7)
- **R34.** A short sample warped as a loop is taken to be 1, 2, 4, 8 or 16 bars of 4/4: the count whose tempo is nearest the tempo its analysis found, or, with no steady beat, nearest the set's tempo at the clip's start. It gets a warp marker at its start on 1.1.1 and one at its end on the last bar's end, and that tempo as the clip's. (S5)
- **R35.** Auto-warping a long sample puts a warp marker on the first beat of every bar its analysis's beats give, counting bars of 4/4 from the first beat found, which is 1.1.1; the clip's Start marker is on 1.1.1, its End marker at the file's end, and its tempo the last bar's. On a generated track at a steady tempo every marker lands within 1 ms of its bar's first beat. (S6, S7)
- **R36.** A clip whose file hasn't been analysed, and whose warp settings need the analysis (R33), is made when the analysis is ready: meanwhile the place it will go shows it pending, and the command that makes it returns once it's made. Making it is one undo step. (S8; showing it pending instead of making it greyed is Beatlayer's own)
- **R37.** With Warp recorded audio on, a recorded clip is warped in Default Warp Mode, with a warp marker at the take's start and one at every tempo change inside it, so it plays where it was recorded and at the speed it was played, and follows the tempo from then on; with it off, the clip is unwarped. (S16; the markers are Beatlayer's own)
- **R38.** Set 1.1.1 Here (`clip.set_1_1_1_here`, the Sample Editor's context menu), at the Sample Editor's insert marker or the selected warp marker, makes that point of the file the clip's 1.1.1: a warp marker is there (made if there was none), every marker moves by the same number of ticks so no segment's tempo changes, the Start marker moves to 1.1.1, and the End marker and loop brace move by the same ticks, keeping their place in the audio. One undo step. (S5, S6; the moves after the first are Beatlayer's own)
- **R39.** Each Warp From Here command (`clip.warp_from_here`, the Sample Editor's context menu) acts at the selected warp marker, or at a new one at the insert marker when none is selected, keeps every marker before it, and replaces those after it, in one undo step: Warp From Here auto-warps the audio after it as R35 does, from the tempo found there; Warp From Here (Start At …) does the same with the set's tempo there as the analysis's starting point, its label showing that tempo; Warp From Here (Straight) deletes the markers after it and sets the clip's tempo to the tempo found after it; and Warp … BPM From Here, its label showing the set's tempo there, deletes the markers after it and sets the clip's tempo to that tempo. (S6)
- **R40.** Warp as x-Bar Loop (`clip.warp_as_loop`, the Sample Editor's context menu, for the whole file) warps the file as a loop of 1, 2, 4, 8, 16 or 32 bars, the count whose tempo is nearest the set's tempo at the clip's start, named in the item's label: a marker at the file's start on 1.1.1 and one at its end, the loop brace over the whole file, and the loop on. Warp Selection as x-Bar Loop (`clip.warp_selection_as_loop`) does the same with a time selection in the Sample Editor: markers at the selection's ends, the brace on it, the loop on. One undo step each. (S6; the bar counts offered are Beatlayer's own)
- **R41.** The warp commands of R38 to R40 refuse an unwarped clip, and R39 and R40 refuse a file whose analysis isn't ready. (S6)
- **R42.** Save Default Clip (`clip.save_default`, the button in an audio clip's title bar) stores the clip's Warp switch, warp markers and tempo, warp mode with its controls (which hold its pitch: Transpose and Detune) and gain as its file's defaults, in the defaults file of R53, replacing any saved before. A new clip of that file takes them (R33); clips that exist don't change; the Warp From Here commands still work. It changes nothing in the set and is no undo step, and it writes outside the project, so it is `external`; `clip.defaults` (`read`) reads a file's saved defaults back. The file's analysis stays in the cache folder (R21). (S4, S18)

**Clip tempo leaders and followers, and stretching (WP-4.11)**

- **R43.** A warped Arrangement clip's Lead/Follow switch (`clip.set_tempo_leader`, `edit`, one undo step, saved with the set, read back at `tempo_leader` in the query tool's `clip`) is Follow unless set. It is refused for a Session clip and for an unwarped clip, and switching a leader's Warp off makes it a follower in the same step. (S9; refusing unwarped clips is Beatlayer's own)
- **R44.** Over a leading clip's span the set's tempo is the clip's: at each tick inside the clip, the tempo of the warp segment playing there, so the clip's file runs at its own speed, as if unwarped, and every following clip follows that tempo. Outside every leader the song's Song Tempo envelope applies. Where active leaders overlap, the one on the track lowest in the track list sets the tempo; a deactivated clip leads nothing. (S9; deactivated clips are Beatlayer's own)
- **R45.** The tempo leaders set shows on the Main track's Song Tempo envelope over each leader's span, and is worked out from the leaders whenever the set changes, so it moves with them; `song.set_tempo_breakpoint`, `song.move_tempo_breakpoint` and `song.delete_tempo_breakpoint` refuse a position inside a leader's span. While any clip leads, the Control Bar's tempo field is disabled and `song.set_tempo` is refused. (S9)
- **R46.** Unfollow Tempo Automation (`song.unfollow_tempo_automation`, the Control Bar tempo field's context menu) makes every leader a follower and writes the tempo they set into the Song Tempo envelope as ordinary breakpoints, so the song plays exactly as it did; one undo step. While Beatlayer follows an external MIDI clock (the Control Bar's EXT switch, which comes in M7), every clip follows and the Lead/Follow switch is disabled. (S9)
- **R47.** Shift-dragging the left or right edge of a warped clip's title bar in the Arrangement (S-ARR-006, I-DRAG-015) stretches the clip (`clip.stretch`): its other edge stays put, its length becomes the dragged one, snapping as a resize does, and every beat in its contents — warp markers, Start and End markers, loop brace — scales by the new length over the old about the beat at the fixed edge, so the same audio fills the new length and every segment's tempo, and the clip's, is divided by that ratio. One undo step; Esc puts it back. Shift-dragging an unwarped clip's edge resizes it as a plain drag does. (S5, S14; scaling every beat about the fixed edge is Beatlayer's own)
- **R48.** The tempo map the engine plays, leaders' tempo included, is the one exports, previews and golden renders use, so a set with leaders renders the same as it plays, at any block size. (S9, S18)

**Audio quantise (WP-4.12)**

- **R49.** Quantize on a warped audio clip (`clip.quantize_audio`; Cmd+U, S-SAMPLE-001, with the Sample Editor focused; Edit ▸ Quantize, M-EDIT-035; the Transform panel's Quantize tool) moves, for each line of the quantise grid inside the time selection (the whole clip with none), the clip's transient nearest that line, if one lies within half a grid step of it: the transient gets a warp marker at its time in the file (made if there is none) and the marker moves `amount` percent of the way to the line, keeping its time in the file. Transients nearest no line get no marker. A marker that would reach or pass a neighbour, such as a late first hit whose line holds the clip's start marker, keeps its place, and a transient with no marker keeps none; the rest still quantise. Grid lines lie from each bar's start as the note editor's do ([piano-roll.md](piano-roll.md) R18). 100 percent lands each on its line; 0 changes nothing and is no undo step; otherwise it is one undo step. It refuses an unwarped clip. (S10, S14, S17; choosing one transient per line is Beatlayer's own)
- **R50.** The quantise settings (`clip_view.quantize_settings`, Cmd+Shift+U, S-SAMPLE-002) are the note editor's ([piano-roll.md](piano-roll.md) R19): the grid, the current editing grid or a chosen division, triplets among them, and the amount, 0 to 100 percent. They are view state, never an undo step. (S10, S17)

**The warp map a preview plays through (WP-4.18)**

- **R51.** A tempo-synced preview plays its file through the warp map a new clip of it would get (R33 to R35, its saved defaults first), at the set's tempo, through the same table and real-time path as a clip (R12, R17); a file a new clip would leave unwarped previews at its own speed. When it starts and how it loops are [browser.md](browser.md) R18 to R23. (S13)

**Commands**

- **R52.** Every command in this spec is registered with a schema, a description written for a model, and a permission class, runs by ID through the agent API, and, unless it is `read`, names where its effect reads back. The edits of the clip and the song are `edit`; `clip.save_default` is `external`; `clip.transients` and `clip.defaults` are `read`. (S18)
- **R53.** A file's saved defaults are kept in a small file of Beatlayer's own, `<sample file name>.beatlayer-clip` in the sample's folder, so they travel with the sample. It holds a format version, the sample's content hash and the settings of R42. Only `clip.save_default` writes it, when Save is pressed: loading, analysing or using a sample never does, and if the folder can't be written the command fails with a message that names the file and the reason, writes nothing else, and leaves any defaults saved before. A file is used only if it is whole, of the current format version, holds a warp map that is valid, and was saved for the content hash of the sample beside it; otherwise it is ignored, and a new clip gets the settings of R33 from the preferences, so a changed sample is never shown its old settings. Beatlayer never reads or writes `.asd` files. (S4, S18)
