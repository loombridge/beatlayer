## Commands

### `focus.arrangement`

**Arrangement View**. Permission: `read`. Contexts: `global`.

Shows the Arrangement View if the Session View is in front, and moves the keyboard focus to it, so its shortcuts apply. With the second window open, moves the focus to the window that shows the Arrangement View and brings it to the front, without changing either window's view. Changes nothing in the set.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-FOCUS-003 | `Option+2` | `Alt+2` | `global` | Move focus to the Arrangement View | runs it |

Arguments: none (send `{}`).

Result: nothing (`null`).

### `focus.browser`

**Browser**. Permission: `read`. Contexts: `global`.

Moves the keyboard focus to the browser (to `part`: the sidebar, the list, or the search field; the list if left out), showing the browser if it's hidden, so its keys apply: Up and Down move through the list, Left and Right open and close folders, Enter loads. Changes nothing in the set.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-FOCUS-006 | `Option+5` | `Alt+5` | `global` | Move focus to the browser | runs it |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `part` | [`Part`](README.md#part) or null | no | The part to focus: `sidebar`, `content` (the list), `search`, or `groove_pool`. Left out, the list. |

Result: nothing (`null`).

### `focus.clip_panels`

**Clip Panels**. Permission: `read`. Contexts: `global`.

Moves the keyboard focus to the Clip View's panels, onto the first control of the panel the left group shows, showing the Clip View first if it is hidden: Navigate ▸ Clip Panels. Tab then moves through the panel's controls in order. Changes nothing in the set and isn't an undo step.

Arguments: none (send `{}`).

Result: nothing (`null`).

### `focus.clip_view`

**Clip View**. Permission: `read`. Contexts: `global`.

Moves the keyboard focus to the Clip View's editor, so the Clip View's shortcuts apply, showing the Clip View first if it is hidden. Changes nothing in the set and isn't an undo step. The result is the detail area's state. With the second window open it acts on the window `window` names, `main` or `second`, and on the window with the focus without it.

### `focus.next_neighbor`

**Next Neighbor**. Permission: `read`. Contexts: `global`, `tab-focus`.

Moves the keyboard focus from a track's control to the same control on the next track, such as from one track's volume to the next track's volume, in the mixers and the Arrangement's track headers, without changing the selected track. Navigate > Next Neighbor runs it whenever there's a next track; Option-Tab (Ctrl-Tab) does while Use Tab Key to Move Focus is on. Changes nothing in the set.

Arguments: none (send `{}`).

Result: nothing (`null`).

### `focus.toggle_tab_navigation`

**Use Tab Key to Move Focus**. Permission: `read`. Contexts: `global`.

Switches whether Tab and Shift-Tab move the keyboard focus between controls in the main window. While it's off, as it is by default, Tab switches between the Session and Arrangement Views. Changes nothing in the set.

Default keys: none.

Arguments: none (send `{}`).

Result: [`SwitchResult`](README.md#switchresult).

### `focus.toggle_wrap_navigation`

**Wrap Keyboard Navigation**. Permission: `read`. Contexts: `global`.

Switches whether Tab and Shift-Tab wrap round at the ends of the focused area or track: from its last control to its first, and from its first to its last. It's on in a new install, as Live's is; while it's off, they stop at the ends. The Settings window calls it Wrap Tab Navigation. Changes nothing in the set.

Default keys: none.

Arguments: none (send `{}`).

Result: [`SwitchResult`](README.md#switchresult).
