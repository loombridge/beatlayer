## Commands

### `browser.add_collection`

**New Collection**. Permission: `edit`. Contexts: `global`, `browser`, `browser-sidebar`.

Makes a collection of the person's own inside a collection (`parent`: 1 to 7, or a nested one, to any depth), as New Collection in a collection's context menu does. Its number is 8 or more and stays with it; `name` is "New Collection" when left out, numbered when that name is taken in the parent, and then its name opens for editing. A nested collection takes the colour of the collection at its top. Kept in the browser's database. Returns the browser's state, whose labels list it under its parent.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `parent` | integer, at least 0 | yes | The collection to make it in: 1 to 7, or a nested one. |
| `name` | string or null | no | Its name. Left out, "New Collection", numbered when the name is taken in that collection, with its name open for editing. |

Result: [`BrowserState`](#browserstate).

### `browser.add_folder`

**Add Folder to Browser...**. Permission: `external`. Contexts: `global`, `browser-sidebar`.

Adds the folder at `path` to the browser's Places, after Current Project, without moving or changing it, and indexes its files in the background so search finds them. Added folders are kept between launches; adding one twice changes nothing. A person choosing the menu item or the sidebar's Add Folder... picks the folder in a dialog.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | The folder's path. |

Result: [`BrowserState`](#browserstate).

### `browser.add_label`

**Add Label**. Permission: `edit`. Contexts: `global`, `browser`.

Keeps what the browser shows as a saved label, as the Results bar's Add Label button does: the label it was made under, the search words and the selected tags. It goes at the end of the Library section, named after its words and tags, with its name open for editing (`browser.state`'s `renaming_label`); `browser.rename_label` finishes it. Choosing it lists what those words and tags find under that label now. Refused when there are no search words and no selected tags. Kept in the browser's database.

Default keys: none.

Arguments: none (send `{}`).

Result: [`BrowserState`](#browserstate).

### `browser.add_tag`

**Add Browser Tag**. Permission: `edit`. Contexts: `global`, `browser`.

Makes a tag in the browser: in the group `group`, or under the tag `parent`, which makes it a subtag. A subtag can't hold another subtag. Changes the browser's database.

Default keys: none.

|---|---|---|---|

| `group` | string or null | no | The group to make it in, by its name. Left out with `parent` left out too, the first group. |
| `parent` | string or null | no | The tag to make it under, by its full name or its own name. It becomes a subtag. |

Result: [`TagsState`](README.md#tagsstate).

### `browser.add_to_arrangement`

**Add Files to Arrangement**. Permission: `external`. Contexts: `arrangement`, `browser`.

Puts audio files into the Arrangement as clips, as dragging them from the browser does: onto the audio track `track` starting at `at` (or the insert marker), one after another; or, with no `track`, onto a new audio track below the last track (the drop area), named after the first file. With `spread`, each file goes on a track of its own, new tracks below the target. With `lane`, a take lane of the track, they go on that lane as takes instead, and with `spread` the others go on the take lane at the same place of the tracks below, which must be audio tracks (a lane is added where one has none there). Each clip is named after its file and lasts as long as the file plays at the song's tempo. A clip placed over part of another replaces that part: the other is shortened, split around it, or removed, so a track never plays two clips at once; when a clip on `track` ends after `at`, it's destructive as well as external. One undo step. Reads the files, outside the project, and registers them so the set keeps them.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `paths` | array of string | yes | The audio files, in the order they go down. |
| `at` | [`Ticks`](README.md#ticks) or null | no | Where the first clip starts. Left out, the insert marker. It isn't snapped: snap first if you want the grid. |
| `lane` | [`TakeLaneId`](README.md#takelaneid) or null | no | A take lane of `track` to put them on in place of its main lane (the comping spec, R36): the clips go one after another on that lane, as takes. With `spread`, the first goes on the lane and each of the others on the take lane at the same place among the take lanes of the next track below, in turn, a lane being added where a track has none there. `track` may be left out; given, it must be the lane's. |
| `spread` | boolean | no | Put each file on a track of its own (as dropping with Cmd or Ctrl held does), new tracks going below the target, instead of one after another on one track. |
| `track` | [`TrackId`](README.md#trackid) or null | no | The audio track to put them on. Left out (or `null`), a new audio track below the last track, as dropping in the drop area does. |

Result: [`AddResult`](README.md#addresult).

### `browser.analysis_state`

**Sound Analysis State**. Permission: `read`. Contexts: `global`, `browser`.

Reports how far the browser's sound analysis has got: the audio files and presets analysed, waiting and skipped, whether analysis is paused, the file under way and the share done. Beatlayer describes every audio file of 60 seconds or less and every instrument and drum preset in the background, for finding similar sounds. Changes nothing.

Default keys: none.

Arguments: none (send `{}`).

Result: [`AnalysisState`](README.md#analysisstate).

### `browser.back`

**Browser History Back**. Permission: `external`. Contexts: `global`, `browser`.

Goes back one step in the browser's history, as Browse Back and Cmd-[ (Ctrl-[) do, showing that step's label, search words, selected tags, open folders and selection. A step is taken when the label changes, when the selected tags change, and when a search starts or its words change (changes in a row make one step); the history holds 100 steps and isn't kept between launches. Refused at the first step (`browser.state`'s `can_back`).

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-BRW-011 | `Cmd+LeftBracket` | `Ctrl+LeftBracket` | `browser` | Go back in the browser's history | runs it |

Arguments: none (send `{}`).

Result: [`BrowserState`](#browserstate).

### `browser.delete_collection`

**Delete Collection**. Permission: `destructive`. Contexts: `global`, `browser`, `browser-sidebar`.

Deletes a nested collection and the collections inside it from the browser, as Delete in its context menu does. It never touches a file: the items simply leave them. When they hold items the command is refused unless `confirm` is true. Returns the browser's state.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `collection` | integer, at least 0 | yes | The nested collection to delete, with the collections inside it. |
| `confirm` | boolean | no | Delete although they hold items: they leave them out. Otherwise the command is refused, naming how many (spec: browser-tags R47). |

Result: [`BrowserState`](#browserstate).

### `browser.delete_tag`

**Delete Browser Tag**. Permission: `destructive`. Contexts: `global`, `browser`.

Deletes a tag or a group in the browser: `tag` for a tag, by its full name (`Format|CLAP`) or its own name, `group` for a group, by its name. Deleting a group deletes its tags. Beatlayer's own tags and groups can't be deleted. A deleted tag is gone from every item that carried it, and undo can't bring it back. When saved labels use the tag (or the group's tags) the command is refused, naming them, unless `confirm` is true; the labels then leave it out.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `confirm` | boolean | no | Delete although saved labels use the tag or the group's tags: they then leave it out. Otherwise the command is refused, naming them (spec: browser-tags R8). |
| `group` | string or null | no | The group to delete, by its name. |
| `tag` | string or null | no | The tag to delete, by its full name or its own name. |

Result: [`TagsState`](README.md#tagsstate).

### `browser.filter`

**Filter Browser**. Permission: `external`. Contexts: `global`, `browser`.

Selects filter tags, as clicking tag buttons in the Filter View does. Without `add`, each tag in `tags` becomes the only one selected in its group (a tag that is already the only one is cleared). With `add`, each tag is added to its group's selection, or taken out if it is in it already. The list then holds the items under the label that carry, for each group with a selection, at least one of its selected tags, and match every search word. Selected tags stay when another Library label is chosen. Changes nothing, but lists files outside the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `tags` | array of string | yes | The tags, by their full names or their own names. |
| `add` | boolean | no | Add the tags to their groups' selections, or take a selected one out, as Cmd-click (Ctrl-click) does. Otherwise each tag is the only one selected in its group, and a tag that is already the only one is cleared. |

Result: [`BrowserState`](#browserstate).

### `browser.load_selected`

**Load Selected Item**. Permission: `external`. Contexts: `browser`.

Loads the browser's selected audio files into the Arrangement, as Enter or a double-click does: onto the selected track at the insert marker if it's an audio track, otherwise onto a new audio track below the last one, one after another, as one undo step. A clip placed over part of another replaces that part, so when a clip on that track ends after the insert marker it's destructive as well as external. A selected preset file, or a device or rack listed under a label (Drums, Instruments, Audio Effects, MIDI Effects or Modulators), is added to the shown track as `device.add_preset` and `device.add` add it, and a chain preset to the chain list's rack (`chain.load_preset`). While a device is being hot-swapped (`device.hot_swap`), a selected preset or device replaces it instead (`device.replace`), as does a chain preset the chain armed by its Hot-Swap button (`chain.load_preset`); a selected audio file loads into it if the device plays samples (the sampler, or the eight-slot drum sampler, into its selected slot: `device.load_sample`). With one plug-in selected it loads that plug-in instead, as `plugin.load` does: onto the selected track (a new track when none is), an instrument onto a new MIDI track when the selected track holds audio, or in place of the device being hot-swapped. Reads the files, outside the project.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-BRW-004 | `Enter` | `Enter` | `browser` | Load the selected item | runs it |
| S-DEV-007 | `Enter` | `Enter` | `browser` | Load the selected device from the browser | runs it |
| S-TRACK-015 | `Enter` | `Enter` | `browser` | Add the browser's selected device to the selected track | runs it |

Arguments: none (send `{}`).

Result: [`AddResult`](README.md#addresult).

### `browser.open_folder`

**Open Folder**. Permission: `external`. Contexts: `browser`.

Opens or closes a folder in the browser's content pane, listing its folders and audio files indented under it (in the Plug-Ins label, a vendor's folder and its plug-ins). A set file opens like a folder, read in the background: its tracks in its order, a group holding its tracks, then its return tracks and Main, each openable in turn (a track lists its Session clips by scene, and every track a Devices row); a set that can't be read opens to a line saying why. A row of an opened set is named by its `path`, the set's path, `#` and `t`, `d` or `c` with the ID of the track, the track whose chain it is, or the Session clip; `set.import` takes those IDs. Opening a folder closes the other open folders it isn't inside, unless `keep_others` (Cmd or Ctrl held). Right and Left do this on the selected folder. Changes nothing, but reads folders outside the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | The folder, set file or row of an opened set, as a row of the content pane gives it. |
| `keep_others` | boolean | no | Keep the other open folders open, as holding Cmd (Ctrl) does. Otherwise opening a folder closes every open folder it isn't inside. |
| `open` | boolean or null | no | Open (true) or close (false). Left out, it toggles. |

Result: [`BrowserState`](#browserstate).

### `browser.preview`

**Preview**. Permission: `external`. Contexts: `browser`.

Previews an audio file (`path`, or the selected file): plays it once from its start through the main output, at the preview volume, on a voice of its own, replacing any preview, whether or not the Preview switch is on, as Shift-Enter and Right do. The file is decoded in the background, so it starts a moment later; `browser.state` reports it loading, then playing. An instrument, Instrument Rack or Drum Rack preset is rendered offline playing a short phrase instead, and plays once whatever the Raw switch says; any other preset plays nothing, and `note` says why. Never changes the set. Plays through the audio device.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string or null | no | The audio file, clip file or instrument preset to preview. Left out, the selected file. |

Result: [`PreviewState`](README.md#previewstate).
