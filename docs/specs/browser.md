## The behaviour

The browser fills the main window's left column. Its sidebar lists labels in three sections, Collections, Library, and Places; choosing a label shows its contents in the content pane beside it, a list of folders and files with a Name column. Places hold folders on disk: the User Library, the open project's folder, and any folder the person adds. Folders open in place, their contents indented beneath them, and the arrow keys move through the list, open and close folders, and cross between the sidebar and the list. The search field at the top finds files by name across every place Beatlayer has indexed, as you type.

With the Preview switch on, selecting an audio file plays it (previewing, or auditioning) at the preview volume, without touching the set. Dragging files from the list onto an audio track in the Arrangement places clips where they're dropped; dropping them below the last track creates a new audio track holding them. Enter or a double-click loads the selected file onto the selected track.

Beatlayer ships none of Live's content, so in M1 the Library labels that hold content (Sounds, Drums, Instruments, the effects, Grooves, and the rest) show what Beatlayer has, which for most is nothing yet, and say which package brings it. Places are the working part. Labels for Ableton's products and services (Max for Live, Packs, Splice, Cloud, Push) are left out, as decision D21 does for menus and settings.

This spec covers what WP-1.10 builds: the browser's layout, places, browsing with the mouse and keyboard, search, preview through the main output, and adding files to the Arrangement by dragging, Enter, or double-click. Collections, tags, filters, extra columns, history, tempo-synced preview, the Cue output, and hot-swapping come later (see the status line).

## Rules

- **R1.** At 1600 × 1000 points the browser sits at layout.md's coordinates: the column from x 9 to 311, from under the Control Bar (y 61) to the detail area's top (y 766); Browse Back at x 9, Browse Forward at 29, the search field from 50 to 270, and the Filter View toggle and menu at 275 and 297, on the top row (y 61 to 82); the sidebar from x 9 to 109 and the content pane from 110 to 311, from y 84 down; in the content pane the column header row (Name), then the item list, then the Preview switch at x 114, y 748, with the preview strip beside it. The Filter View (L-BRW-007) is an M6 feature and is hidden, so the header row sits at the content pane's top, and the rows are 17 points high. Hiding the browser (Cmd-Option-B) gives the main view its place. (S1)
- **R2.** The sidebar lists, top to bottom: the Collections heading with Favorites, Orange, Yellow, Green, Blue, Purple, and Gray, drawn but not yet usable (M6); the Library heading with All, Sounds, Drums, Instruments, Audio Effects, MIDI Effects, Modulators, Plug-Ins, Clips, Samples, Grooves, Tunings, and Templates; the Places heading with User Library, Current Project, the folders the person added in the order added, then Add Folder.... Max for Live, Packs, Splice, Cloud, and Push are left out (D21). A new set shows the All label. The Grooves label lists Beatlayer's bundled grooves and the User Library's Grooves folder ([grooves](grooves.md) R33, WP-6.20). (S1, S2)
- **R3.** The User Library is a folder named User Library in a Beatlayer folder in the Music folder on macOS and Linux, and in the Documents folder on Windows. The app creates it on its first run with Clips, Defaults, Grooves, Presets, Samples and Tunings folders in it (Tunings from WP-6.9, [tunings](tunings.md) R10), and never changes what's already there. A preference can name another folder. (S3)
- **R4.** Current Project shows the folder of the open set's file; a set never saved has none, and the content pane says so. Saving or opening a set changes what it shows. (S4)
- **R5.** Add Folder... (the sidebar's last label, and File > Add Folder to Browser...) asks for a folder and adds it to Places after Current Project, without moving or changing it; adding a folder already there changes nothing. Added folders are kept between launches. Remove from Sidebar, in an added folder's context menu, takes it out of Places and leaves the folder on disk alone. (S4, S10)
- **R6.** The content pane lists a place's folders and the files Beatlayer can open (audio files of the formats audio-import R1 lists, and Beatlayer sets), folders first, each group by name ignoring case, with numbers in names in numeric order; hidden files and other files are left out. The All label lists the places themselves as folders; the Samples label lists every audio file in the places, by name; the other Library labels say what will fill them and when. Opening a folder lists its contents indented beneath it; opening a folder closes the other open folders except the ones it's inside, unless Cmd (Ctrl) is held. (S2, S6)
- **R7.** Clicking an item selects it; Shift-click selects the range to it and Cmd-click (Ctrl-click) adds or removes it. Up and Down move the selection to the item above or below, Shift with them extends it. In the list, Right opens the selected folder (or, on a file, previews it) and Left closes it; Left on an item inside an open folder selects that folder, and Left at the top level moves the focus to the sidebar. Enter loads the selected files (R14); Shift-Enter previews the selected file. In the sidebar, Up and Down choose the label above or below and show its contents, and Right moves the focus to the list. Double-clicking a folder opens or closes it. (S6, S8)
- **R8.** Option-5 (Alt-5), and Navigate > Browser, moves the keyboard focus to the browser, showing it if it's hidden. Cmd-F (Ctrl-F), and View > Search in Browser, shows the browser, chooses the All label, and puts the cursor in the search field; in the field, Down or Enter moves the focus to the first result, and Esc clears the field. (S5, S6, S10)
- **R9.** Search runs as you type: an item matches when every word typed appears in its name, ignoring case. Under All and Samples it searches every place (Samples, audio files only), under a place that place, under Clips the clip files ([clip files](clip-files.md) R6, WP-6.34), under Grooves the grooves it lists ([grooves](grooves.md) R33, WP-6.20), under Tunings the tunings it lists ([tunings](tunings.md) R25, WP-6.10), and under the other Library labels nothing yet. Results are a flat list in name order, each naming its folder; clearing the field shows the label's contents again. (S5)
- **R10.** Beatlayer indexes the places' files on a background thread when it starts, when a folder is added or removed, and when the project folder changes; search sees what's indexed so far and updates as indexing goes on, which the sidebar's Places heading shows. The index is kept on disk, in the browser's database beside the preferences, and read when Beatlayer starts, so the browser lists and searches what was indexed before from the first frame ([browser tags](browser-tags.md) R1); the background walk brings it up to date with what changed on disk, telling a changed file by its size and modification time. Beatlayer doesn't watch folders for changes on disk: a folder is listed afresh each time it's opened. Indexing 100,000 files and searching them as you type keep up: each search answers well inside one frame (16 ms) and indexing takes seconds, measured by `cargo run --release -p bl-shell --example browser_index_bench`. (S4, S11)
- **R11.** The Preview switch (at the content pane's bottom left, and Options > Browser File Preview) is on in a new install and kept between launches. While it's on, selecting a single audio file (by clicking or with Up and Down) previews it; Shift-Enter and Right preview the selected file whatever the switch says. A preview plays the file once from its start, through the main output (not yet the Cue Out, though Cue mode exists since WP-3.18), at the preview volume, a linear gain from 0 (silence) to 2 (+6 dB), unity by default (the Main track's Preview/Cue knob, which the mixer brings). It never changes the set. Selecting another file plays that one instead; selecting a folder, switching Preview off, or Stop Preview stops it. The preview strip shows the file's name, its waveform once it's decoded, and how far it has played. Previews play at the file's own speed (Live's Raw), because tempo-synced preview is M4; files longer than 10 minutes preview their first 10 minutes until previews stream from disk. (S7)
- **R12.** A preview plays on a voice of its own on the audio thread. The file is decoded and converted to the device's rate on a background thread, and handed to the audio thread wrapped for `rtgc`, so the audio thread never allocates, frees, locks, or blocks to start, play, replace, or stop it; a stopped preview fades out over at most 64 frames rather than clicking. (S11)
- **R13.** Dragging files from the list over the Arrangement highlights where they'd go: the audio track under the pointer with a line at the drop position, snapped to the grid while snapping is on (Cmd, or Alt on Windows, held ignores it), or the drop area under the last track. Dropping on an audio track places an audio clip there; dropping in the drop area creates a new audio track below the last track holding the clip. Each clip is named after its file and lasts as long as the file plays at the song's tempo. Several files go one after another on one track; with Cmd (Ctrl) held each goes on a track of its own, new tracks created below the target. A new track is named after its file. A clip dropped over part of another clip replaces that part, as the Arrangement's own edits do (the arrangement editing spec). Either way the drop is one undo step, named "Insert Clip". Dropping on a MIDI, group, or return track or on Main isn't possible: nothing is highlighted and nothing changes. Files dropped on the window from Finder or Explorer land the same way. (S8, S9, S12)
- **R14.** Enter, or a double-click on a file, loads the selected audio files onto the Arrangement's selected track at the insert marker if that's an audio track, or onto a new audio track below the last one otherwise, as one undo step; the insert marker doesn't move. (S8)
- **R15.** A file added to the set is registered in the media store, so its waveform builds and shows, and saving the set records it in the set's media table by its path relative to the project folder; opening the set registers it again. (S12)
- **R16.** Every action above is a registered command with a schema, a description for a model, and a permission class (`browser.*` and `focus.browser` in [commands.md](../commands.md)), reachable headless through `Shell::run`. Commands that read folders or files outside the project, or play through the audio device, are external (`browser.state`, `browser.search`, `browser.open_place`, `browser.open_folder`, `browser.select`, `browser.show_file`, `browser.add_folder`, `browser.preview`, `browser.load_selected`, `browser.add_to_arrangement`); the Preview switch and volume and removing a folder from the sidebar are edits to preferences; moving the focus, focusing the search field, and stopping a preview are reads. (S11) `browser.show_file` shows an audio file, named by its path or by the clip that plays it, in the place it lies in: it shows the browser, chooses that place, opens the folders down to the file and selects it, and is refused for a file that lies in none of the places (WP-4.10; the Sample Editor's Show in Browser, [sample-editor.md](sample-editor.md) R2).
- **R17.** The browser builds only the rows on screen, so a list of 100,000 items draws as fast as a short one, and every part of it reaches assistive technology with a role, a name, and a value: the sidebar's labels as a list with the chosen one selected, each row as a list item naming its kind and whether it's open, the search field, the Preview switch, and the preview strip. (S11)
- **R18.** The preview strip carries a Raw switch, at its right end (the place is Beatlayer's own), off in a new install and kept between launches, as the Preview switch is (R11). `browser.set_raw` switches it, an edit to preferences that reads back in `browser.state`. With Raw on, a preview plays as R11 says: once, from the file's start, at its own speed. (S13)
- **R19.** With Raw off, an audio file previews at the set's tempo, through the warp map a new clip of it would get ([warping.md](warping.md) R51: the file's saved defaults, or what Loop/Warp Short Samples and Auto-Warp Long Samples make of it), and loops from its end to its start. A file a new clip would leave unwarped — an Unwarped One Shot, or a long sample with Auto-Warp Long Samples off — previews as R18's Raw preview does, once and at its own speed. (S13, S14; leaving an unwarped preview unlooped is Beatlayer's own)
- **R20.** A warped preview starts on the next bar line of the song while the transport runs, with its 1.1.1 on that bar line and its beats on the song's beats from then on, through tempo changes and the Arrangement loop's wraps; with the transport stopped it starts at once and keeps the set's tempo where the song stands. (S13; the stopped transport's case is Beatlayer's own)
- **R21.** A file that hasn't been analysed is analysed in the background when it's selected for a preview ([warping.md](warping.md) R20); a warped preview of it starts, as R20 says, once the analysis is ready, and selecting another file meanwhile drops it. A Raw preview never waits for the analysis. (S14; the wait is Beatlayer's own, after Live's rule that a sample can't play until it's analysed)
- **R22.** Clicking in the preview strip's waveform while a warped preview plays moves it to the clicked point, on the next step of the global launch quantisation while the transport runs and at once while it's stopped (`browser.scrub_preview`, `external`, as `browser.preview` is). With Raw on, or on a preview that plays unwarped, a click does nothing. (S13; the step is Beatlayer's own)
- **R23.** A warped preview plays on the preview voice of R12, through the same mapping and real-time path as a warped clip ([warping.md](warping.md) R12, R17): the file, its analysis and its mapping are prepared on a background thread and handed to the audio thread through `rtgc`, so the audio thread never allocates, frees, locks or blocks to start, loop, move, replace or stop it. (S11, S14)
- **R24.** Settings ▸ Library (L-SET-016) shows the User Library's folder under Locations, its path and a Browse button that chooses another folder (`settings.set_user_library`, an edit to preferences, read back in `settings.state` and in `browser.state`'s User Library label). The chosen folder becomes the User Library at once: its starting folders are made in it if it has none (R3), it's indexed in the background (R10), and nothing is moved from the folder before. The choice is kept between launches. (S3, S15)
- **R25.** Right-clicking an item in the content pane, or the keyboard's context-menu key with it selected, opens its context menu (C-BROWSER): Show in Places, which shows the item in the place it lies in as `browser.show_file` does, offered for an item listed under a Library label, a collection, a saved label or a search; Show in Finder on macOS (Show in File Manager on Windows and Linux, Beatlayer's own name), which shows the file or folder in the system's file manager (`browser.reveal`, external); Show Similar Files, drawn disabled until similarity search (milestone M9); then, after a separator, Clear All Colors and the seven collections with their keys ([browser tags](browser-tags.md) R35). The menu acts on every selected item. (S16)
- **R26.** View ▸ Full-Height Browser (M-VIEW-024), and the same item in the Browser Config Menu beside the browser's toggle (L-CTRL-001), runs the browser column from under the Control Bar down to the Status Bar, instead of to the detail area's top; the Info View and the Clip or Device View stay open, under the main view to the browser's right (Beatlayer's own reading of where they go). The content pane's list grows with the column, and the preview strip stays at its bottom. The item is ticked while it's on, and choosing it again puts the column back. `view.toggle_full_height_browser` switches it, an edit to preferences read back in `view.state`; it's kept between launches (Beatlayer's own). (S17)
- **R27.** With the Preview switch on, selecting one instrument preset previews it, and Shift-Enter or Right preview it with the switch off (R11): a preset of one of Beatlayer's instruments, an instrument rack or drum rack preset ([racks](racks.md) R42), or a plug-in instrument's preset ([plug-in scanning](plugin-scanning.md) R15). The preset's devices are made from it on a background thread, plug-ins from their saved state as an offline render makes them ([offline plug-in renders](offline-plugin-renders.md) R3, R11), and play Beatlayer's preview phrase, rendered offline: for an instrument or an instrument rack, the note C3 at velocity 100 held for one bar at the set's tempo; for a drum rack, each pad that holds a chain, lowest note first, a sixteenth note each at velocity 100; each rendered on until its sound falls below −60 dBFS, or for 2 seconds more at most (Beatlayer's own phrase). The render plays once, from its start, at once, whatever the Raw switch says, on the preview voice (R12), and is kept until the preset file changes. (S18; the phrase and its render are Beatlayer's own)
- **R28.** Rendering a preset's preview never uses the set's own devices or plug-in instances and changes nothing in the set. Selecting another item while it renders drops the render. A preset whose plug-in this machine doesn't have, or that fails to load, previews nothing, and the preview strip says why; a preset of an audio or MIDI effect previews nothing. `browser.preview` previews a preset as it previews a file, and `browser.state`'s preview reads it back. (S18)
