## Commands

### `transport.continue`

**Continue Playback**. Permission: `read`. Contexts: `global`.

Resumes playback from where it last stopped rather than from the insert marker. It does nothing while the song plays. It changes nothing in the project.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-TRANS-002 | `Shift+Space` | `Shift+Space` | `global` | Continue playing from where playback stopped | runs it |

Arguments: none (send `{}`).

Result: nothing (`null`).

### `transport.insert_marker_to_playhead`

**Move Insert Marker To Playhead**. Permission: `read`. Contexts: `global`, `arrangement`.

Moves the insert marker to the playhead: where the song is playing now, or where playback stopped. Use it to start again later from the current point. It changes nothing in the project.

Default keys:

### `transport.locate`

**Set Arrangement Position**. Permission: `read`. Contexts: `global`.

Moves the insert marker, where playback starts, to `position`, in ticks from the start of the arrangement (705,600 to the quarter note, so bar 2 of a 4/4 song is 2,822,400), as typing into the Control Bar's Arrangement Position fields does. While the song plays, playback jumps there at once; while it's stopped, `transport.continue` still resumes where playback stopped. With `quantized` set, the jump waits while the song plays for the next line of the global launch quantisation and lands on that line's exact frame, as a locator's jump and a click in the scrub area do (the transport spec, R22); with the quantisation off or None, it jumps at once. Position 0 returns to 1.1.1, as the Home key and Return Play Position to 1.1.1 do. A position before 0 is taken as 0. It changes nothing in the project.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-TRANS-005 | `Home`, `Fn+Left` | `Home` | `global` | Move the insert marker to the start | fixes `position` = `0` |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `position` | [`Ticks`](README.md#ticks) | yes | The new insert marker, in ticks from 1.1.1. A position before 1.1.1 is taken as 1.1.1. |
| `quantized` | boolean | no | Whether the jump waits for the next line of the global launch quantisation while the song plays, as a locator's jump and a click in the scrub area do (the transport spec, R22). With it off, or with the quantisation off or None, the jump happens at once. |

Result: nothing (`null`).

### `transport.phase_nudge`

**Phase Nudge**. Permission: `read`. Contexts: `global`.

Presses or releases the Control Bar's Phase Nudge Down or Up button. While `direction` `down` or `up` is held (`held` true) and the song plays, the song plays 4 % slower or faster than the tempo it plays at otherwise, to bring it into phase with another player; with both held, the one pressed last nudges. Call it again with `held` false to end the nudge: the next block plays at the tempo again, the song's beat staying where the nudge moved it. A nudge you leave held ends when your agent session ends. While the song is stopped a nudge does nothing, and while an incoming clock or a Link session leads the tempo, a press is refused and only a release is accepted. The Tempo field, the tempo map and the set don't change, and it is no undo step. `transport.state`'s `phase_nudge` reads which button is held.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `direction` | [`NudgeDirection`](README.md#nudgedirection) | yes | Which button: `down` plays the song 4 % slower while held, `up` 4 % faster. |
| `held` | boolean | yes | Whether the button is held: true on the press, false on the release. |

Result: nothing (`null`).

### `transport.play`

**Play**. Permission: `read`. Contexts: `global`.

Starts playback from the insert marker, as the Control Bar's Play button does; while the song plays, starts it again from the insert marker. When the song has a song start time (the transport spec, R21), it starts from that instead and leaves the insert marker where it is. Set the insert marker first with `transport.locate`. With the Arrangement loop on, playback that reaches the loop's end goes on from its start. It changes nothing in the project.

Default keys: none.

Arguments: none (send `{}`).

Result: nothing (`null`).

### `transport.play_from_insert_marker`

**Play From Insert Marker**. Permission: `read`. Contexts: `global`, `arrangement`.

Starts playback from the insert marker, even when the song has a song start time (the transport spec, R21). As the app runs it with a time selection in the Arrangement, it plays from the selection's start and stops on its end, with the Arrangement loop off until it stops (R35); an agent asks for that with `transport.play_selection`. It changes nothing in the project.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-ARR-032 | `Option+Space` | `Ctrl+Space` | `arrangement` | Play from the insert marker in the selected clip | runs it |
| S-TRANS-003 | `Option+Space` | `Ctrl+Space` | `global` | Play and stop at the end of the selection | runs it |

Arguments: none (send `{}`).

Result: nothing (`null`).

### `transport.play_selection`

**Play Selection**. Permission: `read`. Contexts: `global`.

Starts playback from `start`, in ticks from the start of the arrangement, and leaves the insert marker where it is, as Space does with a time selection. With `end`, after `start`, the song stops on that exact frame, as Option-Space does with a time selection: the Arrangement loop doesn't apply until then, `transport.state` reads `loop_on` false while it plays, and the loop is on again once the song has stopped. Without `end`, playback goes on as Play does, from the song start time if the set has one (the transport spec, R35, R36). It changes nothing in the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `start` | [`Ticks`](README.md#ticks) | yes | Where playback starts, in ticks from 1.1.1. |
| `end` | [`Ticks`](README.md#ticks) or null | no | Where playback stops, in ticks. With it, the Arrangement loop is switched off until the song stops there; without it, playback goes on as Play does. |

Result: nothing (`null`).

### `transport.play_stop`

**Play/Stop**. Permission: `read`. Contexts: `global`.

Stops playback if the song is playing, and otherwise starts it from the insert marker (from the start of the Arrangement's time selection when there is one, as the app runs it: the transport spec, R35): the space bar, and the Playback menu's Play item, which reads Stop while the song plays. Unlike `transport.stop`, it never returns to 1.1.1. An agent that knows what it wants should use `transport.play` or `transport.stop` instead.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-TRANS-001 | `Space` | `Space` | `global` | Play from the start marker, or stop | runs it |
| S-TRANS-004 | `Space` | `Space` | `global` | Play the Arrangement selection | runs it |

Arguments: none (send `{}`).

Result: nothing (`null`).

### `transport.resync_external_hardware`

**Resync External Hardware**. Permission: `read`. Contexts: `global`.

Sends each output port with Sync on its own Hardware Resync choice, as the Control Bar's Resync External Hardware button does: Stop then Start, Start only, or nothing. While the song plays they go out at the next bar line, just before that bar line's clock, so hardware that has drifted starts again in step on the bar; while the song is stopped, or counting in, it does nothing. Set the choices with `midi.set_port`. It changes nothing in the project.

Default keys: none.

Arguments: none (send `{}`).

Result: nothing (`null`).

### `transport.return_to_start`

**Return Play Position to 1.1.1**. Permission: `read`. Contexts: `global`.

Moves the insert marker, where playback starts, back to the start of the arrangement (1.1.1), as the Playback menu's Return Play Position to 1.1.1 does. While the song plays, playback jumps there at once; while it's stopped, `transport.continue` still resumes where playback stopped. The same as `transport.locate` at position 0, which the Home key runs. It changes nothing in the project.

Default keys: none.

Arguments: none (send `{}`).

Result: nothing (`null`).

### `transport.scrub`

**Scrub**. Permission: `read`. Contexts: `global`.

Presses or releases the Arrangement's scrub area at `position`, in ticks from the start of the arrangement. With `held` true it loops one step of the global launch quantisation (a bar with the quantisation off or None) from the grid line at or before `position`, until you call it again with `held` false: while the song plays, playback jumps to the span's start on the next quantisation line, and while it's stopped, playback starts there. The Arrangement loop is left as it is and applies again afterwards. With `held` false and a loop held, it ends that loop and playback carries on from where it is; with none held, it plays from `position`, as a click in the scrub area does (the jump waits for the quantisation line while the song plays; while it's stopped, playback starts there). It changes nothing in the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `position` | [`Ticks`](README.md#ticks) | yes | The point pressed or clicked in the scrub area, in ticks from the start of the arrangement. |
| `held` | boolean | no | Whether the mouse button is held: loops the span at `position` until a call with `held` false ends it. |

Result: nothing (`null`).

### `transport.set_external_sync`

**External Sync**. Permission: `edit`. Contexts: `global`.

Switches EXT, as the Control Bar's EXT switch and Options > External Sync do: with it on, the song follows the incoming MIDI clock of an input port with Sync on (its tempo, its Start, Continue, Stop and Song Position Pointer), the Tempo field shows the followed tempo and can't be changed, tempo automation isn't played, and every clip that leads the tempo plays as a follower. `on` left out switches to the other state. Switching it on is refused while no input port has Sync on (`midi.set_port`'s `sync`); switching the last such input's Sync off switches EXT off. It is a preference kept between starts, not part of the set. `transport.state` reports it as `external_sync`, and `sync.state` the clock that arrives.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `on` | boolean or null | no | Whether EXT is on; left out, it switches to the other state. |

Result: [`ExternalSync`](README.md#externalsync).

### `transport.set_loop`

**Set Loop Brace**. Permission: `edit`. Contexts: `global`, `arrangement`.

Moves the Arrangement loop brace to start at `start` and run for `length` ticks (705,600 to the quarter note; a 4/4 bar is 2,822,400), as the Control Bar's Loop Start and Loop Length fields do. It doesn't switch the loop on or off: use `transport.set_loop_enabled` for that. While the loop is on, playback that reaches the brace's end jumps back to its start; playback that starts at or after the end plays on. The start must be 0 (1.1.1) or later and the length more than 0. The brace is saved with the set, and undo moves it back.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `start` | [`Ticks`](README.md#ticks) | yes | Where the loop starts: 0 (1.1.1) or later. |
| `length` | [`Ticks`](README.md#ticks) | yes | How long it is: more than 0. |

Result: [`ChangeSet`](README.md#changeset).

### `transport.set_loop_enabled`

**Arrangement Loop On/Off**. Permission: `edit`. Contexts: `global`, `arrangement`.

Switches the Arrangement loop on or off, as the Control Bar's Loop switch does, leaving the brace where it is. With it on, playback that reaches the brace's end jumps back to its start, on the exact sample, until it's switched off or playback stops. Use `transport.set_loop` to move the brace first. The switch is saved with the set, and undo switches it back.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `enabled` | boolean | yes | Whether playback loops between the brace's start and end. |

Result: [`ChangeSet`](README.md#changeset).

### `transport.set_record_quantization`

**Record Quantization**. Permission: `edit`. Contexts: `global`.

### `transport.set_recording`

**Set Recording**. Permission: `external`. Contexts: `global`.

Sets whether the transport is recording: while it is, each armed audio track records its input into the project's Samples/Recorded/, each armed MIDI track records the notes it receives, and the recording becomes a clip on its track when it ends; a count-in starts it a bar or more later. With MIDI Arrangement Overdub on, recorded notes merge into the MIDI clips already there. Features like Hear Metronome Only While Recording follow it too. Recording captures input devices, including a microphone, so the person is asked first, whichever way you set it: to stop a recording without asking, run `transport.stop_recording`.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-TRANS-006 | `F9` | `F9` | `global` | Record | toggles `recording` |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `recording` | boolean | yes | Whether the transport is recording. |

Result: nothing (`null`).

### `transport.state`

**Transport Status**. Permission: `read`. Contexts: `global`.

Reports what the Control Bar's transport section shows: whether the song plays, the play position and the insert marker (in ticks from 1.1.1, and the Arrangement Position fields' bar.beat.sixteenth), the Arrangement loop's start, length, and switch, the tempo, and the time signature, the metronome, Arrangement Record and whether a take is running or the count-in is sounding, Punch-In and Punch-Out, MIDI Arrangement Overdub, Automation Arm and the mode an Arrangement recording writes control moves in, the recording under way (its armed tracks and dropped frames) and what the last recording came to, which Phase Nudge button is held (`phase_nudge`: `none`, `down` or `up`, set by `transport.phase_nudge`), whether a start waits for an outside clock's or Link session's frame, whether EXT is on (`external_sync`, set by `transport.set_external_sync`), and whether the audio engine runs so the transport can play. Every `transport.set_*` setting reads back here. Changes nothing. Use it to check where the song is before and after `transport.play`, `transport.stop`, `transport.locate`, or `transport.set_loop`.

Default keys: none.

Arguments: none (send `{}`).

Result: [`TransportState`](#transportstate).

### `transport.stop`

**Stop**. Permission: `read`. Contexts: `global`.

Stops playback, as the Control Bar's Stop button does, and keeps the position where it stopped, so `transport.continue` can resume there. Run it again while stopped to return the insert marker and the play position to the start of the arrangement (1.1.1), as pressing Stop twice does. It changes nothing in the project.

Default keys: none.

Arguments: none (send `{}`).

Result: nothing (`null`).

### `transport.stop_recording`

**Stop Recording**. Permission: `read`. Contexts: `global`.

Stops recording, the same as `transport.set_recording` with `recording` false, and without asking the person. The recording becomes a clip on its track; playback goes on. It does nothing when the transport isn't recording.

Default keys: none.

Arguments: none (send `{}`).

Result: nothing (`null`).

### `transport.tap_tempo`

**Tap Tempo**. Permission: `edit`. Contexts: `global`.

Taps the tempo, as the Control Bar's Tap Tempo button does: each tap is one beat of the time signature, and from the second tap of a run every tap sets the song's tempo to the mean of the run's last eight intervals or fewer, to the hundredth within 20 to 999 BPM, as one undo step named Tap Tempo. A tap more than 3 seconds after the last starts a new run, and one less than 60 ms after it is ignored. `at` is the tap's frame on the engine clock, which counts the frames the engine has processed; left out, the tap is now. With Start Transport With Tap Tempo on and the song stopped, the tap that makes the run as many taps as the time signature's numerator starts the song one beat later, on a frame the result gives as `start_at`; Stop before it cancels the start. Refused while the song has tempo changes. The result gives the run's `taps`, its `tempo` and `start_at`; `transport.state` reports them under `tap_tempo`.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `at` | integer or null | no | The tap's frame on the engine clock; left out, the tap is now. |

Result: [`TapTempo`](README.md#taptempo).
