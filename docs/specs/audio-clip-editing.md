# Audio clip editing: Reverse, Crop, Consolidate, and Consolidate Time to New Scene

- **Status:** partial (R1 to R6, WP-4.20, R7 to R13, WP-4.7, and R14 to R28, WP-4.13, are built; R29 for WP-6.22)
- **Work packages:** WP-4.7 (Reverse, R7 to R13), WP-4.13 (Crop, Consolidate, and Consolidate Time to New Scene, R14 to R28, built), WP-6.22 (Crop and Consolidate on take lanes, R29). The processed files of R1 to R6 are WP-4.20's, which both use, and so do freezing and bounce ([freeze and bounce](freeze-and-bounce.md)).
- **Parity-matrix row:** Audio clips and warping: Clip pitch, reverse, RAM mode, high-quality interpolation (reverse); Split, Crop, Crop to Time Selection (crop); Consolidate
- **Checked against:** the Live 12 reference manual (online edition), read 17 October 2026, and the UI parity reference's observations of Live 12.4.3 on macOS (10 October 2026)

## The behaviour

Four edits make new audio from a clip's audio. **Reverse** gives an audio clip a backwards copy of its file, with its markers mirrored so the clip plays the same stretch of sound backwards; in the Arrangement it reverses a time selection across several clips. **Crop** shortens what a clip holds to what it plays: an audio clip's region is written as a new, shorter file, and a MIDI clip loses the notes outside it. **Consolidate** (Cmd-J) joins the material in a selection into one new clip per track: for audio, a new file rendered from the clips as they play, before the track's devices; for MIDI, one clip holding every note. **Consolidate Time to New Scene** does the same from an Arrangement time selection into the clip slots of a new Session scene, and leaves the Arrangement as it was. None of them changes a source file: each new file goes into the project's `Samples/Processed/` folder, and every edit is one undo step.

This spec covers what each edit does to the clip and to the disk, where its files go, and how undo and the agent API treat it. It leaves to other specs: the warp map and warped playback ([warping](warping.md), [warp modes](warp-modes.md)), and the Clip View's Sample Editor in which the Audio panel's Reverse sits ([sample editor](sample-editor.md), WP-4.10 and WP-4.10b); Clip Transpose and Detune, which WP-4.7 builds beside Reverse ([warp modes](warp-modes.md)); what a frozen track allows ([freeze and bounce](freeze-and-bounce.md)); and the reversing, cropping, and normalising inside the sampler devices' displays, which are their own (IMP-28, WP-5.15). Linked-track editing, which in Live applies Consolidate to every linked track, is Phase 6's.

## Rules

**The files these edits write (WP-4.20)**

- **R1.** Reverse, Crop on an audio clip, and Consolidate on audio write new files into the set's project folder: `Samples/Processed/Reverse/`, `Samples/Processed/Crop/`, and `Samples/Processed/Consolidate/`, each made the first time it's needed. They never change, move, or delete the file a clip played before. (S1, S3, S6)
- **R2.** Each new file is a WAV of 32-bit floating-point samples, as recordings are (recording R3). A reversed or cropped file holds the source file's own samples at its own sample rate and with its own channels, so it reads back as the source's decoded frames exactly, reversed or cut to the region. A consolidated file is rendered at the engine's rate (R20). Beatlayer's own: Live takes a consolidated file's rate and bit depth from its settings (S7), and Beatlayer writes what loses nothing. (S7, S12)
- **R3.** A new file is named after its source and the edit, Beatlayer's own: `<source file's name> Reverse.wav` and `<source file's name> Crop.wav`, and `<track label> Consolidate [<stamp>].wav` with the stamp of recordings' names. A name already taken in the folder gets ` 2`, ` 3`, and so on before its extension, so nothing is overwritten. A file whose bytes are already one of the set's media isn't written again: the clip names the media the set has. (S12)
- **R4.** Each new file joins the set's media table with its path relative to the project folder and its content hash, and is saved with the set like any media. Undoing the edit leaves the file on disk, and redoing it uses the same file. (S12)
- **R5.** In a set that has never been saved, the new files go into the Temporary Folder, the File & Folder settings' path (L-SET-015), whose default is a `Temporary` folder in Beatlayer's own application-data folder, each in a folder of its kind's name there (`Reverse/`, `Crop/`, and so on). The path is `settings.set_temporary_folder`, read back from `settings.state`. The first save moves each file the set uses from there into the project folder's `Samples/Processed/<kind>/`, R3's naming applying there, and points the media table at its new path. Writing into the Temporary Folder doesn't make a command external: it's the unsaved set's own folder. Beatlayer's own: the manual says only that such files stay in the Temporary Folder until the set is saved. (S1, S3, S6, S9, S11)
- **R6.** The work runs off the audio thread: the file is written on a worker thread while the clip goes on playing what it played, the Status Bar shows its progress, and the edit lands as one undo step once the file is complete, reaching the engine as any clip edit does (audio-clips R12), with no allocation, lock, or wait on the audio thread. A failure, a full disk say, deletes what was written and leaves the set as it was, with a message in the Status Bar. An agent's call returns when the edit has landed. (S1, S13)

**Reverse (WP-4.7)**

- **R7.** Reversing an audio clip makes it play a reversed copy of its file (R1): frame *n* of the new file, in every channel, is frame *L* − 1 − *n* of the source, where *L* is the source's length in frames. The Audio panel's Reverse button (L-CLIP-008) and `clip.reverse` reverse one clip, in the Session View or the Arrangement. (S1, S11)
- **R8.** The clip's settings are mirrored with its file, so it plays the same stretch of sound backwards: a position *t* seconds into the source becomes *L* − *t* in the new file, a region from Start *s* to End *e* becomes one from *L* − *e* to *L* − *s* (the file's end standing in for an End marker the clip doesn't set), the loop brace likewise, and each warp marker keeps its point in the audio: its file position is mirrored and its beat becomes the first marker's beat plus the last marker's beat less its own. The loop switch, gain, transpose, detune, warp mode, fades (which stay at the clip's edges), name, colour, and launch settings don't change. (S1)
- **R9.** A reversed clip's clip envelopes stay where they are in the clip's time, so an envelope that lowers the first half still lowers the first half. (S1)
- **R10.** Reversing a clip whose file is a reversed copy Beatlayer made (R7) gives it back the file the copy was made from, writing nothing, with its settings mirrored back, so reversing twice returns the clip exactly as it was. Beatlayer keeps which file each reversed copy came from in the set's media table. (S1)
- **R11.** In the Arrangement, R (S-ARR-029) and Reverse Clip(s) (C-CLIP-ARR-018) reverse the audio in the time selection on the selected tracks, which selecting clips sets to the span they cover (arrangement-editing R1). Clips the selection's edges cross are split there first (arrangement-editing R8), each part inside is reversed (R7 to R9), and the parts are mirrored within the selection on their tracks, so the selection plays backwards as a whole: a part that started *d* after the selection's start now ends *d* before its end. Beatlayer's own: the manual says only that a selection across several clips is reversed. (S1, S2, S10)
- **R12.** A selection that holds a MIDI clip isn't reversed, and nothing changes; the Arrangement clip's menu shows Reverse Clip(s) on a MIDI clip too, as Live's does, and on one it does nothing. In the Session View, Reverse acts on one clip, and with more than one clip selected it's disabled. (S1, S2, S10)
- **R13.** `clip.reverse` (a clip) and `arrangement.reverse` (tracks and a range in ticks or bars, or the selection) are registered commands (D17) in the `edit` class, each one undo step however many clips it reverses; `clip.reverse` reads back through the query tool's `clip`, field `data`, and `arrangement.reverse` through its `track`, field `clips`. A clip on a frozen track can't be reversed ([freeze and bounce](freeze-and-bounce.md) R8). (S12)

**Crop (WP-4.13)**

- **R14.** Cropping an audio clip writes its region as a new file (R1): the frames from its Start marker to its End marker, or, with the loop on, from the earlier of the Start marker and the loop's start to the loop's end. Crop Clip in the clip's menus (C-CLIP-ARR-017, C-CLIP-SES-014; C-SLOT-005 for the selected slot's clip) and Cmd-Shift-J (S-ARR-003 in the Arrangement, S-SES-028 in the Session View) crop the selected clip; in the Sample Editor's menu the same command is labelled Crop Clip Sample. (S3, S10)
- **R15.** A cropped audio clip plays the new file and plays, at every frame, exactly what it played before: its Start and End markers, loop brace, and warp markers move back by the region's start, and warp markers outside the region are dropped, with one kept or added at each end of the new file where the warp map needs it to hold the timing. (S3)
- **R16.** Cropping to a time selection crops to the part of the file the selection plays: Crop Clip Sample to Time Selection in the Sample Editor, and in the Arrangement, Crop Clip with a time selection inside a clip (C-TRACK-020), whose edges then move to the selection's. A selection over which the clip goes round its loop isn't one stretch of the file, and cropping to it is refused, with a message naming Consolidate, which writes such a stretch out. Beatlayer's own: the manual doesn't say what Live does there. (S3, S5)
- **R17.** Cropping a MIDI clip writes no file: it deletes the notes that start outside its region, which with the loop on is the loop brace and with it off is from the Start marker to the End marker, and shortens a note that starts inside and runs past the region's end to end there. With a time selection, Crop Clip to Time Selection does the same with the selection's part of the clip as the region. The clip's markers and loop then begin at the region's start. Beatlayer's own: shortening a note that runs past the end. (S3, S4)
- **R18.** `clip.crop` (a clip, and optionally a `range` in the clip's time for the time-selection form) is a registered command, one undo step, reading back through the query tool's `clip`, field `data`. It's in the `edit` class, and destructive as well when it would remove anything (audio outside the region, or notes), decided from its arguments against the set as it is, as agent-permissions R1 and R11 decide theirs. A clip on a frozen track can't be cropped (freeze and bounce R8). (S12, S13)

**Consolidate (WP-4.13)**

- **R19.** Consolidate (Cmd-J, S-ARR-002; Edit ▸ Consolidate, M-EDIT-033; the clip's and time selection's menus, C-CLIP-ARR-026, C-TIME-019) replaces the material in a range on each selected track with one new clip spanning the range: the time selection, or the span of the selected clips (arrangement-editing R1). Clips the range's edges cross are split there first and the parts inside replaced; a track with no clip in the range gets nothing; the new clips are selected. (S6, S10)
- **R20.** On an audio track, the new clip's file is what the track's clips play over the range, rendered offline at the engine's rate through the clip player under the song's tempo map, before the track's devices and mixer: every clip with its gain, fades, warping, pitch, and its own settings' clip envelopes, and silence where no clip plays. The file has one channel when its two channels are equal at every frame, and two otherwise (rule G3). (S6, S12)
- **R21.** The file is normalised, its largest sample magnitude brought to full scale, and the clip's gain is set to the inverse, so it plays at the level it had; a silent range is written as it is, at 0 dB. The new clip's Start marker is the file's start, it is warped with markers that hold every frame on the beat it was rendered at, and its loop is on with the brace over the whole file, so dragging its right edge repeats it. It takes the name of the first clip in the range. Beatlayer's own: the loop and the name. (S6, S7; [warp modes](warp-modes.md) R4)
- **R22.** Played back, the consolidated audio clip gives the frames the range gave before, to within the rounding of R21's gain: the difference stays below −120 dBFS. (S6, S7)
- **R23.** On a MIDI track, the new clip holds every note the range plays, at the positions it plays them, with each repetition of a looped clip written out, and the notes cut at the range's edges as a split cuts them (arrangement-editing R8); its loop is on over its whole length, so dragging its edge adds repetitions. The source clips' clip envelopes are written into it at the positions they played. No file is written. Beatlayer's own: the clip envelopes. (S6)
- **R24.** On a frozen track, Consolidate is allowed, as in Live, and the new clip plays the frozen audio over its span (freeze and bounce R7). (S14)
- **R25.** `arrangement.consolidate` (tracks and a range in ticks or bars, or the selection) is a registered command in the `destructive` class, since it deletes the clips it replaces, and one undo step; it reads back through the query tool's `track`, field `clips`. (S12, S13)

**Consolidate Time to New Scene (WP-4.13)**

- **R26.** Consolidate Time to New Scene (Create ▸ Consolidate Time to New Scene, M-CREATE-007; the time selection's menu, C-TIME-020) inserts a scene directly after the selected scene, or after the last scene when none is selected (Beatlayer's own), and gives each track the time selection covers that holds a clip in it one new clip in that track's slot of the new scene, made as R20 to R23 make Consolidate's. The Arrangement is left as it was. (S8, S10)
- **R27.** `arrangement.consolidate_to_scene` (tracks and a range, or the selection) is a registered command in the `edit` class, one undo step, reading back through the query tool's `song`, field `scenes`. (S12)

**Menus and keys (WP-4.7 and WP-4.13)**

- **R28.** Each item sits at its menus.md row with its keys, as the menus' and context menus' specs place them: enabled when what it acts on is selected (an audio clip or a selection holding audio for Reverse; a clip for Crop; clips or a selection holding clips for Consolidate; a time selection holding clips for Consolidate Time to New Scene), and disabled otherwise, as the Edit and Create menus show them in a new set. R, Cmd-J, and Cmd-Shift-J are bound in their contexts (S-ARR-029, S-ARR-002, S-ARR-003, S-SES-028), and the Audio panel's Reverse is a button in L-CLIP-008's place. (S10, S11)

**Take lanes (WP-6.22)**

- **R29.** Crop and Consolidate act on a take lane as on a main lane ([comping](comping.md) R27). Crop acts on a take-lane clip as on any clip (R14 to R18). Consolidate with a range on take lanes replaces each selected lane's material in the range with one new clip on that lane, rendered from that lane's clips alone as R20 to R23 render a track's, whatever the main lane or another lane holds there, and whether the lane is auditioned or not; the new clip is a take like any on the lane. A range over a track's main lane and some of its take lanes consolidates each of those lanes on its own. (S6, S15)
