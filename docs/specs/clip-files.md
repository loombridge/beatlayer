## The behaviour

A clip dragged from the Session View or the Arrangement onto a folder in the browser is saved there as a file of its own, a clip file. It keeps everything the clip holds, its notes or its audio and warp markers, its envelopes and settings, and the devices of the track it was on, so it can be saved as an idea and used in any set. The browser lists it with the other files, and the Clips label lists every clip file in the places. Selecting an audio clip file previews it as the clip plays. Dragging the file onto a track places the clip there, and dragging it onto an empty track or into the drop area also brings back the track's devices; a track that already has clips or devices keeps its own devices and takes only the clip.

The clip file's format is Beatlayer's own. The audio a clip plays isn't inside the file: Collect Files on Export decides whether saving copies it beside the file or leaves the file referring to it where it is, as Live does.

This spec covers the clip file, saving a clip, the Clips label, placing a clip file in a set, and previewing one. It leaves Collect Files on Export to [file management](file-management.md), and to [set exchange](set-exchange.md) saving several Session clips as a set and the Session clips of a set opened in the browser, which behave as clip files do. Exporting a MIDI clip as a Standard MIDI File is [MIDI clips](midi-clips.md)'.

## Rules

- **R1.** A clip file is a file of Beatlayer's own format, with the extension `.blclip`: one zstd frame with its checksum holding JSON, as a set file is, beginning with its format (`beatlayer-clip`), its schema version and the version of Beatlayer that wrote it. It holds one clip as the set saves it: whether it's audio or MIDI, its name, its length, loop and markers, an audio clip's warp settings and warp markers, a MIDI clip's notes with all their values, its clip envelopes and its launch settings. A clip file from a later version of Beatlayer, or a damaged one, is refused and changes nothing. IDs in the file mean nothing: placing it gives everything in it new ones. (S1, S3, S8)
- **R2.** A clip file also holds the device chain of the clip's track as it was when the clip was saved, every device with its state as a rack preset holds it ([racks](racks.md) R42: racks whole, a plug-in's own saved state), and a media table naming each audio file the clip and those devices play, by content hash, size, and path relative to the clip file's folder. (S1, S2, S3)
- **R3.** Dragging one clip, from a Session slot or an Arrangement lane, onto the browser saves it as a clip file: onto a folder's row in a place (the User Library, Current Project, a folder of the person's, or a folder inside one), into that folder; onto a place's label, into the place's folder; onto the Clips label, into the User Library's `Clips` folder. Dragging several Session clips saves them as a set ([set exchange](set-exchange.md) R12); several Arrangement clips save nothing (Beatlayer's own). Saving changes nothing in the set. (S1, S2, S3, S4, S7)
- **R4.** The file is named after the clip, or after its track when the clip has no name, with `.blclip` added; a name already taken in the folder gets " 2", " 3" and so on, as device presets do ([device chains](device-chains.md) R17). It's written whole or not at all, and the Status Bar names it. The new row is then selected with its name ready to edit: typing and Enter rename the file, and Esc keeps the name it has. (S4, S8)
- **R5.** Saving a clip copies the audio files it and its track's devices play, or leaves the clip file referring to them where they are, as Collect Files on Export says ([file management](file-management.md) R7 to R9). (S1, S2)
- **R6.** The browser lists clip files with the other files it opens (browser R6). The Clips label lists every clip file in the places, by name, each naming its folder, as the Samples label lists audio files, and search under it finds clip files only (browser R9). An audio clip file carries the Content tag Audio Clip, and a MIDI clip file MIDI Clip ([browser tags](browser-tags.md) R7). (S2, S6, S7)
- **R7.** A clip file dragged over the Arrangement or the Session View highlights where it would go, as audio files do (browser R13, [the Session View](session-view.md) R18), and dropping it places the clip: on an Arrangement track of its kind (audio or MIDI) at the drop position, snapped to the grid while snapping is on; in the Arrangement's drop area, on a new track of its kind below the last track; in an empty Session slot on a track of its kind; in the Session's drop area, on a new track of its kind, in the scene it was dropped at. Several clip files go in as several audio files do: one after another on one track, or in one slot after another down the scenes; with Cmd (Ctrl) held, each on a track of its own, across the tracks at one scene in the Session (S-SES-017). A track of the other kind, a group or return track, Main, and a slot already holding a clip take no clip file: nothing is highlighted and nothing changes. A clip file dropped from Finder or Explorer lands the same way. (S1, S7, S8)
- **R8.** A clip placed on a track that has no clips and no devices, or on a new track, brings its device chain (R2) onto the track first, every device with its state, plug-ins loaded from their saved state. A clip placed on a track that has clips or devices brings no devices: the track keeps its own chain. A new track is named after the clip file. (S1, S3)
- **R9.** A placed clip is the clip the file holds, its positions in beats from where it lands: a warped audio clip and a MIDI clip keep their length in beats, and an unwarped audio clip lasts as long as its audio plays at the set's tempo where it lands (Beatlayer's own). Its clip envelopes come with it: on a track that took its device chain, those of devices follow the new devices; on a track that kept its own chain, those of the track's mixer stay and those of devices it didn't bring are left out (Beatlayer's own). (S1, S3)
- **R10.** Enter, or a double-click on a clip file, places it as R7 and R8 say: with the Arrangement shown, on the selected track at the insert marker when that's a track of the clip's kind, otherwise on a new track below the last one, as browser R14 does for audio files; with the Session View shown, in the selected slot when it's empty and on a track of the clip's kind, otherwise on a new track in the selected scene (Beatlayer's own). (S8)
- **R11.** Each placement, with any new track and devices it brings, is one undo step, named "Insert Clip" as browser R13's is. (S8)
- **R12.** The audio a placed clip and its devices play is registered in the set's media store and media table (browser R15), from the path the clip file's media table gives, relative to the clip file's folder. A file missing there, or changed, is found by its content as [file management](file-management.md) R6 finds a set's missing files, searching the clip file's folder, the set's project folder, the User Library and the places; one still missing is listed as missing as a set's missing files are, the clip is placed all the same, and the Status Bar says how many files are missing. (S8)
- **R13.** With the Preview switch on, selecting one audio clip file previews it, and Shift-Enter or Right previews it with the switch off (browser R11). It previews as browser R19 to R23 preview an audio file, but through the clip's own warp settings, warp markers, loop and start and end rather than the file's defaults: warped and looping at the set's tempo with Raw off, from the clip's start at the audio's own speed, once, with Raw on (Beatlayer's own reading of S3 and S5). A clip file whose audio is missing doesn't preview, and the preview strip says why. (S3, S5, S8)
- **R14.** A clip file is read on a background thread, with a size limit as a set file has, and a file the reader refuses never crashes Beatlayer; the reader is fuzzed as the set file's is. (S8)
- **R15.** Every action above is a registered command. `clip.save_file` saves a clip as a clip file in a folder, with a name, and returns the file's path; it writes outside the project, so it's external, and reads back in `browser.state` (the new row). `browser.add_to_arrangement`, `browser.load_selected`, `session.drop_files` and `browser.preview` take clip files as they take audio files, and the browser's rows name a clip file's kind (audio or MIDI clip); a placed clip reads back through the query tool's `clip`, `track` and `device` objects. (S8)
- **R16.** With the Preview switch on, selecting one MIDI clip file previews it, as Shift-Enter or Right do with the switch off: the clip is rendered on a background thread through the device chain the file holds (R2), at the set's tempo, for one pass of its loop, or its length when it doesn't loop, with plug-ins made from their saved state as an offline render makes them ([offline plug-in renders](offline-plugin-renders.md) R3, R11); the render then previews as a warped audio file does (browser R19 to R23), starting on the next bar while the transport runs and looping; with Raw on it plays once from its start, at once (Beatlayer's own). A MIDI clip file whose chain has no instrument previews nothing, and the preview strip says why. The render is kept until the file or the set's tempo changes, so selecting the file again doesn't render it again. (S3, S5, S8; the render is Beatlayer's own way of previewing)
- **R17.** A clip that plays with a groove saves the groove in its clip file. Placing the clip puts that groove in the set's Groove Pool, or, when a groove with the same content is there, has the clip use that one (Beatlayer's own). (S1)
