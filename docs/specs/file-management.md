## The behaviour

You make a set the one a new set starts from, and save templates to reuse a setup. You collect a set's external files into its project folder so the set no longer depends on files elsewhere. When a set is opened and a file it uses can't be found where it was, Beatlayer looks for it again by its content and relinks it. This spec covers the default set, templates, Collect All and Save, finding and relinking missing files, Collect Files on Export, which decides whether saving a clip or tracks to the browser copies the files they use, and the File Manager: the window onto a set's, a project's and the User Library's files, where missing files are repaired, external files collected and unused files found. It also covers opening a set's backups and saving a copy of a set. Where the commands sit in the File menu is in menus.md; how a file becomes a clip and where a set's media table lives are in audio-import.md and app-shell.md.

## Rules

- **R1.** On start-up and after New Set, the set is the saved default set when one has been saved and can be read, otherwise the factory default set. (S1, S5)
- **R2.** `set.save_as_default` saves the open set as the default set, which R1 then uses. It is saved as a copy, so the open set keeps its own file, its name, and its undo history, and stays open. `path` names the default set's file (`.blset` is added if it's missing); left out, it goes in the User Library's `Templates` folder, or beside the application's preferences when there is no User Library. The choice is kept for the next start. (S1)
- **R3.** `set.save_as_template` saves the open set as a template in the User Library's `Templates` folder, making that folder the first time. `name` names the template, without the `.blset` extension; left out it takes the open set's name. As in R2 the open set is unchanged. A template is an ordinary set file: it can be opened, or set as the default set with R2. (S1)
- **R4.** `set.collect_all_and_save` copies every media file the set uses that lives outside its project folder into the project's `Samples/Imported` folder, re-points the set's media table at the copies, and saves the set, so the set no longer depends on files elsewhere. A name already taken in `Samples/Imported` gets ` 2`, ` 3`, and so on before its extension, so nothing is overwritten. It fails if the set has never been saved, so it has no project folder to collect into. The result's `files` is how many files were copied. (S2)
- **R5.** The browser's Templates label lists the set files in the User Library's `Templates` folder (browser R2); with no User Library it says so. (S1)
- **R6.** Files the set uses that are missing or changed are found again by their content (audio-import R10): Beatlayer searches the set's project folder, the User Library, the folders the files were last in, and any folders a call gives, each with its subfolders; it hashes only files of the recorded length. A file with one candidate is relinked to it, whatever its name; a file with several keeps its row, and the person chooses (R14). This runs by itself when a set is opened, and on demand as `set.relink_missing`. The set's media table is re-pointed at what was found, so the next save keeps the new paths; the Status Bar says how many were relinked. The result's `files` is how many were relinked. (S3, S4)
- **R7.** Settings ▸ Library (L-SET-016) has Collect Files on Export, a chooser of Always, the choice in a new install, Never and Ask, kept between launches (`settings.set_collect_files_on_export`, an edit to preferences read back in `settings.state`). It decides what happens to the audio files a clip, Session clips or tracks use when they're saved to the browser as a clip file or a set ([clip files](clip-files.md) R5, [set exchange](set-exchange.md) R14). Collect All and Save (R4) doesn't follow it, nor do presets: a rack preset carries its samples inside it ([racks](racks.md) R42). (S6, S8)
- **R8.** Always copies every such file that isn't already in the saved file's project (R9); Never copies none, and the saved file names each file where it is, by its path relative to the saved file's own folder. Ask, when the item uses a file outside that project, asks with Copy, Don't Copy and Cancel: Copy does what Always does, Don't Copy what Never does, and Cancel saves nothing. The commands that save to the browser take `copy` to answer for the person; while the setting is Ask, one given no `copy` is refused, so an agent asks the person first. (S6)
- **R9.** Copies go into the `Samples/Imported` folder of the project the saved file lands in: for a file saved into a project folder, one holding a set, or into a folder inside one, that project folder; for a new set, the project folder it's given ([set exchange](set-exchange.md) R13); for a file in the User Library, the User Library. A clip file saved into a folder that's in neither gets a `Samples/Imported` folder beside it (Beatlayer's own). A name already taken there gets " 2", " 3" and so on, as R4's copies do, and a file with the same content already there is used rather than copied again. The saved file names the copies by their paths relative to its own folder. (S6, S7; Beatlayer's own where S6 is silent)

**The File Manager (WP-6.63)**

- **R10.** File ▸ Manage Files (M-FILE-007), View ▸ File Manager (M-VIEW-007), a click on the Status Bar's missing-files message (R12), and Manage Project in a project folder's context menu in the browser (C-BROWSER-014) show the File Manager in the detail area's place (L-OTH-002), in front of the Clip or Device View; its close button, or the menu items again, hide it (`view.toggle_file_manager`; view state, not saved and not an undo step). Its Manage Set, Manage Project and Manage User Library buttons choose its view: Manage Set the open set's files, Manage Project a project's (the open set's, or the folder whose menu opened it), Manage User Library the User Library's. Collect and Save sits at its foot (R15). The list of a set's plug-ins ([plugin list](plugin-list.md) R1) takes the same place: showing either hides the other (Beatlayer's own). (S9, S10, S15)
- **R11.** Manage Set lists every file the open set uses, one row each, with its name, its size and its Location (Missing, User Library, Project or External); a row opens to list the clips and devices that use it. A file dragged from the browser onto a row replaces it for every clip and device that uses it, as one undo step, each audio clip keeping its warp markers only as [warping](warping.md) R27 says. A row's Hot-Swap button arms the browser at the file's folder, and Enter or a double-click on a file there replaces it the same way, the browser staying armed. A row's Edit button opens the file in the external sample editor and takes the edited file back for every clip that uses it, as [the Sample Editor](sample-editor.md) R16 does for one clip. (S9, S16)
- **R12.** When the open set uses files that are missing or changed after opening's search (R6), the Status Bar says how many, and stays saying so until none is (the wording is Beatlayer's own). Clips and devices that play a missing file play silence, and the query tool reports them as offline. A click on the message shows the File Manager's Manage Set view at its Missing Files section. (S11)
- **R13.** The Missing Files section lists each missing file, with what uses it. A file dragged from the browser onto a missing file's row (I-DROP-012) relinks it to that file, whatever its content: a file of other content becomes the file of every clip and device that used the missing one, as R11's replacing does, as one undo step. (S11, S15)
- **R14.** The Automatic Search section has Search Folder, with Set Folder… to choose the folder, Search Project and Search Library switches, and Go. Go searches the switched-on places, each with its subfolders, by content as R6 does: a missing file with one candidate is relinked to it; one with several keeps its row, which offers Hot-Swap, arming the browser with the candidates listed, so Enter or a double-click relinks to the one chosen while the music plays; one with none says so on its row. This replaces R6's first match: whenever a file has several candidates, the person chooses, and opening a set relinks only files with one. (S3, S11)
- **R15.** The External Files section lists the files used from outside the project (in Manage Set, the set's project; in Manage User Library, the User Library), grouped by where they are: other projects, the User Library and elsewhere. Each group shows how many files it has and their size, a Show button that lists them in the browser as search results are listed, and a Collect Into Project switch, on for other projects and elsewhere and off for the User Library (Beatlayer's own defaults). Collect and Save copies the switched-on groups' files into the project's `Samples/Imported` folder, as R4 copies, re-points every set that uses them, and saves. File ▸ Collect All and Save first asks the same question, with the same groups and switches; R4's `set.collect_all_and_save` takes the groups, all of them when none are given. (S2, S12)
- **R16.** Manage Project shows the Missing Files, Automatic Search and External Files sections for every set in the project folder, then Unused Files (R17) and Packing ([set exchange](set-exchange.md) R16). Manage User Library shows the same for the clip files, presets and sets in the User Library, without Packing. A Collect and Save or a relink there rewrites each set or clip file it changes, a set keeping the version it replaces in its project's `Backup` folder as a save does ([the app shell](app-shell.md) R19); the open set changes as an edit, one undo step. (S10)
- **R17.** The Unused Files section lists the audio files in the project folder (or the User Library) that no set, clip file or preset there uses, grouped by kind: Recorded, Imported, Processed (by its kind) and Other (Beatlayer's own groups, after its folders). Each group shows its count and size and a Show button. Selecting a file previews it, as the browser does (browser R11). Delete, by the Delete key or the file's context menu, asks first, warning that another project may use the files, then moves the selected files to the system's trash (Beatlayer's own: nothing is erased outright). (S13)

**Backups and copies (WP-6.63)**

- **R18.** File ▸ Open Beatlayer Set Backups (M-FILE-008) is a submenu listing the open set's backups in its project folder's `Backup` folder ([the app shell](app-shell.md) R19), newest first, each by its time in local time (Beatlayer's own labels); it's disabled while the set has none. Choosing one opens it in the open set's place, asking first about unsaved changes as Open does ([the app shell](app-shell.md) R4), as the set itself: the set keeps its file and name, its song is the backup's, and it opens with an empty undo history and unsaved, so Save makes the backup the set's current version and keeps the version it replaces as a backup (Beatlayer's own). The save history ([crash recovery](crash-recovery.md) R13, R16) lists the same backups and restores one into the open set as one undo step instead. (S14, S15, S16)
- **R19.** File ▸ Save a Copy... (M-FILE-011) asks for a name and a folder and saves a copy of the open set there, placed as Save As places a set ([the app shell](app-shell.md) R17, R20): in the folder when it's a project folder, otherwise in a new "<name> Project" folder. The copy's media table names the same files, by paths from its own project folder. The open set keeps its file, its name, its undo history and whether it has unsaved changes. (S14, S16)

**Commands and access (WP-6.63)**

- **R20.** Every action above is a registered command: `view.toggle_file_manager` (read) shows and hides the File Manager on a view; `file_manager.state` reports a view's sections and rows (external, as it lists files outside the project); `file_manager.replace_file` replaces or relinks a file (edit, or external when the new file is outside the project); `file_manager.hot_swap` arms the browser to replace a file, `file_manager.edit_file` opens one in the external sample editor and `file_manager.set_search_folder` names the folder the Automatic Search looks in; `set.relink_missing` takes the Automatic Search's switches and folder and returns each file's candidates; `set.collect_all_and_save` takes the groups to collect, and the project to collect for; `file_manager.delete_unused` moves files to the trash (destructive); `set.backups` (read) lists the backups, `set.open_backup` opens one, refusing while the open set has unsaved changes as `set.open` does, and `set.save_copy` saves a copy (both external). Each reads back in `file_manager.state`, `set.backups`, the query tool's `song`, or its result. (S16)
- **R21.** The File Manager builds only the rows on screen, and every part reaches assistive technology: its view buttons as a tab list, each section as a group with its name and count, each row as a list item naming its file, its location and what uses it, and the switches and buttons with their names and states. The keyboard moves through it as through the browser's list (browser R7, R17). (S16)
