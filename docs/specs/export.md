# Export audio: the range, file types, bit depth, sample rate, dither, and normalise

- **Status:** partial (R1 to R23 each have a passing test; Render as Loop, R24 to R27, is WP-4.17's; the dialog is not built yet)
- **Work packages:** WP-1.12; WP-4.17 (Render as Loop, R24 to R27)
- **Parity-matrix row:** Files and export: Export (Main; normalise); Export formats (WAV, AIFF, FLAC at 16, 24, or 32 bits)
- **Checked against:** the Live 12 reference manual (online edition), section 5.1.3, read 11 October 2026, and the UI parity reference's observations of Live 12.4.3 (10 October 2026).

## The behaviour

Export Audio/Video, in the File menu (⇧⌘R, Ctrl-Shift-R), renders the set's output to an audio file. Live opens a modal dialog for the settings: which part of the song to render (Render Start and Render Length, the whole set unless a time selection was made in the Arrangement first), what to render (the Main output, every track, or some), and how to encode it (WAV, AIFF, or FLAC at 16, 24, or 32 bits, a sample rate, dither below 32 bits, and Normalize). Then the person chooses where the file goes, and Live renders it offline, as fast as the computer allows, with a progress bar whose Cancel stops the render and deletes the partial file.

Beatlayer renders the range through the same engine code that plays the set on a device (`bl_engine::Offline`, the code behind `bl-cli render` and the golden tests), converts the sample rate where needed, normalises, dithers, quantises, and encodes, writing to a hidden file beside the destination that's moved into place only when it's complete. So a cancelled or failed export leaves nothing behind, and an export at the engine's rate holds exactly the samples a golden render holds.

This spec covers the Main output to WAV, AIFF, and FLAC, the range, bit depth, sample rate, dither (the non-proprietary kinds), normalise, Render as Loop (WP-4.17), cancelling, and the commands that reach them (`export.audio`, `bl-cli export`). It leaves to other packages: exporting each track, the selected tracks, or one track, and Include Return and Main Effects (WP-2.26); MP3 (WP-2.26); Convert to Mono and Create Analysis File (see "Not built yet" below); video (Phase 9); real-time rendering through external hardware (M5); and the dialog itself, whose controls the UI parity reference doesn't record yet (L-OTH-003 says only that it's modal; see R16).

## Rules

- **R1.** The range is a start and an end in the song, in ticks. Unless a range is given, it's the Arrangement's time selection if there is one, and otherwise the whole set: from 1.1.1 to the end of the last clip. A set with no clips and no selection has nothing to export, and the export is refused. A range must start at 1.1.1 or later and be longer than zero. (S2, S8)
- **R2.** The export renders the Main output: the post-fader sum of every track, as the set plays on a device. A track whose Audio To is Ext. Out isn't in the Main output, so it isn't in this export; exporting that track on its own (WP-2.26) renders it. (S2; [routing.md](routing.md), R3)
- **R3.** The range plays straight through, from its start to its end, as Play from an insert marker at the start plays it: the first frame is the frame the start falls on through the tempo map, and the file holds the frames from there to the frame the end falls on. The Arrangement loop doesn't wrap the render. (S2, S8)
- **R4.** Rendered at the engine's rate as 32-bit float, the file holds the engine's samples exactly. As 16 or 24 bits without dither or normalise, each sample is the engine's rounded to the nearest step (halves away from zero) and clipped to the range, as the golden references round theirs, so the export of a golden fixture nulls against its reference to the bit. (S5; the golden harness)
- **R5.** The file types are WAV, AIFF, FLAC, and MP3, and the bit depths 16, 24, and 32. 16 and 24 bits are integers; 32 bits is IEEE floating point, written as WAV format 3 and as AIFF-C with `fl32` samples. FLAC holds integers only, so a 32-bit FLAC export is refused. MP3 is lossy and has no bit depth (R23). The file type is the one asked for, or else the destination's extension's (`.wav`; `.aif` or `.aiff`; `.flac`; `.mp3`), and the two must agree. (S4)
- **R6.** At a sample rate at or above the engine's, the engine renders at the export's rate, with every clip's file converted to it. At a lower rate, the engine renders at its own rate and the render is converted down, with the media converter (aliasing below −100 dB), aligned to the render (the converter's delay removed), and `ceil(frames × to ÷ from)` frames long. The engine's rate is the audio device's, or the rate set in the audio settings, or 48 kHz when neither is known. Rates from 8 kHz to 384 kHz are accepted. (S3, S9)
- **R7.** Dither applies only below 32 bits. No Dither adds nothing. Rectangular adds noise spread evenly over one step (±½ step) before rounding; Triangular adds the sum of two such noises (±1 step, a triangular distribution). Triangular is the default. The noise comes from a generator seeded the same way for every export, so the same export repeats bit for bit. Noise Shaped adds Beatlayer's own noise-shaped dither: a triangular dither and the rounding error both pass through a second-order high-pass filter, so the noise falls in the 2–5 kHz region hearing is most sensitive to and rises above 15 kHz; its filter state is kept per channel. It follows Cutler's error-feedback noise shaping (U.S. Patent 2,927,962) and the audibility weighting of Lipshitz, Wannamaker and Vanderkooy ("Minimally audible noise shaping", J. Audio Eng. Soc. 39(11), 1991). It is not a reproduction of any proprietary dither, and it takes the place of Live's three POW-r modes. (S4, S10)
- **R8.** Normalize multiplies the whole export, after any rate conversion and before dither and quantisation, by the gain that brings its largest sample magnitude to full scale (0 dBFS). As 32 bits, the largest sample is 1.0; as 16 or 24 bits, it's the largest step, clipped where full scale has no positive step. A silent export isn't changed. Without Normalize, nothing is. (S3)
- **R9.** The render runs offline, block after block on one thread, as fast as the computer allows, with no audio device. Its speed, the song's length divided by the time the render took, is reported. (S5)
- **R10.** The file is written to `.<name>.partial` beside the destination, and moved into place only when it's complete; with Normalize, the render first goes to a scratch file, `.<name>.render`, beside it. Cancelling, or any failure (a disk error, a render that isn't finite), deletes both and leaves the destination as it was: no file, or the file that was there before. (S5)
- **R11.** A file already at the destination is replaced only when the export is told to replace it; otherwise the export is refused before anything renders.
- **R12.** The file has the engine's channels: two, the Main output's left and right. (S10, rule G3; Convert to Mono isn't offered)
- **R13.** A clip whose audio file is missing or changed plays silence, as on a device, and the result names its media. (S5; [audio-clips.md](audio-clips.md), R14)
- **R14.** The same set and settings export the same bytes every time, at any block size. (S10)
- **R15.** `export.audio` runs an export by ID with JSON arguments (D17): the destination `path`, `bit_depth` and `sample_rate` (required), and optionally `file_type`, `dither` (Triangular), `normalize` (off), `start` and `length` (R1's range), and `replace` (R11). It's in the `external` class, because it writes a file outside the project, so an agent asks first; its result says where the file went, its format, range, length, peak, the normalise gain, the render's speed, and any missing media. `bl-cli export` runs the same command on a headless shell. (S1)
- **R16.** The File menu shows Export Audio/Video... (M-FILE-015) in Live's place with ⇧⌘R, and ⇧⌘R (Ctrl-Shift-R) is kept for it (S-FILE-007). Both open the Export Audio/Video dialog (L-OTH-003), which isn't built yet, so the item is shown disabled and the key does nothing. (S6, S7)
- **R17.** `export.audio` takes `rendered_track`: `main` (the default), `all_tracks`, `selected_tracks`, or `{ "track": <id> }`, as Live's Rendered Track does. A single track renders its post-fader output: its own devices, volume and pan, without the processing of a group it sits in, its sends' return tracks, or the Main's devices and fader. (S2, S3; WP-2.26 part 1, [#2](https://github.com/loombridge/beatlayer/pull/2))
- **R18.** `include_return_and_main_effects` renders an individual track with its sends' return tracks and the Main's devices and fader, as it sounds soloed in the set; it's refused with `rendered_track: main`. (S3)
- **R19.** `all_tracks` exports every audio, group and return track and the Main, and every MIDI track with an instrument or an audio effect, each to its own file; a MIDI track with neither is skipped, and one with an audio effect but no instrument renders silence. `selected_tracks` follows the same rules for the selected tracks. Every file in one export has the same range and length. (S2)
- **R20.** A multi-track export names its files beside `path` as `<stem> - <track name>.<extension>`, with characters a file name can't hold replaced.
- **R21.** A multi-track export renders each file under a hidden temporary name; cancelling or a failure leaves none of them, temporary or finished. If moving the finished files into place fails part-way, the files already moved stay. (R10)
- **R22.** Normalize applies to each file of a multi-track export separately.
- **R23.** An MP3 export writes 320 kbps CBR at one of MP3's sample rates (8,000, 11,025, 12,000, 16,000, 22,050, 24,000, 32,000, 44,100 or 48,000 Hz), one or two channels; `bit_depth` and `dither` are ignored; a rate MP3 can't hold is refused before the render. The LAME tag's delay and padding are written so a decoder trims the decode to exactly the frames written, and it decodes within the audio import spec's MP3 tolerance (R5, below 15 kHz) of the WAV export of the same render. (WP-2.26 part 2, [#47](https://github.com/loombridge/beatlayer/pull/47))
- **R24.** `export.audio` takes `render_as_loop` (off unless given), the dialog's Render as Loop. With it on, the file holds exactly the range's frames, as R3 and R6 give them, with the range's tail (R25) added onto its start, sample by sample, so the file loops without the tail being cut where it wraps and is no longer than the range: its frame *i* is the range's frame *i* plus every tail frame *j*, counted from 0 at the range's end, with *j* mod the range's length equal to *i*, so a tail longer than the range wraps round again. Live does this in two passes, the first measuring the tail and the second writing the file; Beatlayer renders once, and the file is the same as the two passes give, since a render repeats exactly (R14). (S3)
- **R25.** The tail is what the song sounds after the range's end with nothing new played: the render goes on past the end as if Stop were pressed there, every note ended and every clip stopped, automation holding its value at the end, while the devices run on. It lasts until the output has stayed below −120 dBFS for 100 ms, and at most 60 s (Beatlayer's own bounds). Without Render as Loop, nothing past the range is rendered (R3). (S3)
- **R26.** The tail is added at the file's rate, after any conversion down (R6), and before Normalize (R8), dither, and quantisation (R4, R7), so Normalize's peak is the looped file's. In a multi-track export each file adds its own track's tail (R19, R22), and an MP3 export adds its tail before encoding (R23). (S3)
- **R27.** A Render as Loop export repeats bit for bit at any block size (R14), and cancelling it or a failure leaves nothing behind (R10, R21). (S3)

- Create Analysis File: the option keeps Live's control and place in the dialog. Beatlayer writes its own analysis file beside the export (the waveform overview it already makes for imported audio, in Beatlayer's format) instead of Live's `.asd`. It is built with the dialog.
