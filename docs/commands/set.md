## Commands

### `set.backups`

**Beatlayer Set Backups**. Permission: `read`. Contexts: `global`.

The open set's backups, in the project folder's `Backup` folder, newest first, each with the time it was made in local time. The list is empty when the set has no backups.

Default keys: none.

Arguments: none (send `{}`).

Result: [`Backups`](README.md#backups).

### `set.cancel_pack`

**Cancel**. Permission: `edit`. Contexts: `global`.

Stops the pack or unpack under way, leaving no pack and no unpacked folder.

Default keys: none.

Arguments: none (send `{}`).

Result: [`PackStatus`](README.md#packstatus).

### `set.collect_all_and_save`

**Collect All and Save**. Permission: `external`. Contexts: `global`.

Copies the files the open set uses that live outside its project folder into the project's `Samples/Imported` folder, re-points the set's media table at the copies, and saves the set, as File ▸ Collect All and Save does in Live, so the set no longer depends on files elsewhere. `groups` chooses which places to collect from: "other-project", "user-library" and "elsewhere"; all of them when none are given. Fails if the set has never been saved; use `set.save_as` to give it a project folder first. The result's `files` is how many files were copied.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `groups` | array of [`ExternalGroup`](README.md#externalgroup) | no | The groups to collect from: "other-project", "user-library" or "elsewhere". All of them when none are given. |
| `project` | string or null | no | The project folder to collect for, when it isn't the open set's: every set in it is rewritten, each keeping the version it replaces in its project's `Backup` folder (R16). |

Result: [`FileReport`](README.md#filereport).

### `set.create_pack`

**Create Pack**. Permission: `external`. Contexts: `global`.

Packs a project folder (the open set's when `project` is left out) into one `.blpack` file at `path`, as the File Manager's Create Pack does: every file and folder in it, byte for byte, in a ZIP64 archive whose first entry is a manifest, without hidden files (sets' journals and saves under way) and without `Backup`. Files the project's sets use from outside its folder aren't in the pack; the result names them. Refused while the open set has unsaved changes or was never saved, when its project is the one packed. The pack is written to a hidden file and renamed into place, so a pack that stops or is cancelled (`set.cancel_pack`) leaves nothing. An agent's call waits for the end and returns the pack; a person's runs on a worker thread, and `set.pack_status` shows how far it has got. Changes nothing in the project. Writes a file outside it.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string or null | no | Where to write the pack, as a save dialog gives it, such as `/Music/Tango Project.blpack`. A person who leaves it out is asked; an agent must give it. |
| `project` | string or null | no | The project folder to pack. Left out, the open set's. |

Result: [`CreatedPack`](README.md#createdpack).

### `set.discard_changes`

**Don't Save**. Permission: `destructive`. Contexts: `global`.

Throws away the open set's unsaved changes, as choosing Don't Save when asked to save does: the set goes back to how it was when it was last opened or saved (a set never saved goes back to the factory default set), and its undo history is cleared. The changes can't be brought back. Nothing on disk changes. Does nothing if there are no unsaved changes.

Default keys: none.

Arguments: none (send `{}`).

Result: [`SetResult`](README.md#setresult).

### `set.discard_recovery`

**Discard Recovery**. Permission: `destructive`. Contexts: `global`.

Declines to recover a set that `set.list_recoverable` lists, the one with `id` or the newest: its unsaved edits are removed from beside the set, so it isn't offered again, and a copy of its journal is kept in the recovery folder's Discarded folder for seven days. Its set file is untouched.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `id` | string or null | no | The recoverable set's `id`, as `set.list_recoverable` gives it. Leave it out for the newest. |

Result: [`DiscardedRecovery`](README.md#discardedrecovery).

### `set.export_clips`

**Save Clips as Set**. Permission: `external`. Contexts: `session`, `browser`.

Saves several Session clips of the open set as a new set in `folder`, as dragging them onto a folder in the browser does: a track for each track they are on, in the open set's order, with its kind, name, colour, mixer and devices but none of its other clips or automation, and each clip in the scene as far below the first clip's scene as it was in the open set. The new set takes the open set's tempo and time signature. Named, placed, written and copied as `set.export_tracks` does, with " Clips" added to the open set's name. Changes nothing in the open set. Writes files outside the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `clips` | array of [`ClipId`](README.md#clipid) | yes | The Session clips to save. At least one. |
| `folder` | string | yes | The folder to save the set in. |
| `copy` | boolean or null | no | Answers Collect Files on Export when it is set to Ask, as `set.export_tracks`' does. |
| `name` | string or null | no | The set's name, without the extension. Left out, the open set's name with " Clips" added. |

Result: [`ExportedSet`](README.md#exportedset).

### `set.export_dawproject`

**Export DAWproject File**. Permission: `external`. Contexts: `global`.

Writes the open set to the file at `path` as DAWproject 1.0, adding `.dawproject` when it is missing. It is refused when a file is already there unless `replace` is true. The plug-ins' states are taken from the running plug-ins as a save takes them, and the file is written on a worker thread into a hidden file beside the destination and then renamed into place, so the destination holds the whole file or nothing new; the set does not change. The file holds the tracks, groups, returns and their mixer and routing, the clips with their notes, media, warping, fades and crossfades, the scenes and slots, the tempo and time signature, the automation, the devices and plug-ins with their saved states, Beatlayer's own devices and racks with their presets, and the locators. The audio files are embedded unless `embed_media` is false, when each is referred to by its absolute path. The result gives the file's path and a `report` of what the format cannot carry, which the file leaves out. Writes a file outside the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | The file to write, absolute or relative to the app's working directory; `.dawproject` is added when it is missing. |
| `embed_media` | boolean | no | Whether to put the audio files in the DAWproject file (the default) or refer to them by their absolute paths. |
| `replace` | boolean | no | Whether to write over a file already at `path`; without it, an existing file is refused. |

Result: [`ExportDawProjectResult`](README.md#exportdawprojectresult).

### `set.export_tracks`

**Save Tracks as Set**. Permission: `external`. Contexts: `arrangement`, `session`, `browser`, `track-headers`.

Saves tracks of the open set as a new set in `folder`, as dragging their title bars onto a folder in the browser does: whole, with their clips, devices, take lanes and automation, a group with the tracks inside it. The new set also holds the open set's return tracks with their devices, and its tempo, time signature and scenes. It is named `name`, the track's name when one track is saved, or the open set's, and is placed as Save Set As places a set: in the folder when it is a project folder, otherwise in a new "<name> Project" folder; written whole or not at all. The audio files are copied into its project folder's `Samples/Imported` or left where they are, as Collect Files on Export says (`settings.state`'s `library.collect_files_on_export`); under Ask, `copy` answers for the person and leaving it out refuses the command. The new row is selected with its name open for editing (`browser.state`'s `renaming`; `browser.rename_file` finishes it). Changes nothing in the open set. Writes files outside the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `folder` | string | yes | The folder to save the set in. |
| `copy` | boolean or null | no | Answers Collect Files on Export when it is set to Ask: `true` copies the audio files the tracks play into the new set's project folder, `false` leaves the new set naming them where they are. Under Always and Never it is ignored; under Ask, leaving it out refuses the command. |
| `name` | string or null | no | The set's name, without the extension. Left out, the track's name when one track is saved, and the open set's otherwise. |
| `tracks` | array or null | no | The tracks to save: one, a group with the tracks inside it, or several. Left out, the selected tracks. Main can't be saved. |

Result: [`ExportedSet`](README.md#exportedset).

### `set.import`

**Import Tracks from Set**. Permission: `external`. Contexts: `arrangement`, `session`, `browser`, `track-headers`.

Adds tracks from a set file to the open set, as dragging the set or its rows from the browser does. With neither `tracks` nor `devices`, every track of the file but its return tracks and Main; with `tracks`, those tracks (a group brings the tracks inside it); with `devices`, only that track's chain of devices, with every device's state and without automation, onto a track that takes it or a new track. An added track keeps its kind, name, colour, mixer, sends' levels, devices, Arrangement clips, Session clips, take lanes and automation, with new IDs; its Session clips go in the open set's scenes at the positions they had, and the open set gets empty scenes at its end when it has fewer. Its sends go to the open set's return tracks in the same position and are left out past the last; an input, output or sidechain naming a track that isn't added goes back to its default or to none; links are dropped. The audio files are registered from the file's project folder and found by content when they moved; none is copied. The open set's tempo, time signature, scenes and loop are unchanged. One undo step. Reads a file outside the project. Read the new tracks back with the query tool's `song` and `track` objects.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | The set file to take tracks from, or a track's chain of devices. |
| `at` | [`TrackId`](README.md#trackid) or null | no | For tracks, the track of the open set they go after, at its level (inside its group when it is in one); for a chain, the track it goes on, after the track's own devices. Left out, the first selected track (the last one for tracks), or, when none is selected, after the last track or on a new track. |
| `devices` | [`TrackId`](README.md#trackid) or null | no | Add only the chain of devices of this track of that set (its Devices row), with every device's state and without automation. |
| `drop_area` | boolean | no | Ignore the selection: tracks go after the last track, and a chain goes on a new track of its kind (a MIDI track for a chain with an instrument or a MIDI effect, an audio track otherwise), as dropping in a view's drop area does. Ignored when `at` is given. |
| `tracks` | array or null | no | The tracks to add, by their IDs in that set (the IDs `browser.state` gives in the rows of the opened set): one track, a group with every track inside it, or several, which come in that set's order. Left out (and `devices` too), every track but its return tracks and Main, as dropping the set file does. A return track or Main can't be added; add its chain of devices with `devices`. |

Result: [`Imported`](README.md#imported).

### `set.import_dawproject`

**Import DAWproject File**. Permission: `external`. Contexts: `global`.

Reads the DAWproject file at `path` and opens what it holds as a new set, in place of the open one, as opening a set does: it is refused while the open set has unsaved changes. The new set starts empty and holds what the file carries: its tracks, groups, returns and their mixer and routing, its clips with their notes, media, warping and loops, its scenes and slots, its tempo and time signature, its colours, fades and crossfades, its devices and plug-ins with their saved states, its automation, MIDI controllers and note expressions, and its markers as locators. It is unsaved, and its name is the file's name without `.dawproject` until it is first saved. The result's `report` says what the import left out or changed, and `set.import_report` gives that report again while the set the import made is open. Reads a file outside the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | The DAWproject file to read, absolute or relative to the app's working directory. |

Result: [`ImportDawProjectResult`](README.md#importdawprojectresult).

### `set.import_report`

**DAWproject Import Report**. Permission: `read`. Contexts: `global`.

Reports what the last DAWproject import left out or changed: each thing, where it was, how many there were, and what Beatlayer did, and the application and version the file says made it. It gives the report again while the set the import made is open, and nothing after another set opens. Changes nothing.

Default keys: none.

Arguments: none (send `{}`).

Result: [`ImportReport`](README.md#importreport).

### `set.install_pack`

**Install Pack...**. Permission: `external`. Contexts: `global`.

Unpacks a `.blpack` file into a new project folder inside `folder`, as File ▸ Install Pack... does: named as the pack's project folder, with " 2", " 3" and so on when `folder` already holds one of that name. The whole pack is checked before anything is written (a manifest from a later version, a name that is absolute, climbs out with `..`, is a link or can't be a file name, or more bytes than `folder` has free refuse it), then written to a hidden folder that is renamed into place once every file has the size and checksum the pack says, so a pack that is refused, fails or is cancelled (`set.cancel_pack`) leaves nothing. Opens no set and changes nothing in the open set. An agent's call waits for the end and returns the new folder and its sets; the browser lists the folder where it lies in a place. Reads a file and writes files outside the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `folder` | string or null | no | The folder to make the project folder in. A person who leaves it out is asked, the pack's own folder first; an agent must give it. |
| `pack` | string or null | no | The pack to unpack. A person who leaves it out is asked; an agent must give it. |

Result: [`InstalledPack`](README.md#installedpack).

Closes the recovery prompt the app shows at launch, leaving every set it listed to be offered again at the next launch: nothing is recovered and nothing is thrown away. The prompt's Later button runs it, and Esc does the same. Changes nothing in the set.

Default keys: none.

Arguments: none (send `{}`).

Result: [`RecoveryPrompt`](README.md#recoveryprompt).

### `set.list_recoverable`

**List Recoverable Sets**. Permission: `read`. Contexts: `global`.

Lists the sets that Beatlayer, here or in an earlier run, stopped without closing (a crash, a forced quit, a power cut) while they had unsaved edits. Each has an `id` for `set.recover` or `set.discard_recovery`, its file (null if it had never been saved), how many edits followed its last save, and when the last was made. Sets open in another running instance aren't listed. Changes nothing.

Default keys: none.

Arguments: none (send `{}`).

Result: [`RecoverableSets`](README.md#recoverablesets).

### `set.recover`

**Recover Set**. Permission: `destructive`. Contexts: `global`.

Opens a set that `set.list_recoverable` lists, the one with `id` or the newest, exactly as it was after its last journalled edit. It replaces the open set, whose undo history is cleared; if the open set had unsaved edits they're kept for recovery in turn. The recovered set is unsaved: use `set.save` to keep it in its file, or `set.save_as`. Use it when the user wants back the work a crash interrupted.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|

### `set.relink_missing`

**Relink Missing Files**. Permission: `external`. Contexts: `global`.

Searches for the files the open set uses that are missing or changed, and relinks each one to the file found with the same content, as Live's automatic search does. The search covers the set's project folder, the User Library, the folders the files were last in, and any `folders` given, each with its subfolders; `project` and `library` switch the first two off, and `folder` names the folder the Automatic Search's Search Folder chooses. A file with one candidate is relinked to it; a file with several keeps its row, and the candidates are in the result's `candidates`, so the person chooses. The result's `files` is how many files were relinked. It also runs by itself when a set is opened.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `folder` | string or null | no | The folder the Automatic Search's Search Folder names. |
| `folders` | array of string | no | Folders to search, each with its subfolders, absolute or relative to the app's working directory. May be empty. |
| `library` | boolean or null | no | Whether the User Library is searched. On unless asked otherwise. |
| `project` | boolean or null | no | Whether the set's project folder is searched. On unless asked otherwise. |

Result: [`FileReport`](README.md#filereport).

Read the result back with the query tool's `song` (`undo.next_undo`).

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | The row's `id`, as `set.save_history` gives it. |

Result: [`Restored`](README.md#restored).

### `set.save_as`

**Save Beatlayer Set As...**. Permission: `external`. Contexts: `global`.

Saves the set under a new name or in a new place, always inside a project folder, and that file becomes the set's. `path` gives a folder and the set's name, such as `/Music/Tango.blset` (`.blset` is added if it's missing). If the folder is a project folder, one that already holds a `.blset` set, the set joins that project as `<name>.blset` there; a set of that name there is replaced, and the replaced version kept in that project's `Backup` folder. Otherwise a new project folder, `<name> Project`, is made in the folder (or `<name> Project 2` and so on if that name is taken, so nothing is overwritten), and the set is saved inside it, as `/Music/Tango Project/Tango.blset`. The result's `path` is where the set was saved. Moving to another project folder keeps the set using the same media files. A person choosing the menu item or pressing the shortcut picks the path in a dialog that opens in the set's project folder.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-FILE-004 | `Cmd+Shift+S` | `Ctrl+Shift+S` | `global` | Save the set under a new name | runs it |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | A folder and the set's name, as a set file's path such as `/Music/Tango.blset`, absolute or relative to the app's working directory. The set goes in that folder if it's a project folder (it holds a set already), and otherwise in a new `<name> Project` folder inside it; the result says where. |

Result: [`SetResult`](README.md#setresult).

### `set.save_copy`

**Save a Copy...**. Permission: `external`. Contexts: `global`.

Saves a copy of the open set at `path`, as File ▸ Save a Copy... does: in the folder when it is a project folder, otherwise in a new "<name> Project" folder. The copy names the same media files. The open set keeps its file, its name, its undo history and whether it has unsaved changes.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | Where to save the copy, as a save dialog gives it: a folder and the set's name, such as `/Music/Tango.blset`. |

Result: [`SavedCopy`](README.md#savedcopy).

### `set.save_history`

**Save History**. Permission: `read`. Contexts: `global`.

Lists the open set's save history, newest first: the save points Save Continuously kept since the last save (none while it is off), then the set as last saved, then its backups. Each row has an `id` for `set.restore`, its kind (`save_point`, `saved` or `backup`), its time in UTC and its label, which is the edit's name for a save point. A set never saved has no rows. Changes nothing.

Default keys: none.

Arguments: none (send `{}`).

Result: [`SaveHistory`](README.md#savehistory).
