## Commands

### `device.add`

**Add Device**. Permission: `edit`. Contexts: `device-view`, `browser`.

Adds a device as a person does from the browser: to the selected track (or `track`), after the selected device or at the end of its role's place in the chain (or at `index`), switched on, with its type's default preset if one was saved, and selects it. The chain keeps Live's order: MIDI effects, the instrument, then audio effects. An instrument or MIDI effect added while an audio, group, or return track is selected goes on a new MIDI track at the end of the track list, which becomes the selected track, as one undo step (Insert Device and Track). With `chain` it goes into that rack chain instead. A chain holds one instrument; a rack holds more.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `device` | [`NewDevice`](README.md#newdevice) | yes | The device to add. |
| `chain` | [`ChainId`](README.md#chainid) or null | no | A rack's chain to add it to, at any depth, in place of the track's own chain (WP-5.1). |
| `index` | integer or null | no | Where it goes in the chain; after the selected device, or at the end of its role's place in the chain, if left out. |
| `track` | [`TrackId`](README.md#trackid) or null | no | The track; the selected track if left out. |

Result: [`DeviceAdded`](README.md#deviceadded).

### `device.add_layers`

**Add Samples**. Permission: `external`. Contexts: `device-view`.

Adds audio files to a multisampler as layers, as dropping them on the zone editor's layer list does: each file is imported into the set's media, and gets one layer after the selected layers (or at the end), or at `index`, or straight after the layer `after`, with every zone whole and unfaded (or copied from the layer `like`, so the new layers sound together with it), its Root Key from the file's sampler metadata (C3 where it has none), Sample Start and End at the file's ends, and its loop points from the file's first loop with Sustain Mode left off. The new layers become the selected ones. A file that isn't audio is skipped and named in `skipped`. One undo step. It reads files outside the set.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `paths` | array of string | yes | The audio files, one layer each. |
| `after` | [`LayerId`](README.md#layerid) or null | no | Puts the first straight after this layer, instead of at `index` or after the selected ones (R61). |
| `device` | [`DeviceId`](README.md#deviceid) or null | no | The multisampler; the selected device if left out. |
| `index` | integer or null | no | Where in the layer list the first goes; after the selected layers (or at the end with none selected) if left out. |
| `like` | [`LayerId`](README.md#layerid) or null | no | Gives each new layer this layer's key, velocity and sample select zones with their fades, so the two sound together (R61). |

Result: [`LayersAdded`](README.md#layersadded).

### `device.add_preset`

**Add Preset**. Permission: `external`. Contexts: `device-view`.

Adds the device or rack a preset file (.blpreset) holds, as choosing it in the browser (Enter, a double-click or a drag) does: where `device.add` puts a device of its role, on `track` (the shown track if left out) or in the rack chain `chain`, after the selected device if that keeps the chain's order. A device takes the preset's values and name; a rack comes whole, with new IDs for its chains and devices. One undo step, named Insert Device (Insert Device and Track when it goes on a new MIDI track). The new device is selected. A chain preset is refused: `chain.load_preset` loads it. Reads a file outside the project; the samples a rack preset carries are written to the User Library's Samples/Preset Samples folder if the set's media store lacks them.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | The preset file: a device's or a rack's. |
| `chain` | [`ChainId`](README.md#chainid) or null | no | The rack chain that takes it, instead of a track's own chain. |
| `index` | integer or null | no | Where it goes in the chain; after the selected device, or at the end of its role's place, if left out. |
| `track` | [`TrackId`](README.md#trackid) or null | no | The track, as `device.add` takes it; the shown track if left out. |

Result: [`DeviceAdded`](README.md#deviceadded).

### `device.add_sample_edit`

**Edit Sample**. Permission: `edit`. Contexts: `device-view`.

Adds one edit to the end of a sample's edit list without looking at the audio: `edit.kind` is `trim`, `cut`, `reverse`, `fade_in`, `fade_out` or `normalize`, and `edit.range` (`from` to `to`, in frames of the sample as the earlier edits left it) is its selection, left out for the whole sample (Trim and Cut need one). With a `layer` the edit joins that layer's list and its length and markers follow the audio; with none it joins the sample of the device itself, which this command doesn't check against the sample's length. The source file is never written. One undo step named for the edit. `device.edit_sample` checks the selection against the sample.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `device` | [`DeviceId`](README.md#deviceid) | yes | The device. |
| `edit` | [`SampleEdit`](README.md#sampleedit) | yes | The edit. |
| `layer` | [`LayerId`](README.md#layerid) or null | no | The layer, or `null` for the device's own sample. |

Result: [`ChangeSet`](README.md#changeset).

### `device.audition_sample`

**Audition Sample**. Permission: `read`. Contexts: `device-view`.

Plays a sampler's sample from a point through the device, as a click in its display does: `from` is the start as a share of the sample from 0 to 1, `layer` a multisampler's layer (its first selected layer if left out). The voice plays at the sample's root pitch (C3 for Simpler, the layer's root key for the multisampler) through the device's settings, and goes on until the same command comes with `down: false`, as the button's release. It needs the audio engine on; `sent` says whether it was. It changes nothing in the set.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `device` | [`DeviceId`](README.md#deviceid) or null | no | The sampler device; the selected device if left out. |
| `down` | boolean | no | Whether the button goes down (`true`, the default) or comes up. |
| `from` | number | no | Where in the sample to start, as a share of its length from 0 to 1. |
| `layer` | [`LayerId`](README.md#layerid) or null | no | A multisampler's layer; its first selected layer if left out. |

Result: [`Auditioned`](README.md#auditioned).

### `device.autosample`

**Autosample**. Permission: `external`. Contexts: `device-view`.

Samples an instrument across a range of notes and velocities into a new multisampler on a new MIDI track: the native instrument, the plug-in instrument, or the external instrument, rendered alone with its current settings. The notes are the lowest one and every `step` above it up to the highest, which is always sampled; each is played at `velocity_layers` velocities, held for `note_length` seconds and followed by `release_tail` seconds of render, and sampled `round_robins` times for the round robins. The samples are 32-bit floating-point WAVs in the project's `Samples/Processed/Autosample` folder, named for the instrument, the note and the velocity, and they join the set's media. With `detect_loops` on, each sample gets a sustain loop so a sustained sound holds past the note. The result is a new MIDI track straight after the source's, holding a multisampler with one layer per sample, its zones spread between the sampled notes, Round Robin on in Forward mode where there are round robins, and the volume envelope's release as long as the release tail. One undo step; undoing it leaves the files on disk. It writes files, and plays hardware for the external instrument.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `detect_loops` | boolean or null | no | Whether a loop is found in each sample. Off by default. |
| `device` | [`DeviceId`](README.md#deviceid) or null | no | The instrument to sample: a native instrument, a plug-in instrument, or the external instrument. The one selected in the Device View when it is left out. |
| `highest` | integer or null | no | The highest note sampled, from 0 to 127 (C-2 to G8). C6 by default. |
| `lowest` | integer or null | no | The lowest note sampled, from 0 to 127 (C-2 to G8). C1 by default. |
| `name` | string or null | no | The name of the instrument the samples are named for, and of the new track. The instrument's own name by default. |
| `note_length` | number or null | no | How long each note is held, in seconds, from 0.1 to 30. 2 by default. |
| `release_tail` | number or null | no | How long the render goes on after the note is released, in seconds, from 0 to 30. 1 by default. |
| `round_robins` | integer or null | no | How many times each note is sampled, from 1 to 8, for the round robins. 1 by default. |
| `step` | integer or null | no | How many semitones between the sampled notes, from 1 to 12. 3 by default. |
| `velocity_layers` | integer or null | no | How many velocity layers each note is sampled at, from 1 to 16. 1 by default. |
| `wait` | boolean or null | no | Whether to wait for the samples to be made before returning. True by default; with it off the command starts the samples and returns at once, and the progress is read from the dialog. |

Result: [`Autosampled`](README.md#autosampled).

### `device.autosample_cancel`

**Stop Autosampling**. Permission: `edit`. Contexts: `device-view`.

Stops a running autosample: the files it wrote are deleted and the set is left as it was. It does nothing when no autosample is running.

Default keys: none.

Arguments: none (send `{}`).

Result: [`AutosampleCancelled`](README.md#autosamplecancelled).

### `device.clear_sample_edits`

**Revert Edits**. Permission: `edit`. Contexts: `device-view`.

Empties a sample's edit list, a layer's (`layer`) or the device's own (none given). A layer's sample is `length` frames long again, the unedited sample's length at its own rate, and its markers keep their share of it. One undo step. `device.edit_sample` with `revert` reads the length itself.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `device` | [`DeviceId`](README.md#deviceid) | yes | The device. |
| `length` | integer, at least 0 | yes | The unedited sample's length in frames at its own rate. |
| `layer` | [`LayerId`](README.md#layerid) or null | no | The layer, or `null` for the device's own sample. |

Result: [`ChangeSet`](README.md#changeset).

### `device.compare_copy`

**Compare: Copy**. Permission: `edit`. Contexts: `device-view`.

Copies every value of a native device's active state, A or B, over the other, as the Edit menu's and the device menu's Compare: Copy A to B (Copy B to A while B is active) do. What the device plays doesn't change, and no envelope is overridden. One undo step, named as the item that ran it. Racks and plug-ins have no states, so a command for one is refused. From the menus it copies the selected device's state.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `device` | [`DeviceId`](README.md#deviceid) | yes | The device. |

Result: [`ChangeSet`](README.md#changeset).

### `device.compare_switch`

**Compare: Switch**. Permission: `edit`. Contexts: `device-view`.

Makes the other of a native device's two states, A and B, the active one, as the Edit menu's and the device menu's Compare: Switch to B/A and the P key do. Every parameter whose value differs between the states moves to the newly active state's value, a continuous one gliding as any change does, and every parameter of the device that has an envelope is overridden until Re-Enable Automation. One undo step, named as the item that ran it. A change to a parameter goes to the active state only. Racks and plug-ins have no states, so a command for one is refused. `device.parameters` says which state is active and each parameter's value in the other; the query tool's `device` has both in `compare`. From the keyboard and the menus it switches the selected device.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-DEV-011 | `P` | `P` | `device-view` | Switch the device between its A and B states | runs it |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `device` | [`DeviceId`](README.md#deviceid) | yes | The device. |

Result: [`ChangeSet`](README.md#changeset).

### `device.convert`

**Convert Sampler**. Permission: `edit`. Contexts: `device-view`.

Converts Simpler to a multisampler (`to: multisampler`) or a multisampler to Simpler (`to: snapshot`), keeping the device's place in its chain, its name, its on or off state and its sample, as one undo step. Simpler becomes one layer with every zone whole, its region as Sample Start and Sample End, its loop as a sustain loop and its edits, with its envelope, volume and pan as the multisampler's; a multisampler becomes Simpler in Classic mode playing its first layer. Slicing and One-Shot, and layers past the first, don't carry over, and the result's `dropped` names what didn't. The new device has a new ID, which the result gives.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `to` | [`ConvertTo`](README.md#convertto) | yes | What to convert it to. |
| `device` | [`DeviceId`](README.md#deviceid) or null | no | The sampler device; the selected device if left out. |

Result: [`Converted`](README.md#converted).

### `device.crop_sample`

**Crop Sample**. Permission: `edit`. Contexts: `device-view`.

Removes the sample outside Simpler's region, or outside a multisampler layer's Sample Start and Sample End, by writing a processed copy: a WAV with the sample's edits applied, at its rate and channels, in the project's `Samples/Processed/Crop/` folder. The device or layer then plays the copy, with its edit list empty and the region the whole of it, as one undo step; the original file stays as it was. A set that has never been saved has no project folder, and the command is refused with a message in the Status Bar. The copy is the sample's new media, which reads back in the device's `media` or the layer's `media`.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `device` | [`DeviceId`](README.md#deviceid) or null | no | The sampler device; the selected device if left out. |
| `layer` | [`LayerId`](README.md#layerid) or null | no | A multisampler's layer; its first selected layer if left out. |

Result: [`SampleProcessed`](README.md#sampleprocessed).

### `device.cut`

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-EDIT-001 | `Cmd+X` | `Ctrl+X` | `global` | Cut | runs it |

Arguments:

### `device.set_external`

**Set External Device**. Permission: `edit`. Contexts: `device-view`.

Sets the routing of a device that works with hardware outside the computer (the External Instrument and the External Audio Effect), as the choosers in its title bar do; give only the settings to change. `midi_to` is `{ "type": "none" }` (No Output, a new device's) or `{ "type": "port", "name": ... }` with a MIDI output port's name as `midi.ports` lists it, with its Track switch on; `channel` is the MIDI channel to send on, 1 to 16 (1 on a new device), which takes MPE's place; `mpe` sends MPE MIDI in place of one channel, with the MPE/Multi-channel Settings it gives (`{}` for the new ones: the lower zone with 15 note channels), the notes on the zone's member channels and the rest on its master; `audio_from` is the audio interface's inputs the hardware's sound comes back on, a channel or a pair (`{ "type": "pair", "channel": 1 }`, the first pair on a new device); `audio_to` is the audio interface's outputs an External Audio Effect sends its signal to, a channel or a pair (the first pair on a new device); `hardware_latency` is the delay the hardware adds that the computer can't detect, in the unit the unit switch is on: `{ "unit": "milliseconds", "value": 12.5 }` (0 to 1000, kept in milliseconds when the sample rate changes) or `{ "unit": "samples", "value": 600 }` (0 to 192000, kept in samples); to switch the unit, send the converted value. Each change recompiles the song's audio, so these are settings, not parameters. Read them back in the query tool's `device` result, under `external`. A CV device (CV Instrument, CV Triggers) has no MIDI To or Audio To: `cv_outputs` and `cv_inputs` set its CV outputs and inputs, each given as `{ "name": ..., "channel": ... }` with the port's name in the device (Pitch, Gate, Mod 1, Mod 2 on CV Instrument) and the audio interface's channel, counted from 1, or no `channel` for No Output (No Input), the state of a new device; the ports not given stay. A CV output writes its voltage on its channel at full value (1.0 is +10 V), added to whatever else plays there. Read them in the query tool's `device` result, under `external`.

Default keys: none.

| Name | Type | Required | Description |
|---|---|---|---|
| `device` | [`DeviceId`](README.md#deviceid) | yes | The device. |
| `audio_from` | [`Channel`](README.md#channel) or null | no | Audio From: the audio interface's inputs it comes back on. |
| `audio_to` | [`Channel`](README.md#channel) or null | no | Audio To: the audio interface's outputs an external effect sends its signal to. |
| `channel` | integer or null | no | The MIDI channel, 1 to 16. |
| `cv_inputs` | array or null | no | A CV device's inputs, as `cv_outputs`; `null` is No Input. |
| `cv_outputs` | array or null | no | A CV device's outputs (`docs/specs/cv-tools.md`, R4): each named by its name in the device (Pitch, Gate, Mod 1 and so on) and set to an interface channel, counted from 1, or to `null` for No Output. The outputs left out stay as they are. |
| `hardware_latency` | [`HardwareLatency`](README.md#hardwarelatency) or null | no | Hardware Latency with its unit: the unit switch is the unit given, so switching the unit sends the converted value. |
| `midi_to` | [`ExternalPort`](README.md#externalport) or null | no | MIDI To: `none` for No Output, or `port` with the MIDI output port's name. |
| `mpe` | [`MpeSettings`](README.md#mpesettings) or null | no | MPE, chosen in place of a channel, with the MPE/Multi-channel Settings the notes go out on (the MPE spec, R19). Giving a `channel` instead sends on that channel again. |

Result: [`ChangeSet`](README.md#changeset).
