## The behaviour

A convolution effect plays a recorded or generated impulse response: the way a room, a plate, a spring or a loudspeaker answers a single click, imposed on every sample of the input. A device that convolves has an impulse-response slot. The person fills it by choosing a response from the device's chooser, by dropping an audio file on the device's display, or by dragging one from the browser; an agent fills it with `device.load_sample`. The file is imported as any sample is, by its content, decoded and resampled to the engine's rate, its silent tail trimmed and its level normalised so that changing responses keeps the loudness, and prepared for the convolution engine away from the audio thread. The set keeps the file by content hash, as it keeps samples, so Manage Files finds it when it goes missing and Collect All and Save copies it.

The chooser lists Beatlayer's bundled responses in categories, after Live's, and a User category with the person's own. The bundled responses are Beatlayer's own: a script in the repository generates every one from a written design (a room's dimensions and absorption, a plate's size and damping, a spring's dispersion), and the packaged app carries the script's output read-only.

This spec covers the slot, loading, the chooser and the bundled responses. What a device does with its response (Attack, Decay and Size, its mix) is the device's own spec.

## Rules

### The slot (WP-8.30)

- **R1.** A device type may declare impulse-response slots in its description, each with a name. Every device of that type has them, and no other device does. A new device's slot holds the response its spec names, or nothing; a slot holding nothing gives silence where its response would play, and the device's dry path is unaffected. (S1, S4; Beatlayer's own)
- **R2.** A slot is filled by `device.load_sample` with the device, the file's path and `slot` (the slot's name, which may be left out on a device with one slot); by dropping an audio file on the device's display cell; and by dragging a file from the browser onto that cell. Each is one undo step named `Load Impulse Response`. `device.set_sample` with no file clears a slot, one undo step named `Clear Impulse Response`. Loading a response is a media change, not a parameter: it isn't automatable and has no automation lane. (S1, S3, S4; the step names are Beatlayer's own)
- **R3.** A slot takes any file audio import reads ([audio import](audio-import.md)) with one, two or four channels: one channel is a mono response, heard on both outputs; two are a stereo response, left input to left output and right to right; four are a true-stereo response, its channels in the order left input to left output, left input to right output, right input to left output, right input to right output (LL, LR, RL, RR). Any other channel count is refused with its reason and leaves the slot as it was. A file longer than 30 seconds at its own rate is refused with its reason. (S1; the layouts' order and the 30 seconds are Beatlayer's own)
- **R4.** The file is decoded, resampled and prepared on a loader thread, never on the main thread or the audio thread. The slot names the new response at once, in the device's state and in the chooser; the previous response (or silence) goes on playing until the new one is prepared, and the convolution engine then crossfades to it ([the architecture](../02-architecture.md), `bl_dsp::convolution`). `device.load_sample` returns when the response is prepared, with its readings (R12), so an agent reads back what plays. (S7; Beatlayer's own)
- **R5.** A response is resampled to the engine's rate with the media resampler before it is prepared, and prepared again from the decoded file when the engine's rate changes. (S5, S7)
- **R6.** Trimming: the frames after the last frame at which any channel reaches −90 dB relative to the response's peak, across its channels, are dropped. The frames before the first sound are kept, so a response's own predelay stays. (Beatlayer's own)
- **R7.** Normalising: the trimmed response is scaled so that its energy per output channel is 1: for a mono response the sum of its squared samples is 1; for a stereo response the sum over both channels is 2; for a true-stereo response the sum over its four channels is 2. A unit impulse at frame 0 is unchanged, and changing from one response to another leaves a steady noise's output level within 1 dB. The device's own level controls act after this. (Beatlayer's own)
- **R8.** A slot's response is kept with the set as samples are ([file management](file-management.md)): its file's path and content hash, with the slot's name; its decoded audio isn't stored in the set. Collect All and Save copies it into the project's folder with the set's samples, and a `.blpack` carries it. A set saved and opened again plays the same response. (S5)
- **R9.** Opening a set whose response's file is missing keeps the slot's name and plays silence for that response; Manage Files lists the file among the missing ones, and relinking, by hand or by search, finds it by its content hash. Relinked, the device plays it from the next prepared block, with no undo step. (S5)

### The chooser and the User category (WP-8.30)

- **R10.** `device.impulse_responses` (`read`) lists, for a device with a slot, the chooser's categories in order, each with its responses by name and file, and says which one each slot holds. The categories are the bundled ones (R17), each listing the responses in the app's bundled impulse-response folder for that category, then User. A device's spec may give it its own list instead, as Cabinet's fixed choices do ([Cabinet](cabinet.md)). (S1, S2; Beatlayer's own)
- **R11.** The User category lists the audio files in the User Library's `Impulse Responses` folder and its subfolders, by name, then every response loaded in the open set from anywhere else, by file name, without repeats. It is the same for every device with a slot. A file dropped on a device or dragged from the browser shows under User from then on, while the set is open; nothing is copied into the User Library. (S1, S5; the folder's name and what the category lists are Beatlayer's own)
- **R12.** The query tool's `device` result reports each slot under `impulse_responses`: its name, the response's file name, path and content hash, its category and name in the chooser (User for a file from elsewhere), its channel layout (mono, stereo or true stereo), its length in frames at the file's rate and after trimming at the engine's rate, the gain normalising applied in dB, and its state (`empty`, `preparing`, `ready` or `missing`). `device.load_sample` and `device.set_sample` are read back there. (S4)
- **R13.** Choosing a response from a device's chooser, or with its arrows, runs `device.load_sample` with that file; the arrows step through the responses of the chosen category and on into the next category at either end. The choosers show the loaded response's category and name; a slot holding a file from elsewhere shows User and the file's name. Each change is one undo step (R2). (S1)
- **R14.** A drop on a display cell takes the first file of the drop; a file the slot refuses (R3) leaves it as it was and the Status Bar says why. A drop of a non-audio file is refused the same way. (S1; Beatlayer's own)
- **R15.** Every rule above holds headless: the `testing` category's convolution test device, with one slot, loads a mono, a stereo and a true-stereo file by `device.load_sample`, plays them after a save and reopen, lists the chooser by `device.impulse_responses` and reads every slot back by R12, before any reverb exists. (S7; Beatlayer's own)

### Beatlayer's bundled responses (WP-8.31)

- **R16.** Beatlayer's bundled responses are its own: `cargo xtask impulses` generates every one from a design table in the repository; the packaged app carries them read-only in its bundled impulse-response folder, one subfolder per category, where R10's chooser finds them; and a test checks that the files shipped are the script's output. None is a recording, and none comes from any other library. The generated files aren't kept in the repository: the script makes them when the app is packaged and when tests run. (S6; Beatlayer's own)
- **R17.** The bundled categories, in the chooser's order, are Early Reflections, Chambers and Large Rooms, Made for Drums, Halls, Plates, Springs, Bigger Spaces and Textures, each with Beatlayer's own names for its responses, followed by User (R11). (S1; leaving out Real Places, a category of recorded spaces, and the names are Beatlayer's own)
- **R18.** Rooms, chambers, halls, bigger spaces and the drum rooms are each a rectangular room given by its dimensions, its source and two listener positions (left and right, for a stereo response) and its walls' absorption in the octave bands from 125 Hz to 8 kHz. Each response is the room's early reflections by the image-source method up to its mixing time, each reflection delayed by its path length at 343 m/s and attenuated by distance and by each wall it meets in each band, followed by a late tail of noise filtered into the octave bands, each band decaying at the reverberation time Eyring's formula gives for that band, crossfaded in over 10 ms at the mixing time. An Early Reflections response is the image-source part alone, to 80 ms. (S8; Beatlayer's own)
- **R19.** A plate is a thin rectangular plate's modes (Kirchhoff's mode frequencies for its size, thickness and material, up to 20 kHz), each decaying at a frequency-dependent rate set by its damping, read at two pickup positions. A spring is one to three springs, each a chain of first-order allpass filters giving its dispersive chirp, repeating at its transit time with its own decay. A texture is a response the design table builds from filtered noise, chirps and their sums, each documented there. (S10, S11; Beatlayer's own)
- **R20.** Every response is a stereo 32-bit float WAV at 48 kHz (the import path resamples it, R5), or a true-stereo one where its design says so, at most 10 seconds long, and every random part comes from a generator seeded per response, so running the script twice gives the same bytes. The bundled responses together, Cabinet's included ([Cabinet](cabinet.md)), take less than 60 MB. (Beatlayer's own)
- **R21.** Each room, plate and spring response's reverberation time in every octave band from 125 Hz to 8 kHz, measured by Schroeder's backward integration over a 30 dB range (RT30), is within 10 % of its design, and each of a room's first eight reflections arrives within one frame of its image-source time. (S8, S9; Beatlayer's own)
- **R22.** The packaged app fails to build, and its test fails, when a bundled response is missing or differs from the script's output; the chooser lists every bundled category with its responses. (S6)
