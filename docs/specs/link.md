# Link: tempo, phase, and start and stop shared with other apps on the network

## The behaviour

Link joins apps on the same network into a session that shares a tempo and a beat. Switched on, Beatlayer joins the session on its network, or starts one. Anyone in the session can change the tempo and everyone follows, the last change winning; a tempo change from a peer overrides the set's tempo automation. Each app starts and stops on its own, but always in phase: a start waits for the next boundary of its quantum, which in Beatlayer is the global launch quantisation, so bars line up across apps. With Start Stop Sync on, starts and stops are shared too, with the peers that have it on.

In the engine, Link's timeline is read and written on the audio thread once per block, through the library's real-time interface, and the song plays at the session's tempo and keeps its beat in phase with the session's. In the app, the Link toggle in the Control Bar shows the number of peers and has a menu beside it; Settings ▸ Link holds Show Link Toggle and Start Stop Sync; and while the transport is stopped with peers in the session, the Arrangement Position fields show how far the session is through the quantum, which is when a start will happen.

Beatlayer builds the open-source Link library, version 4.1.1, from source, and talks to it through its C interface.

## Rules

### The session (WP-7.14)

- **R1.** Link is off on a new install. `link.set_enabled` switches it on and off, and whether it's on is kept in the preferences, not in a set. On, Beatlayer joins the Link session on its networks, or starts one alone. (S1, S3; keeping it in the preferences is Beatlayer's own)
- **R2.** Switching Link on with no session to join changes neither the tempo nor the song position: playback goes on with no jump. Switching it on where a session exists takes the session's tempo and phase, which may jump the song's beat once. A peer joining Beatlayer's session makes no jump in Beatlayer. Opening or making a set while in a session with peers keeps the session's tempo. Switching Link off plays on at the tempo it had, with no jump. (S3, S6)
- **R3.** The tempo is shared both ways. A change Beatlayer makes (the Tempo field, `song.set_tempo`, a tap, an agent) goes to the session at the moment it's made. A change from a peer is played from the first block after it reaches Beatlayer ([transport](transport.md) R24), and becomes the set's tempo: the Tempo field shows it, and the set saves it, with no undo step of its own. When changes cross, the last one made wins. The session's range is the Tempo field's, 20 to 999 BPM. (S3, S6, S8; making it the set's tempo without an undo step is Beatlayer's own)
- **R4.** While Link is on, the set's tempo envelope plays as it would alone, and each change it makes goes to the session as Beatlayer's own. A tempo change from a peer overrides the envelope as a hand move does ([automation](automation.md) R5): the envelope stops playing and Re-Enable Automation lights ([automation](automation.md) R8) until it's re-enabled. (S3; the envelope sending its changes is Beatlayer's own)
- **R5.** The quantum is the global launch quantisation's length in quarter notes at the time signature where the song is ([launch quantisation](launch-quantisation.md) R13): 1 Bar in 4/4 is 4, 2 Bars 8, 1/4 is 1, 1/8T one third. With quantisation None, or switched off, the quantum is one quarter note. One beat of the session is one quarter note. (S1, S3; None's quantum and the beat as a quarter note are Beatlayer's own)
- **R6.** While Link is on and the song plays, the song's beat keeps the session's phase within the quantum at the moment each block is heard: the moment Beatlayer gives Link is the block's start on Link's clock plus the audio interface's output latency. Beatlayer follows the session's beat, not only its tempo: it closes small differences by playing each block up to 2 % faster or slower than the session's tempo, and jumps only when the difference is more than a sixteenth note. Played this way, Beatlayer's audio is heard within 3 ms of the session's beat. (S1, S6; the numbers but 3 ms are Beatlayer's own)
- **R7.** With at least one other peer, anything that starts the transport (Play, Continue Playback, a start from 1.1.1, a Session launch while stopped) waits for the next moment at which the session's phase within the quantum equals the start position's, and starts there, on that frame; Beatlayer starts at the start position, so its bars line up with the session's. Alone in a session, it starts at once. While it waits, `transport.state` reports `waiting_for_link` and when it will start; Stop while it waits cancels the start. (S1, S3, S6; Stop cancelling is Beatlayer's own)
- **R8.** Start Stop Sync is off on a new install, kept in the preferences, and set by `link.set_start_stop_sync`. With it on, Beatlayer's starts and stops go to the session at the moment R7 gives them, and the session's reach Beatlayer: a peer's start starts Beatlayer from its insert marker by R7's rule, and a peer's stop stops it at the stop's moment. Switching Start Stop Sync on while the session plays doesn't start Beatlayer. Only peers with it on share starts and stops. (S2, S6)
- **R9.** With Start Playback with Tap Tempo on, a start by tapping starts in phase with the session as R7 does. (S5)
- **R10.** With EXT on and an incoming clock leading ([MIDI clock](midi-clock.md) R17), Beatlayer gives the session the clock's tempo as its own changes; the session's phase still decides when a start of Beatlayer's own happens (R7), and the clock's Start and Continue start Beatlayer where the clock says. (S1; the phase staying the session's is Beatlayer's own)
- **R11.** While Link is on, the recording count-in doesn't play ([metronome](metronome.md) R10). (S3)
- **R12.** Link's timeline is read and written on the audio thread once per block, through the library's real-time pair of calls and session states made before the stream starts; a block writes only when Beatlayer changed something in it (a tempo change, a start or stop, a start's phase request). Nothing on the audio thread allocates, takes a lock or blocks. Link's own notifications (the peer count, the tempo, start and stop) arrive on Link's threads and only post a message for the main thread. (S6, S8)
- **R13.** The moment of each block on Link's clock comes from Link's own clock, read at the start of each block and smoothed by the engine's block clock ([MIDI I/O](midi-io.md) R16), so jitter in when the audio callback runs doesn't move the beat. (S6)
- **R14.** An offline render doesn't join or follow Link: it plays the set's own tempo map. (Beatlayer's own)
- **R15.** `link.state` (`read`) reports whether Link is on, the number of other peers, the session's tempo, the quantum, the session's phase within it, whether the session plays, Start Stop Sync, and whether a start waits and until when. `link.set_enabled` is `external`, since it talks on the network, and `link.set_start_stop_sync` `edit`, as a kept preference; each names its readback. (S8)
- **R16.** Beatlayer's engine reaches the session through an interface of `bl-link`'s that a test can stand in for, giving tempo, phase and start and stop at chosen frames; two real Link instances in one test process find each other over the loopback network. (Beatlayer's own)

### The app (WP-7.15)

- **R17.** The Link toggle (L-CTRL-002) sits in the Control Bar's tempo group before the tempo controls and shows on a new install. Settings ▸ Link's Show Link Toggle (a chooser of Show and Hide, Show at first, kept in the preferences, `link.set_show_toggle`) hides it and its menu; hiding it leaves Link as it is. A click on it runs `link.set_enabled`, and it's lit while Link is on. (S2, S3, S7)
- **R18.** While Link is off the toggle reads Link. While it's on, it reads the number of other peers in the session before the word: 0 Links, 1 Link, 2 Links. (S3, S6)
- **R19.** A menu arrow beside the toggle opens a menu of Link (ticked while on), Start Stop Sync (ticked while on), Link Audio (ticked while on, [Link Audio](link-audio.md) R1), the names of the connected peers that have Link Audio on (not clickable), and Configure Link…, which opens Settings on the Link page; each item runs its command. (S2; the order is Beatlayer's own)
- **R20.** The Link page of Settings (L-SET-013), after Audio and before Tempo & MIDI (L-SET-002), starts with a Link section: Show Link Toggle and Start Stop Sync (a switch). Link Audio's section follows it ([Link Audio](link-audio.md) R2 to R7). While no audio device runs, the page shows only a message that Link needs the audio engine running, and Link stays as it is set. (S2, S4, S7; the message's wording is Beatlayer's own)
- **R21.** Playback ▸ Options ▸ Link Start Stop Sync (M-PLAY-006d) is ticked while Start Stop Sync is on and runs `link.set_start_stop_sync`. (S7)
- **R22.** With at least one other peer, while the transport is stopped or waits to start (R7), the Arrangement Position fields (L-CTRL-013) show a progress bar across their width that fills from left to right with the session's phase within the quantum, empty at each boundary; after Play, the transport starts when the bar reaches the start position's phase. The fields keep showing the position over it. While the song plays, or with no other peer, there's no bar. (S3)
- **R23.** In the accessibility tree the Link toggle is a switch named Link, its value the peer count it shows; its menu arrow a button named Link Options; the progress bar a progress indicator named Link Quantum on the Arrangement Position fields, its value the share of the quantum gone by. (Beatlayer's own names but Link)
- **R24.** Every control runs a registered command, so an agent reaches each through the agent API with the person's effect: `link.set_enabled`, `link.set_start_stop_sync`, `link.set_show_toggle` (`edit`, a kept preference) and the Link Audio commands; `link.state` reads back each. (S8)
- **R25.** The toggle, its menu and the progress bar redraw from what the engine and Link last published, without waiting on either. (S8)
