# The track header's context menu

- **Status:** partial (R1 to R9 and R12 to R16 are implemented; R10 is WP-6.22's and R11 WP-6.23's)
- **Work packages:** WP-4.22 (R1 to R9); WP-6.22 (the take-lane items, R10); WP-6.23 (Link Tracks and Unlink Track(s), R11); WP-6.52 (Cut, Copy, Paste and Duplicate on whole tracks: R3 as changed, R12 to R16); Deactivate All Devices is WP-5.29 (IMP-25, R7)
- **Parity-matrix row:** Menu bar and context menus: structure, order, and wording of generic commands
- **Checked against:** Live 12.4.3 on macOS, observed on 10 October 2026 (the menu as opened on a MIDI track's title bar), and the Live 12 reference manual, chapters 6, 8, 18, 20, 21, and 22

## The behaviour

Right-clicking a track's title bar opens a menu of what can be done to the track: the clipboard items, Duplicate and Delete, Rename and Edit Info Text, Freeze and Bounce, the three Insert items, Group Tracks, then Select Track Content, Save as Default MIDI Track, the colour palette, and Assign Track Color to Clips. The title bars are the Arrangement's track headers and the title bars over the Session View and over both mixers. The menu acts on the selected title bars, so with several tracks selected an item acts on all of them as its command does.

Items whose commands exist today run them. The rest are drawn in Live's place and disabled, each saying which package makes it work. The menu differs a little when the track is a group, when several tracks are selected, when it opens in the Arrangement, and when the Arrangement has a time selection on the track.

This spec covers the track title bar's menu, Delete and Rename on the selected title bars, Cut, Copy, Paste and Duplicate on whole tracks (R12 to R16), and how the menu opens from the keyboard. The other commands it runs are specified where they live: [tracks and undo](tracks-and-undo.md), [routing](routing.md) for Duplicate Track Without Clips, [comping](comping.md) for the take-lane items and [linked-track editing](linked-track-editing.md) for linking.

## Rules

- **R1.** A right-click on a track's title bar opens the track header's menu, in the Arrangement's headers (the pinned returns and Main too), over the Session View, and over the Arrangement's mixer. Its rows are C-TRACK-001 to C-TRACK-016 of menus.md in Live's order with Live's separators and labels, except that Duplicate Track Without Clips (IMP-12) sits straight after Duplicate. (S1)
- **R2.** The right-click first selects the title bar unless it's selected already; with several selected title bars, the one clicked keeps the selection, so the menu acts on all of them. (S1)
- **R3.** Cut, Copy and Duplicate act on the selected tracks, as their keys do with title bars selected (R12 to R14), and are enabled when a selected track can be copied. Duplicate Track Without Clips runs `track.duplicate_without_clips`. Insert Audio Track, Insert MIDI Track and Insert Return Track run `track.create` as their keys do. Group Tracks runs `track.group`. Each item shows the key Live shows. (S1, S3)
- **R4.** Delete runs `track.delete` on every selected track except Main, as one undo step named Delete Track(s); a track deleted with its group isn't deleted twice. With no track selectable, or only Main selected, Delete is disabled. The Delete key does the same on selected title bars. (S1, S3)
- **R5.** Rename types the name in the first selected track's title bar, which starts from the track's name; Return runs `track.rename` with it, Esc leaves the name as it was, and while it's typed the keys go to it and not to shortcuts; with no title bar drawn to type in (the track scrolled out of view or inside a folded group), Rename does nothing. Main can't be renamed, and Rename is disabled when only Main is selected. (S1, S3)
- **R6.** The items whose commands aren't built are drawn disabled in their places, and each names its package in its AccessKit description and its hover text, as "Not built yet: arrives with …": Edit Info Text (WP-2.24, the Info View, which leaves the user's own info text to the edit commands), Freeze Track (WP-4.14), Bounce Track in Place (WP-4.15), Select Track Content and Save as Default MIDI Track (no package plans them yet), and the colour palette (drawn as 5 rows of 14 dimmed swatches, one control for a screen reader) and Assign Track Color to Clips (they wait for tracks to have colours, WP-6.30b). (S1)
- **R7.** The menu gains rows for the other states, drawn beside the items they go with because menus.md doesn't record where Live puts them: for a group track, Ungroup Tracks (`track.ungroup`, enabled), Bounce Group to New Track (WP-4.15) and Assign Track Color to Grouped Tracks and Clips (disabled, WP-6.30b); with several tracks selected, Link Tracks and Unlink Track(s) (R11); in the Arrangement's headers, Show Take Lanes, Insert Take Lane, Delete All Take Lanes and Delete All Unused Take Lanes (R10); in the Arrangement with a time selection on the track, Crop Clip (disabled, WP-4.13). Deactivate All Devices (IMP-25, the device chains spec R39) sits in the group with Freeze Track and Flatten, just before Freeze Track, and reads Activate All Devices while every top-level device on the selection is already off. (S2)
- **R8.** The menu's items run in the track-headers context whichever view it opened in, so Delete, Rename and the keys shown work from the Session View and the mixers as from the Arrangement's headers. (S3)
- **R9.** S-CTX-002 opens the menu for the selected title bar: in the Arrangement, with the view or the title bar focused and the title bars selected; over the Session View and the mixers, with the track's column focused. The menu's first item that can be chosen is focused, Up and Down move through the items that can be chosen, and Enter runs one. Every item reaches AccessKit with its label, its keys and its enabled state. (S3; accessibility R8)
- **R10.** In the Arrangement's headers the take-lane items work, on the selected audio and MIDI tracks: Show Take Lanes runs `arrangement.show_take_lanes` and is ticked while the clicked track's take lanes show; Insert Take Lane runs `take_lane.insert` and shows Shift+Option+T; Delete All Take Lanes runs `take_lane.delete_all` and Delete All Unused Take Lanes, the row after it, `take_lane.delete_unused` ([comping](comping.md) R4, R7, R24). Each is enabled when a selected track can take it: Show Take Lanes and Insert Take Lane with an audio or MIDI track selected, the two deletes when one has a take lane. (S2, S4)
- **R11.** Link Tracks and Unlink Track(s) work: with two or more audio or MIDI tracks selected, Link Tracks runs `track.link`, and with Cmd (Ctrl) held while it's chosen, in a linked track's menu, adds the selection to that track's link group; Unlink Track(s), enabled when a selected track is linked, runs `track.unlink`. On a group track's header both are offered whatever else is selected and act on the audio and MIDI tracks inside the group ([linked-track editing](linked-track-editing.md) R2 to R5). (S2)

**Whole tracks (WP-6.52)**

- **R12.** With track title bars selected, Duplicate (Cmd+D, S-EDIT-004; C-TRACK-003; Edit ▸ Duplicate, M-EDIT-006) duplicates the selected tracks (`track.duplicate`). Each copy goes straight after its track, a group's after the group and holding copies of its tracks, a track inside a selected group being copied only with it; a return track's copy goes straight after it among the return tracks, every track's send to it at −∞ dB, as a new return track's is (Beatlayer's own). Each copy is named as Duplicate Track Without Clips names its copies ([routing](routing.md) R28: "4 Audio"'s copy is "5 Audio"), and the copies become the selected tracks. One undo step, `Duplicate Track(s)`. Main can't be duplicated. (S1, S3, S5, S6)
- **R13.** A track's copy holds everything the track has, under new IDs throughout: its kind, name, colour, mixer, sends and routing; its devices with their states and sidechains; its Arrangement clips, its take lanes ([comping](comping.md) R1) and its Session clips, in the same scenes; its automation and clip envelopes; and, when it's frozen, its frozen state and files ([freeze and bounce](freeze-and-bounce.md) R13). A reference between tracks copied together goes between the copies (a sidechain from one to the other, or one's Audio From the other); a reference to a track not copied stays as it is (sends go to the same return tracks, an input comes from the same track). A copy isn't in a link group ([linked-track editing](linked-track-editing.md) R5). Copying a track within a set and adding one from another set ([set exchange](set-exchange.md) R5) make the copy the same way, and differ only in the references to tracks outside it, which a track from another set settles as set exchange R6 says. Beatlayer's own: a frozen track's copy, and keeping references to tracks not copied. (S5, S6)
- **R14.** With track title bars selected, Copy (Cmd+C, S-EDIT-002; C-TRACK-002) puts copies of the selected tracks on the clipboard (`track.copy`), made as R13 makes them, and changes nothing in the set; it's never an undo step. Cut (Cmd+X, S-EDIT-001; C-TRACK-001) copies them and then deletes them as Delete does (R4), one undo step, `Cut Track(s)`. Paste (Cmd+V, S-EDIT-003) with tracks on the clipboard inserts a copy of them (`track.paste`) straight after the last selected track, at its level, inside its group when it's in one, or after the last track when none is selected, whatever else is selected, and selects them; one undo step, `Paste Track(s)`, each Paste making new copies. The clipboard holds whichever was copied last, tracks or Arrangement material (arrangement editing R11). Beatlayer's own: the names of Cut's and Paste's undo steps, and where pasted tracks go. (S1, S3, S6)
- **R15.** The clipboard lasts from set to set (arrangement editing R11), so tracks copied in one set paste into another: there the copies are made as tracks added from a set are ([set exchange](set-exchange.md) R5 to R7), their references to tracks not pasted settled by set exchange R6 and their audio files registered by set exchange R7 from the media table copied with them. (S6)
- **R16.** `track.duplicate` (`edit`; tracks, or the selection), `track.copy` (`read`), `track.cut` (`destructive`) and `track.paste` (`edit`; the track to paste after, or the selection) are registered commands with a schema and a description for a model; the three that edit read back through the query tool's `song`, field `tracks`, and return the new tracks' IDs. In the track-headers context Cmd+X, Cmd+C, Cmd+V and Cmd+D run them, and the menu's Cut, Copy and Duplicate do; with clips or time selected, the same keys run the Arrangement's edits (arrangement editing R9 to R11). Duplicate Track Without Clips keeps its rule (routing R28) and makes its copies the same way, without clips or automation. (S3, S6)
