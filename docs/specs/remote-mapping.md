## The behaviour

Most controls in the window can be driven from a MIDI controller or from the computer keyboard. A mapping joins one source, a MIDI note, a range of notes, a controller, a high-resolution controller, pitch bend, or a computer key, to one control: a Session slot, a switch or button, a radio button, or a continuous control such as a fader. Mappings belong to the set, so they're saved with it and travel with it. Each has a Min and a Max that limit the part of the control's range the source covers, and a controller's mapping has a mode: absolute, or one of the relative encodings encoders send.

Every MIDI input whose Remote switch is on feeds one merged remote input. A message there that a mapping takes is used for remote control and never reaches a track, so a key mapped to a clip no longer plays its instrument. What the message does depends on the control's kind and the source: a note launches a slot by its launch mode and toggles a switch; a controller sets a fader through the mapping's range; an encoder nudges a value up or down. Takeover Mode, a preference, decides what happens when a fader and the control it drives disagree. A slot mapped to a range of notes plays its clip chromatically, transposed by the key played. While a control's value changes, Beatlayer sends it back to every output whose Remote switch is on, so motor faders and LEDs follow.

The window side, the map modes that make mappings by a click and a message, the overlays and the Mapping Browser, is [map modes](map-modes.md)'s. This spec covers the mappings in the set, the remote input, what a message does to each kind of control, takeover, chromatic slots and feedback.

## Rules

### Mappings in the set (WP-7.1)

- **R1.** A mapping joins one source to one control. A MIDI source is one of: a note (a channel from 1 to 16 and a key from 0 to 127); a note range (a channel, a lowest and a highest key, and for a slot a root key between them, R33); a control change (a channel and a controller from 0 to 127); a 14-bit control change (a channel and a controller from 0 to 31, whose partner 32 higher carries the low seven bits); or pitch bend (a channel). A key source is one key of the computer keyboard, named as the keymap names keys. (S1, S4, S5, S6; the key naming is Beatlayer's own)
- **R2.** Every mapping has a Min and a Max, and a controller mapping has a mode: Absolute, Absolute (14-bit) for a 14-bit source, or one of the eight relative modes, Signed Bit, Signed Bit 2, Bin Offset and Twos Complement, each accelerated or linear (R25, R26). A pitch bend mapping is absolute. (S4, S5)
- **R3.** The control is any mappable control the window shows ([map modes](map-modes.md) R11 to R13), named by the IDs of what it belongs to: a slot by its track and scene, a mixer control by its track and what it is, a device parameter by its device and parameter, a Clip View control by what it sets, a Control Bar control by its element. Each mappable control has a kind, which decides what a message does to it: a slot, a switch, a button, a radio button with its options in order, or a continuous control with its range. (S1; the naming is Beatlayer's design)
- **R4.** A new mapping's Min and Max are the bottom and the top of its control's range: a continuous control's own range, a radio button's first and last options, and for a ranged switch (R20) the controller values 64 and 127 (Beatlayer's own). A controller mapping starts in the mode its learning gives ([map modes](map-modes.md) R5), Absolute when it is made by command without one. Min and Max are kept in the control's own units, and a continuous control's are applied as positions along its travel, as a macro's are ([macros](macros.md) R7). (S4; the defaults are Beatlayer's own)
- **R5.** One source maps one control, and a control has at most one MIDI mapping and at most one key mapping. Mapping a source that already maps another control moves the mapping to the new control; mapping a control that already has a mapping of that kind replaces it. A note range counts as each of its keys, so mapping a key inside a range takes it from the range's control. (Beatlayer's own)
- **R6.** Mappings belong to the set: saved with it and loaded back, and a set saved before them loads with none. Making a mapping, deleting it, and changing its Min, Max or mode are one undo step each. A control that leaves the set (a deleted track, scene, device or clip panel's owner) takes its mappings with it in the same undo step, and undoing brings them back; copying a track, a device or a rack copies none of its mappings. A mapping whose control a loaded set doesn't hold is dropped, and loading says how many. Key mappings are the set's and never shortcuts ([custom shortcuts](custom-shortcuts.md) R17). (S6, S14; undo, copying and dropping are Beatlayer's own)

### The remote input (WP-7.1)

- **R7.** Every MIDI input whose Remote switch is on feeds one remote input, their messages merged in the order they arrive; a mapping matches a message by its channel and its kind and number, whichever port it came from. An input whose Remote switch is off feeds nothing to remote control. (S2, S14)
- **R8.** A message on the remote input that a mapping takes goes to remote control and never reaches a track, even when its port's Track switch is on. A note mapping takes its key's note-ons and note-offs; a 14-bit mapping takes both of its controllers; a pitch bend mapping takes every pitch bend on its channel. A message no mapping takes reaches tracks as [MIDI I/O](midi-io.md) R5 says, and one from an input whose only switch on is Remote goes nowhere and is counted. (S6, S7, S14)
- **R9.** Whether a mapping takes a message is decided on the MIDI system's thread, before the message is sent towards the engine, from a table of mapped messages (one bit for each channel and each note, controller and pitch bend) that the main thread publishes whenever the mappings change. Reading it there allocates nothing, takes no lock and never blocks, and a change to the mappings applies to every message stamped after it is published. (S15; Beatlayer's design)
- **R10.** Messages a mapping takes, stamped as [MIDI I/O](midi-io.md) R13 says, cross to the main thread on a lock-free queue of their own, and the main thread applies them in the order they arrived on its next poll. While a map mode is on, every message on the remote input crosses that queue too, for learning ([map modes](map-modes.md) R5), and whether it also reaches tracks is still R8's to decide. A sender never waits: when the queue is full, what doesn't fit is dropped and counted. (S15; Beatlayer's design)
- **R11.** Applying a mapped message runs its control's registered command with the value or the press the laws (R15 to R32) give: the command a click, a drag or a key on that control runs, so it reaches the engine as that gesture would, a move on an automated control overrides its envelope as a hand move does ([automation](automation.md) R5), and moves while Automation Arm records are written as automation ([automation](automation.md) R17). A slot's press and release run `session.launch` and `session.release`. A message whose control is refused (a parameter a macro holds, a control a set no longer has) changes nothing and is counted. (S1, S11, S14)
- **R12.** A run of messages to one mapping that changes a continuous control is one undo step, named as the control's own gesture is, which ends at a message to another mapping, any other edit, or one second of the shell's clock without a message for it; each change of a switch or a radio button is a step of its own, and a launch or a release is no undo step, as [launch quantisation](launch-quantisation.md) R9 makes launches read-class. (Beatlayer's own)
- **R13.** A key mapping acts on the key's press and its release, as a note's note-on and note-off do, while no text field has the keyboard and no map mode is on; holding a key doesn't repeat it. While the computer MIDI keyboard is on, the keys it plays ([MIDI I/O](midi-io.md) R18 to R22) play notes and their key mappings don't act. A key that has both a key mapping and a single-key shortcut runs the mapping, and a key pressed with Cmd, Ctrl or Option (Alt) is never a key mapping's. While a map mode is on, mappings don't act: a message or a key is taken for mapping instead ([map modes](map-modes.md) R4, R5 and R7). (S6, S8; the shortcut and the modifiers are Beatlayer's own)
- **R14.** Every action here is a registered command with a schema, a description and a permission class, run by ID through the agent API: `remote.mappings` (`read`): every MIDI and key mapping, with its source, its control's path and name, its kind, Min, Max and mode, and a note range's root; `remote.map` (`edit`): makes a mapping from a source and a control, with an optional Min, Max and mode; `remote.unmap` (`edit`): deletes the mappings named, or the mapping of a control by source kind; `remote.set_range`, `remote.invert_range` (swaps Min and Max) and `remote.set_mode` (each `edit`); and `remote.input` (`edit`): applies a MIDI message or a key press and release as if it came from the remote input, so an agent tries a mapping without a controller. The first five read back in `remote.mappings`; `remote.input`'s effect is its control's, read back as that control's own command is. (S15)

### What a message does (WP-7.2)

A control's value is read along its travel from 0 to 1 ([device framework](device-framework.md) R1), and a mapping's Min and Max are positions on that travel (R4); "the mapping's range" below means from Min to Max, Min above Max turning it round, and a stepped control takes the step nearest the position it's given.

- **R15.** A note-on of a note mapped to a slot presses the slot's launch button with the note's velocity and its note-off releases it, so the clip's launch mode decides what happens ([launch quantisation](launch-quantisation.md) R17 to R21); a key mapped to a slot does the same with velocity 127. A slot's mapping is the slot's, not its clip's: an empty slot's press does what clicking it does. (S1, S9)
- **R16.** A launch carries a velocity from 1 to 127: a note's own, and 127 from a click, a key or a controller. The clip plays at a gain of 1 − a · (127 − v) / 126, where `a` is its velocity amount from 0 to 1 and `v` the velocity, so at 100 % a note of velocity 1 is silent and at 0 % velocity changes nothing; the gain holds until the clip stops or launches again. (S9, S14; the curve is Beatlayer's own)
- **R17.** A note-on of a note mapped to a switch toggles it, and its note-off does nothing. A note-on mapped to a button presses it, and its note-off releases it where the button acts on release. A note-on mapped to a radio button selects its next option, after the last the first. (S1; wrapping is Beatlayer's own reading)
- **R18.** A note-on of a single note mapped to a continuous control sets it to Max, or to Min when it is at Max already. (S1; the test at Max is Beatlayer's own reading)
- **R19.** A note range of `n` keys mapped to a continuous control or a radio button gives its `k`-th key from the lowest (`k` from 0) the position `min + k / (n − 1) · (max − min)`, a radio button taking the option nearest that position; note-offs do nothing. (S1)
- **R20.** For an absolute controller (a control change, a 14-bit control change or pitch bend, of full scale `F`: 127, or 16,383 for the last two, and half scale `H`: 64, or 8,192): on a slot, a value of `H` or more presses the launch button and a lower value releases it, a press only when the value comes from below `H` or is the first since the mapping was made, and a release only when it comes from `H` or above. On a ranged switch (a track's activator, a device's on/off switch, and a device's own switch parameters), a value from Min to Max turns it on and one outside turns it off, and with Min above Max a value outside turns it on and one inside off; Min and Max are controller values. On every other switch, `H` or more turns it on and less turns it off. (S4; the edge rule on a slot is Beatlayer's own)
- **R21.** An absolute controller's value `c` gives a radio button the option at position `c / F` of the mapping's range, and a continuous control the position `min + (c / F) · (max − min)`. (S4)
- **R22.** A 14-bit control change's value is its controller's value times 128 plus its partner's: a message on the controller applies at once with the low part taken as 0, and a message on its partner applies again with the low part it carries. Pitch bend's value is its 14 bits, 8,192 its centre. (S4; applying the high part alone first is Beatlayer's own, as MIDI 1.0 orders the pair)
- **R23.** A relative controller's message is an increment or a decrement of a size: on a slot an increment presses the launch button and a decrement releases it; on a switch an increment turns it on and a decrement off; on a radio button an increment selects the next option and a decrement the previous one, stopping at the ends; on a continuous control it moves the control by its size in steps (R26), within the mapping's range. (S5)
- **R24.** The four relative encodings read a controller value `c` as follows, a size of 0 changing nothing: Signed Bit, 65 to 127 an increment of `c − 64` and 1 to 63 a decrement of `c`; Signed Bit 2, 1 to 63 an increment of `c` and 65 to 127 a decrement of `c − 64`; Bin Offset, 65 to 127 an increment of `c − 64` and 0 to 63 a decrement of `64 − c`; Twos Complement, 1 to 63 an increment of `c` and 64 to 127 a decrement of `128 − c`. (S5; the encodings are Beatlayer's own reading of the four names)
- **R25.** In an accelerated mode a message moves a continuous control by its size in steps; in a linear mode by one step whatever its size. (S5; Beatlayer's own reading of "linear")
- **R26.** A step is one 127th of the mapping's range for a continuous control, and one step of a stepped control's own. (Beatlayer's own)
- **R27.** When a controller is learned ([map modes](map-modes.md) R5), Beatlayer guesses its mode from the controller's messages that arrive while it is learned, until another control is selected or the map mode ends: a 14-bit pair when a message on a controller from 0 to 31 is followed by one on its partner on the same channel; relative when two messages in a row carry the same value, the value naming the encoding of a decrement of one (1 Signed Bit, 65 Signed Bit 2, 63 Bin Offset, 127 Twos Complement), accelerated when any of its messages has a size above one and linear otherwise; Absolute in every other case. Each new message can change the guess, and the mapping takes the latest. (S5; the guess is Beatlayer's own)
- **R28.** Takeover Mode, in Settings ▸ Tempo & MIDI after the Control Surfaces table and before the MIDI ports table (L-SET-014), offers None, Pick-Up and Value Scaling. It is a preference, kept between starts and the same for every set, no undo step, None on a new install (Beatlayer's own), set by `settings.set_takeover_mode` (`edit`, as a kept preference) and read back as `takeover_mode` in `settings.state`. (S3, S13)
- **R29.** Takeover applies to an absolute controller's mapping on a continuous control while the control's position differs from the one the mapping's last message gave it: after a click, a drag, automation, an agent, another mapping, or a control surface moved it, and for the first message after the mapping is made or the set loads. With None each message sets the control as R21 says. (S3)
- **R30.** With Pick-Up, a message changes nothing until the controller reaches the control's position: when its value is the control's, or the control's lies between the controller's previous value and this one. From then the control follows the controller as None does, until something else moves it again. The first message, which has no previous value, changes nothing unless it is the control's own value. (S3; the first message is Beatlayer's own)
- **R31.** With Value Scaling, a message that moves the controller from `c` to `c′` moves the control from `p` to `p + (c′ − c) · (e − p) / (e − c)`, where `e` is the end of the range the controller moves towards, so both reach that end together; once the two are within one step (R26) of each other, the control follows the controller as None does. The first message, with no previous value, changes nothing. (S3; the formula is Beatlayer's own)
- **R32.** The value laws are pure functions of the mapping, the message, the control's kind and value and, for takeover, the mapping's last value: `bl-control` holds them apart from the window, and the same message on the same state gives the same result on every platform. (S15)

### Chromatic slots (WP-7.2b)

- **R33.** A slot mapped to a note range has a root key inside the range, learned first ([map modes](map-modes.md) R6), and the range's lowest and highest keys. (S10)
- **R34.** A note-on of a key `k` in a slot's range presses the slot's launch button with its velocity (R16) and launches the clip transposed by `k − root` semitones; the root launches it as it is. The key's note-off releases it as R15 says. (S1, S10)
- **R35.** A transposed launch moves a MIDI clip's notes by the semitones on their way to the track's devices, a note moved outside 0 to 127 not playing, and an audio clip's pitch by the semitones added to its own Transpose, through its warp mode as Transpose does, limited to the 48 semitones either way that Transpose allows. The transposition is the launch's: it changes nothing in the set, the clip's Transpose control doesn't move, and it holds until the clip stops or launches again. (S10, S14; the limits and leaving the clip unchanged are Beatlayer's own)
- **R36.** One clip plays on a track ([launch quantisation](launch-quantisation.md) R11), so a second key launches the clip again at its own transposition on its launch's grid line, as a relaunch does; releasing a key whose launch is no longer the latest does nothing. (S14; Beatlayer's own reading)
- **R37.** A launch carries its transposition and velocity to the engine in the launch command, and the engine applies them on the launch frame without building a new program and without allocating, locking or blocking on the audio thread. `session.launch` takes an optional `transpose` (−127 to 127 semitones) and `velocity` (1 to 127), so an agent launches a clip as a mapped key would. (S15)

### Feedback and the indicators (WP-7.4)

- **R38.** While a control with a MIDI mapping changes value, by any means, Beatlayer sends the mapping's message with the control's value to every output whose Remote switch is on: an absolute controller or pitch bend the value R20 to R22 would map to the control's position (the high part then the low part for a 14-bit pair); a note mapped to a switch a note-on with velocity 127 while it's on and velocity 0 while it's off; a note mapped to a slot velocity 127 while its clip plays or is queued and 0 otherwise; a relative mapping the absolute value of the control's position in its range, 0 to 127, on the mapping's controller. A single note on a continuous control, a note range, and key mappings send nothing. (S2; what each sends is Beatlayer's own)
- **R39.** Feedback is sent once for each change, at most one message per mapping on each poll of the main thread, carrying the latest value; a change that a mapping's own message caused isn't sent back to that mapping, so a motor fader isn't fought while it is moved. Switching an output's Remote switch on, loading a set and making a mapping send every mapping's value. (S2; Beatlayer's own)
- **R40.** Feedback leaves through the MIDI output from the main thread, stamped with the time it is sent, on a path of its own beside the engine's: it never waits for the audio thread and the audio thread never waits for it. (S15; Beatlayer's design)
- **R41.** The Control Bar's remote pair of MIDI indicators, between the sync pair and the tracks' pair (L-CTRL-026), lights its upper lamp for a moment for each message remote control takes, by a mapping or for learning, and its lower lamp for each feedback message sent, as [MIDI I/O](midi-io.md) R25's lamps do. The key indicators beside the Key switch (L-CTRL-021) light their upper lamp for each key a key mapping takes; the lower lamp stays dark (Beatlayer's own). (S7, S13)
- **R42.** Remote control records as clicking does: the Control Bar's Arrangement Record, transport controls, Session Record and New, the tracks' Arm buttons, slots, the relative Session mapping strip and the step recording arrows are mappable ([map modes](map-modes.md) R11 to R13), and a mapped slot on an armed track records into an empty slot as a click on it does. (S11)
- **R43.** `remote.state` (`read`) reports the remote input's counts (messages taken, dropped, refused, and sent as feedback), when each indicator lamp last lit, the takeover state of each mapping (following, or waiting with its last value), and the guess of R27 while a controller is learned. (S15)
- **R44.** Nothing in remote control runs on the audio thread except what R9 and R37 say, and the work there allocates nothing, takes no lock and never blocks. (S15)
