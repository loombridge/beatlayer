## The behaviour

Live 12 organises the browser with tags. Every item can carry tags, each in a tag group, and a tag can hold subtags. The Tag Editor, beside the content pane, lists every group with a check box per tag, so a person puts tags on the selected items and makes tags and groups of their own; Quick Tags, at the bottom of the content pane, shows the selected items' tags and adds one by typing its name. Typing `#` and a tag's name in the search field finds what carries it. The Filter View, at the top of the content pane, shows the chosen label's tag groups as rows of buttons: clicking tags narrows the list to what carries them, and Add Label keeps the search and the tags as a label of its own in the sidebar, which lists what they find from then on. Collections are seven coloured labels, Favorites first: the keys 1 to 7 put the selected items in one, 0 takes them out, and choosing a collection lists everything in it. Back and Forward step through where the browser has been, and the content pane can show more columns than Name and sort by any of them.

Beatlayer ships none of Live's content and none of its tag vocabulary. It fills four tag groups of its own from what it knows of each item (what the file is, a plug-in's format and vendor, where a device goes in a chain), and the rest are the person's. Tags, collections and saved labels live in one database file beside Beatlayer's preferences, with the index of the places' files, so the browser knows them from the first frame after a start. Tagging changes the database, never the files. Beatlayer adds, from IMP-07, plug-ins hidden from browsing and search, a preferred format for a plug-in that comes in several, and collections that hold collections.

This spec covers the database, tags and tag groups, the Tag Editor, Quick Tags, `#` search, the Filter View and its menu, saved labels, the Library labels' order and visibility, the content pane's columns, the browser's history, collections, and IMP-07's parts. Automatic tags of samples and plug-ins, the Function group they fill and the Filter View Menu's Include Auto Tags are WP-9.11's (R49 to R58); similarity search is [sound similarity](sound-similarity.md)'s.

## Rules

**The browser's database (WP-6.31)**

- **R1.** The browser keeps the index of the places' folders and files (browser R10), the tags and tag groups and the items that carry them, the collections and their members, and the saved labels in one database file in Beatlayer's configuration folder, beside its preferences (Beatlayer's own place). Beatlayer reads it when it starts, so the browser lists, searches and filters what was indexed before from the first frame; indexing then runs in the background as browser R10 says and brings the database up to date with what changed on disk, telling a changed file by its size and modification time. This replaces browser R10's index held only in memory. (S18)
- **R2.** Search keeps browser R9's meaning, every word typed found in an item's name ignoring case, and browser R10's speed: with 100,000 files indexed, a search answers within one frame (16 ms), measured by the browser's index benchmark. (S18)
- **R3.** The database is written on a background thread, and each write is atomic: a write stopped at any point leaves the database as it was before the write or after it. Several running instances of Beatlayer share it without damaging it. A database that can't be read is renamed aside, `.damaged` added to its name, a new one is built from the places, and the Status Bar says so. (S18; Beatlayer's own)
- **R4.** The database records its schema version. A database from an earlier version of Beatlayer is migrated when it's opened; one from a later version is left untouched, and that session keeps its index in memory, as browser R10 did, without tags, collections or saved labels. (Beatlayer's own, as [crash recovery](crash-recovery.md) leaves a newer version's sessions alone)
- **R5.** Tags and collections belong to an item by its key: a file or folder by its path; a plug-in by its format and identifier, the key hiding uses (plugin-scanning R7); one of Beatlayer's own devices or an empty rack by its row's ID in the device labels. When a tagged or collected file is no longer at its path, its tags and collections stay in the database, and pass to the first file of the same size and content (its BLAKE3 hash, audio-import R9) that indexing finds in a place, so a file moved or renamed outside Beatlayer keeps them. A file that is still at its path never gives its tags away, even when its place leaves the index, and tags that pass are added to the ones the file already has. The hash of a tagged file is kept in the database apart from the index, so it outlasts the file's row. (S18; Beatlayer's own, after file-management R6)

**Tags and tag groups (WP-6.31)**

- **R6.** Every tag belongs to one tag group. A tag can hold subtags, one level deep: a subtag holds none. A tag's full name is its path, the group's name, the tag's and any subtag's joined by `|`, as `Format|CLAP`. An item that carries a subtag also counts as carrying its tag, in filters and searches (Beatlayer's own). (S5, S11, S12)
- **R7.** Beatlayer fills four tag groups itself, its default groups, from what it knows of each item, and keeps them current as indexing and plug-in scanning go on: **Content**, what the item is: Sample (an audio file), Audio Clip, MIDI Clip, Preset, Set, Backup Set (a set in a project's `Backup` folder, which isn't also a Set), Device (one of Beatlayer's own devices or an empty rack) and Plug-In; **Format**, a plug-in's format: CLAP, VST3 and AUv2, as the Plug-Ins label's badges name them; **Creator**, a plug-in's vendor, a tag for each; and **Devices**, where a plug-in, a device or a device preset goes in a chain: Instrument, Audio Effect and MIDI Effect. These tags can't be taken off an item, and the four groups and the tags Beatlayer gives can't be renamed or deleted. The group names, and the tags Audio Clip, MIDI Clip, Preset, Set, Backup Set, AUv2 and VST3, are Live's; the other tags are Beatlayer's own. (S4, S5, S10, S11, S13, S15)
- **R8.** A person makes tags of their own in any group, Beatlayer's included, and groups of their own, and puts subtags under any tag outside the Creator group. Their own tags and groups can be renamed and deleted. Renaming changes the tag on every item that carries it and in every saved label that uses it. Deleting a tag takes it off every item; deleting a group deletes its tags; deleting either when a saved label uses it first asks, naming the labels, and the labels then leave it out. (S5, S10)
- **R9.** Any item the browser lists can carry tags: files, folders, plug-ins and Beatlayer's own devices, one or many selected together. A tag on a folder counts for everything inside it, at any depth: filters and `#` searches find those items by it, and Quick Tags shows it on them. Tagging changes only the database, never a file, and isn't an undo step of the set. (S5, S9, S11)

**The Tag Editor (WP-6.31)**

- **R10.** The Tag Editor (L-BRW-013) opens beside the content pane, from the Filter View Menu's Tag Editor item or with Cmd-Shift-E (Ctrl-Shift-E) while the browser has the focus (S-BRW-014), and closes by the same key, the same item, or the close button at its top right. Whether it's open is kept between launches. (S5, S13, S15, S16)
- **R11.** The Tag Editor lists every tag group in order, each foldable, with its tags, each tag's subtags under it, and a check box beside every tag. A check box is ticked when every selected item carries the tag, shows a dash when only some do (Beatlayer's own mark), and is empty otherwise; ticking it puts the tag on every selected item, and unticking takes it off them. A tag Beatlayer gives (R7) or one an item has from its folder (R9) can't be unticked on that item. A folded group, or a folded tag, that holds a tag the selection carries is drawn marked, and a tag with subtags shows an arrow. (S5, S11)
- **R12.** Each group in the Tag Editor ends with Add Tag…, which makes a tag at the end of it, named as the person types, and the list ends with Add Group…. A person's own tag has a context menu with Add Subtag In… (outside the Creator group, and not on a subtag), Rename and Delete; a person's own group has Rename and Delete. Dragging a tag moves it within its group, and dragging a group moves it in the list (I-DRAG-056); the Filter View shows groups and tags in that order. Reset Order, in the context menu of the list's background, puts every group and tag back in its first order (Beatlayer's own name and place). (S5, S11)

**Quick Tags and searching by tag (WP-6.31)**

- **R13.** Quick Tags (L-BRW-012) sits at the bottom of the content pane, above the preview strip; it's shown in a new install, hidden and shown by the Filter View Menu's Show Quick Tags, and kept between launches. It lists the tags the selected items carry, marking with an asterisk each one not all of them carry. A person's own tag shows an X that takes it off the selected items; Beatlayer's tags and a folder's tags show none. Selecting a tag there shows its group in the Status Bar; double-clicking it searches for it, as `#` and its path typed in the search field do (I-CLICK-051); its context menu's Show Tag in Tag Editor opens the Tag Editor with that tag shown and selected. (S6, S12, S13)
- **R14.** Quick Tags' Add… field takes a tag's name; Cmd-E (Ctrl-E) while the browser has the focus moves the keyboard focus to it. As the person types, it suggests the tags whose names hold what's typed, by full name; Enter or a click on a suggestion puts that tag on the selected items. A name no tag has offers Create New Tag…, which asks for the group or the tag to put it in, an existing one or a new one named there, makes it (as a subtag at most one level deep, R6) and puts it on the selected items. Esc leaves the field. (S6, S12, S14)
- **R15.** In the search field, `#` followed by a tag's name, or its full path, finds the items that carry it (R6, R9), in any group. While a `#` term is typed the field suggests the tags whose names hold what's typed, those searched most recently first, and Enter or a click takes one. Several `#` terms must all match, and plain words still match names (browser R9). A `#` term that names no tag is searched as plain text, and the Status Bar says that no tag has that name. (S1, S10, S11, S12)

**Commands and access (WP-6.31)**

- **R16.** Every action above is a registered command. `browser.tags` reads the tag groups and their tags in order, which are Beatlayer's, and, given items, the tags each carries, and from where (its own, a folder's, Beatlayer's); it's external, as `browser.state` is, because it lists files outside the project. `browser.tag_items` puts tags on items and takes them off; `browser.add_tag` makes a tag in a group or a subtag under a tag; `browser.add_tag_group`, `browser.rename_tag` (a tag or a group), `browser.move_tag` (a tag or a group) and `browser.reset_tag_order` are edits; `browser.delete_tag` (a tag or a group) is destructive, because undo can't bring back what carried it. `browser.show_tag_editor` (read) and `browser.show_quick_tags` (an edit to preferences) show and hide the panels. Each edit reads back in `browser.tags`, and the panels in `browser.state`. (S18)
- **R17.** The Tag Editor and Quick Tags build only the rows on screen, and reach assistive technology: each group as a group with its name and whether it's folded, each tag as a check box naming its full path and whether it's ticked, partly ticked or fixed, Quick Tags' tags as a list, and the Add… field as an editable field. From the keyboard, Up and Down move through the Tag Editor's rows, Left and Right fold and unfold them, and Space ticks and unticks (Beatlayer's own keys). (S11, S18; browser R17)

**The Filter View (WP-6.32)**

- **R18.** The Filter View toggle, on the browser's top row at x 275 (L-BRW-001), View ▸ Show Filter View (M-VIEW-027) and Cmd-Option-G (Ctrl-Alt-G) while the browser has the focus (S-BRW-013) show and hide the Filter View. It's shown in a new install, and kept between launches. Shown, it fills the content pane's top from y 84, under each group's name a row of its tag buttons that wraps (to y 204 in the default state, L-BRW-007), and the column header row and the list move down under it (the header at y 208 to 227, the list from 227, L-BRW-009, L-BRW-010); hidden, they sit at the content pane's top, as browser R1 says. (S3, S12, S13, S15, S16)
- **R19.** Each label has its own filter groups. In a new install they are (Beatlayer's own choice): under All, every group; under Plug-Ins, Devices, Format and Creator; under the device labels (Instruments, Audio Effects, MIDI Effects, Drums, Modulators), Devices and Content; under the other Library labels, a place, a collection and a saved label, Content. The person's own groups show under every label. A group shows only once an item under the label carries one of its tags, and shows only those tags, in the Tag Editor's order. (S3, S5, S9, S15)
- **R20.** Clicking a tag button selects that tag alone in its group; Cmd-click (Ctrl-click) adds it to the group's selection or takes it out (I-CLICK-031); clicking a selected tag alone clears it. The list then holds the items under the label that carry, for each group with a selection, at least one of that group's selected tags, and that match every search word: tags in one group widen the list, groups narrow it (Beatlayer's own reading of S3). The selected tags are kept when another Library label is chosen, and apply there to the groups it shows. (S3, S9, S16)
- **R21.** The Filter View Menu, the button at x 297 on the top row, lists in order: an item for each group the chosen label can show, ticked while it shows; Show All Filter Groups; Reset Filter Groups to Default, which puts the label's groups back to R19's; then Include Auto Tags (R55); Tag Editor (R10); and Show Quick Tags (R13), each ticked while its panel shows. Right-clicking a group's name in the Filter View offers Hide Filter Group, which hides it under the chosen label. Which groups each label shows is kept between launches. The menu's order, Show All Filter Groups and Hide Filter Group are Beatlayer's own. (S3, S12, S15)
- **R22.** While a search or a filter is active, the Results bar (L-BRW-008) sits between the Filter View and the column header row. It says how many filter tags are selected, and holds Clear, an X, which clears the selected tags and the search words, and Add Label, a bookmark (R24). The search field's own clear button clears only the words. Esc in the search field clears the words and the selected tags. Cmd-F (Ctrl-F, browser R8) clears the selected tags under All and selects the search field's text rather than clearing it, so typing replaces it and the arrow keys edit it. (S1, S3, S11, S13, S14)
- **R23.** Tab moves from the search field to the Filter View toggle, the Filter View Menu, then the sidebar, and from the sidebar to the Filter View when it shows, otherwise to the content pane (I-FOCUS-007). In the Filter View, the arrow keys move between tag buttons, Enter selects or clears one alone and Cmd-Enter (Ctrl-Enter) adds or takes it from its group's selection (Beatlayer's own keys). Each group reaches assistive technology as a group with its name, and each tag as a toggle button naming its tag and whether it's selected. (S11, S17)

**Saved labels and the Library labels (WP-6.32)**

- **R24.** Add Label keeps what the browser is showing as a saved label: the label it was made under, the search words and the selected tags. The new label goes at the end of the Library section, after the Library labels (L-BRW-004), named after its words and tags, with its name ready to edit; it's kept between launches. Choosing it lists what those words and tags find under that label now, so it follows new files and new tags. (S1, S3, S9)
- **R25.** A saved label's context menu (C-BROWSER-018) holds Rename (also Cmd-R, Ctrl-R), Choose Icon, which offers Beatlayer's own icons and Reset Icon, and Remove, which deletes the label and nothing else. The Library labels can be renamed and given icons too, and the person's folders in Places given icons; All, User Library and Current Project keep theirs. (S1, S12, S16)
- **R26.** Edit, shown when the pointer is to the right of the Library heading, gives every Library and saved label a check box that shows or hides it in the sidebar; Done ends it. Dragging a Library or saved label moves it within the section, All staying first (I-DRAG-056), and the Library heading's context menu has Reset Label Order, which puts Beatlayer's labels back in browser R2's order with the saved labels after them (Beatlayer's own name). Hidden labels and the order are kept between launches. (S8, S10, S11)

**The content pane's columns (WP-6.32)**

- **R27.** The Name column always shows. The Content Options menu, opened by the menu button at the column header row's right (L-BRW-009) or by right-clicking any column's name, lists the other columns, each ticked while shown: Date Modified, Size, Kind, and, for audio files, Length, Sample Rate and Channels (Beatlayer's own columns and names); then Show File Extensions. Dragging a column's name moves the column (I-DRAG-057); the columns share the pane's width, and the Name column takes what the others leave. (S8, S12)
- **R28.** Clicking a column's name sorts the list by it, and clicking it again reverses the order; the column sorted by shows an arrow. By default the list sorts by Name as browser R6 says, folders first; sorting by another column keeps folders first and orders each folder's contents by that column, ties by name. Length, Sample Rate and Channels come from the files' headers, which are read in the background: a file not read yet sorts as having no value, and the list sorts again as the headers arrive. The columns shown, their order, the sort and Show File Extensions are kept between launches. (S8, S12)

**The browser's history (WP-6.32)**

- **R29.** The browser keeps a history of what it showed this session: each step holds the chosen label, the search words, the selected filter tags, the open folders and the selection. A new step is taken when the label changes, when the selected tags change, and when a search starts or its words change, except that changes to the search words in a row make one step. A step taken after going back drops the steps ahead of it. The history holds the last 100 steps and isn't kept between launches (Beatlayer's own limits). (S2, S9)
- **R30.** Browse Back and Browse Forward, on the top row at x 9 and 29 (L-BRW-001), Cmd-[ and Cmd-] (Ctrl-[ and Ctrl-], S-BRW-011, S-BRW-012), Navigate ▸ Browser History Back and Browser History Forward (M-NAV-016, M-NAV-017) and the mouse's back and forward buttons over the browser (I-CLICK-050) go one step back or forward, showing that step's label, words, tags, open folders and selection. Each is disabled at its end of the history, as in a new set. (S2, S9, S14, S15, S16)
- **R31.** Starting hot-swap ([device chains](device-chains.md) R19, [racks](racks.md) R44) clears the search words and the selected tags as a new step, so Browse Back brings them back. (S11, S14)

**Commands (WP-6.32)**

- **R32.** Every action above is a registered command, reachable headless through `Shell::run`: `browser.set_filter_view` and `browser.set_columns` (the shown columns, their order, the sort and file extensions) are edits to preferences; `browser.filter` (select tags, alone or added to a group's selection) and `browser.clear_filters` change what the browser lists and are external, as `browser.search` is; `browser.set_filter_groups` (show, hide, show all, reset under a label), `browser.add_label`, `browser.rename_label`, `browser.set_label_icon`, `browser.set_label_shown`, `browser.move_label` and `browser.reset_label_order` are edits; `browser.remove_label` is destructive; `browser.back` and `browser.forward` are external, as `browser.open_place` is. Each reads back in `browser.state`, which reports the Filter View, the groups shown, the selected tags, the saved labels, the columns and sort, and whether Back and Forward can go. (S18)
- **R33.** The Filter View, the saved labels and the columns follow browser R17: only the rows on screen are built, and every part reaches assistive technology with a role, a name and a value. (S18)

**Collections (WP-6.32b)**

- **R34.** The Collections section lists seven collections in order, Favorites, Orange, Yellow, Green, Blue, Purple and Gray (browser R2), each with a colour of its own from Beatlayer's theme. (S7, S15)
- **R35.** With items selected in the content pane, the keys 1 to 7 (S-BRW-008), and the matching items of the item's context menu (C-BROWSER-005 to 011), put them in the collection of that number; when every selected item is in it already, the key or item takes them out (Beatlayer's own). The key 0 (S-BRW-009) and Clear All Colors (C-BROWSER-004) take them out of every collection. Any item the browser lists can be in collections, several kinds together, and in several at once. Collections are kept in the database (R1, R5) and aren't undo steps of the set. (S7, S16)
- **R36.** Choosing a collection lists every item in it, of every kind, in browser R6's order, folders openable; search, filters (R20) and Enter and dragging work there as under any label, and a plug-in or device listed there loads as it does from its own label (plugin-scanning R11, [racks](racks.md) R43). (S7)
- **R37.** Each row of the content pane shows a small square in the colour of each collection the item is in, in the collections' order, three at most. (S7)
- **R38.** A collection's context menu has Rename, also Cmd-R (Ctrl-R) with the collection chosen; the name is kept between launches, and the collection keeps its key. (S7)
- **R39.** Edit, shown when the pointer is to the right of the Collections heading, gives each collection a check box that shows or hides it in the sidebar; Done ends it. A hidden collection comes back into the sidebar when an item is put in it; a shown one stays when it empties. Which are hidden is kept between launches. (S7)
- **R40.** `browser.set_collection` puts items in a collection or takes them out, `browser.clear_collections` takes them out of every one, and `browser.rename_label` and `browser.set_label_shown` (R32) take a collection as well as a label; all are edits, read back in `browser.state`, whose rows name the collections each item is in. (S18)

**Hidden plug-ins and the format preference (IMP-07, WP-6.33)**

- **R41.** A plug-in row's context menu in the browser has Hide Plug-In, or Show Plug-In for a hidden one, acting on every selected plug-in row (Beatlayer's own items, at the end of the menu). A hidden plug-in is remembered by its format and identifier (plugin-scanning R7); hiding acts on every version of the plug-in that shares them. `plugin.hide` hides and shows plug-ins, an edit to preferences read back in `plugin.settings`. (S18)
- **R42.** A hidden plug-in is left out of the Plug-Ins label, its vendor's folder (and a vendor's folder whose plug-ins are all hidden is left out), search, collections, saved labels, the Filter View's tags and hot-swap's lists. A set that uses one still loads it and plays it, and its tags and collections are kept. (S18)
- **R43.** The Content Options menu (R27), while the Plug-Ins label is chosen, has Show Hidden Plug-Ins, unticked in a new install and kept between launches (`plugin.settings`' `show_hidden`; Beatlayer's own place and name). While it's ticked, hidden plug-ins are listed, searched and found again, each row drawn dimmed. (S18)
- **R44.** Settings ▸ Plug-Ins (L-SET-017) has Preferred Plug-In Format, after the Plug-In Sources switches: None in a new install, CLAP, VST3 or, on macOS, Audio Units (Beatlayer's own row and name). With a format chosen, a plug-in that the scanner found in several formats (the same name and vendor, ignoring case) is listed, searched and offered by hot-swap only in that format; with None, in every format. `plugin.settings` sets the preference and sets it back to none. The preference never stops a set from loading a plug-in in another format. (S18)

**Nested collections (IMP-07, WP-6.33)**

- **R45.** A collection holds collections of the person's own inside it, to any depth (Beatlayer's own). New Collection, in a collection's context menu, makes one inside it, named "New Collection" (numbered when the name is taken there), with its name ready to edit. In the sidebar a collection holding others has a fold triangle and lists them under it, indented, in the order made; dragging a nested collection's label onto another collection, or between two, moves it (I-DRAG-056). (S18)
- **R46.** Items go into a nested collection by being dragged onto its label (I-DROP-024), or from the item's context menu, where each collection with nested ones has a submenu listing them. The keys 1 to 7 stay the seven collections' own. A nested collection takes the colour of the collection at its top, and a row in it shows that colour's square (R37). (S18)
- **R47.** Choosing a collection lists the collections nested in it first, as folders that open in place, then the items put in it. Search and filters under a collection cover its nested collections too. A nested collection's context menu has Rename and Delete; deleting one removes it and the collections inside it from the browser, and never touches a file; it asks first when they hold items. (S18)
- **R48.** `browser.add_collection` makes a nested collection, `browser.move_collection` moves it, and `browser.set_collection` (R40) takes a nested collection too; they are edits. `browser.delete_collection` is destructive. Each reads back in `browser.state`, whose labels list the nested collections under their parents. (S18)

### Automatic tags (WP-9.11)

- **R49.** Beatlayer gives items automatic tags, auto tags, in the Function group, which it fills itself beside R7's: plug-ins from the categories their formats declare (CLAP features, VST3 subcategories, Audio Unit types and subtypes, LV2 classes), and samples of 60 seconds or less from their sound ([sound similarity](sound-similarity.md) R1 to R3). (S19, S20)
- **R50.** The Function group's tags are Beatlayer's own list: for instruments Synth, Bass, Keys, Piano, Organ, Strings, Brass, Woodwind, Drums, Percussion and Sampler; for effects EQ, Filter, Dynamics, Distortion, Delay, Reverb, Modulation, Pitch, Spatial, Utility and Analyser; for samples Kick, Snare, Clap, Hi-Hat, Cymbal, Tom, Percussion, Bass, Synth, Pad, Lead, Vocal, FX, Loop and One-Shot. Each format's categories map to these tags by a table kept with the plug-in scanner; a category with no row gives no tag. (S20; the list and the table are Beatlayer's own)
- **R51.** Auto tags are stored with their source, apart from a person's tags: the Tag Editor marks them, and a person can remove an auto tag from an item or make it a tag of their own (R10). An auto tag a person removes is remembered in the database and isn't given again by a rescan or a new analysis. (S20; remembering it is Beatlayer's own)
- **R52.** A person's tag edits never change an item's auto tags, and auto tags never change a person's. (S20)
- **R53.** A sample's auto tags come from Beatlayer's own classifier over its sound description, fitted by a script in the repository from generated, labelled sounds, from a fixed seed, so running the script gives the committed weights; a sample gets a tag only at a confidence of 0.6 or more, and Loop or One-Shot from the loop detector. On Beatlayer's generated set each sample tag is right at least 85 % of the time. A sample's tags are kept with its description, by its content, so a moved or renamed file has them without being analysed again, and a description made by an earlier fit of the classifier is made again. (S20; the classifier and the target are Beatlayer's own)
- **R54.** Auto tags are kept only in the browser's database, never written into files. (Beatlayer's own, as R4)
- **R55.** The Filter View Menu's Include Auto Tags (C-FILTER-004) is on in a new install and ticked while on, and is kept as the Filter View's state between launches. With it off, auto tags neither show in the Filter View nor filter, and `#` search doesn't match them; a person's tags and R7's work as before. (S19, S20)
- **R56.** Auto tags survive a restart, as every tag does (R4). (S20)
- **R57.** `browser.tags` marks each tag on an item `auto` or not; `browser.set_include_auto_tags` (`edit`, a kept setting) names `browser.state` as its readback; removing an auto tag, or making it a person's, runs the tag commands of R10 with the tag named. (S13)
- **R58.** Plug-ins' auto tags are given on each scan and samples' as analysis reaches them; neither makes search or the interface wait. (S20)
