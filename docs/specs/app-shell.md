# The app shell: start-up, sets, the Settings window's Audio page, and the CPU meter

- **Status:** implemented (R1 to R22 each have a passing test)
- **Work packages:** WP-1.7, WP-1.7b (project folders)
- **Parity-matrix row:** Views and workflow: Control Bar, Status Bar; Mixing and routing: CPU meter, disk overload indicator; Interface placement and key bindings
- **Checked against:** Live 12.4.3, through the UI parity reference recorded on 10 October 2026, and the Live 12 reference manual as published that day

## The behaviour

When Beatlayer starts, it shows a new set in the main window: Live's compact title bar, the Control Bar along the top, the browser at the left, the main view, the detail area, and the Status Bar, where Live puts them. A new set opens in the Arrangement View, a deliberate difference from Live (IMP-04, D20). The File menu's New, Open, Save, and Save As work on Beatlayer's set files, asking before unsaved changes are lost. As in Live, a set lives in a project folder: its first save makes a "<name> Project" folder for it where the person points the save dialog, and Save As either joins the project folder it's pointed into or makes a new one. The Settings window opens from the application menu (the Options menu on Windows), its shortcut, or the Control Bar's sample-rate display; its Audio page chooses the driver, the input and output devices, the channels, the sample rate, and the buffer size, and every change applies to the running device at once, and its test section plays a test tone at a chosen level and frequency. The Control Bar's CPU meter shows how much of each buffer's time audio processing takes, and reads OFF while the audio engine is off.

This spec covers the shell's own behaviour. Where each pane and control sits is in [layout.md](../ui-parity/layout.md) (rows L-WIN, L-CTRL, L-STAT, L-SET), the menus are in [menus.md](../ui-parity/menus.md), and the keys are in [shortcuts.toml](../ui-parity/shortcuts.toml); the views inside the panes have their own packages and specs.

## Rules

- **R1.** At start-up and after New Set, the set is the factory default set: two MIDI tracks, two audio tracks, and two return tracks, with an empty undo history (Undo reads "Nothing to Undo"), shown in the Arrangement View. A saved default set, when there is one, is the set New Set and start-up open instead. (S1, S5, S7)
- **R2.** Open Set replaces the set with the file's (a `.blset` file, or a project folder holding one set), exactly as it was saved, with an empty undo history; a file that can't be read changes nothing and the Status Bar says why. (S6)
- **R3.** Save Set saves to the set's file as its next revision, keeping the version it replaces in the project folder's `Backup` folder; a set that has never been saved asks for a file instead, as Save Set As always does, and the set then takes the file's name, in the project folder R17 and R18 choose. (S3, S6, S10)
- **R4.** New Set, Open Set, and Quit ask whether to save unsaved changes first, offering Save, Don't Save, and Cancel. Don't Save before Open Set asks for the file first and throws the changes away only once one is chosen, so cancelling keeps them. An agent's command never asks, so losing work is a command of its own: `set.new` and `app.quit` are destructive and discard; `set.open` refuses while there are unsaved changes; `set.discard_changes` (destructive, the Don't Save choice) returns the set to its last save. The agent API asks the person before destructive commands. (S6)
- **R5.** Cmd-, (Ctrl-, on Windows) opens the Settings window on the page shown last, the Audio page the first time; the pages are listed in Live's order. In the Settings window, Tab and Shift-Tab move between options whatever the Tab setting, Option-Tab (Ctrl-Tab) and Option-Shift-Tab (Ctrl-Shift-Tab) change page, Up and Down change the focused choice, and Esc closes the window. (S1, S2, S3, S4)
- **R6.** A buffer-size change on the Audio page applies to the running device straight away, without a restart. (S2)
- **R7.** A driver, device, sample-rate, or channel change on the Audio page applies straight away; if the device refuses it, the previous settings are reopened and the error shows. A sample rate of 0 (an agent's, or a settings file's, "the device's current rate") opens the device at the rate it runs at then, which `audio.devices` lists: opening a device at a rate sets the device's own rate on Core Audio, and that rate stays after the stream closes, so after a change to 96 kHz, 0 keeps 96 kHz ([architecture](../02-architecture.md), "Audio and MIDI I/O"; [device-changes](device-changes.md) R3). (S2)
- **R8.** Cmd-Option-Shift-E (Ctrl-Alt-Shift-E) switches the audio engine off and on. While it's off, the CPU meter reads OFF and the Status Bar says the engine is off; clicking the message opens the Audio settings. (S1, S3)
- **R9.** The Control Bar's sample-rate display shows the rate the device runs at, and clicking it opens the Audio settings. (S1)
- **R10.** The insert-track keys add a track directly after the selected track, or after the last selected track when several are selected, in the list it belongs to (a group's tracks among their group's tracks, a return among the returns), and select it; with no track selected, after the last one. A track is named for its number and kind ("5 Audio"; returns are lettered, "C Return"). One undo step removes it. (S3, S12)
- **R11.** A key press runs the command the keymap binds for the focused area's context, then `tab-focus` while Use Tab Key to Move Focus is on, then `global`. Tab switches the Session and Arrangement Views while Tab doesn't move the focus; held for half a second or more, it switches back on release. (S3, S4)
- **R12.** Option-0 (Alt-0) moves the keyboard focus to the Control Bar's last-focused control, the browser toggle the first time; Option-2 (Alt-2) to the Arrangement View. (S3, S4)
- **R13.** The Audio page's test section has Live's Test Tone switch, Tone Volume, and Tone Frequency: a sine on every output channel, at -36 dBFS and 440 Hz on a new install, from -60 to 0 dBFS and 20 Hz to 20 kHz, with the level and frequency kept for the next start. The tone stops when the Settings window closes. The audio callback that plays it allocates nothing, takes no lock, and blocks on nothing. (S2, S8)
- **R14.** On macOS the main and Settings windows draw Live's compact title bar, 23 points tall: the system's window buttons centred in it at the left, the set's name (or "Settings") centred; dragging, double-clicking, and the buttons behave as the system's. At 1600 × 1000 points every row anchored to the top sits at layout.md's window coordinates. In full screen there's no title bar. Other platforms keep the system's title bar. (S1, S8)
- **R15.** The menu bar has every item and separator of menus.md in Live's order and words, with Beatlayer's name where Live names its own product ("New Beatlayer Set", "Quit Beatlayer") and the items for Ableton's services and other products left out; a separator left with nothing to separate goes too. (S1, S8)
- **R16.** Cmd-W (Ctrl-W) closes the frontmost secondary window, as File, Close Window does; with only the main window in front it's disabled. A floating device's window is a secondary window: closing it docks the device (device chains R27, WP-2.5b). (S9)
- **R17.** Saving a set that has never been saved, or Save Set As into a folder that isn't a project folder, makes a project folder called "<name> Project" in the folder the person chose and saves the set inside it as `<name>.blset`, where <name> is the name given (a name without the `.blset` extension gets it). The new folder holds just the set: `Backup` appears with the first save that replaces a version, and the `Samples` folders when something is recorded or collected into them. The chosen folder is made if it isn't there. (S10, S11)
- **R18.** A project folder is a folder with a set file directly inside it. Save Set As into a project folder saves the set there under the name given, without a new folder, so the set joins that project; choosing one of its sets replaces that set and keeps its project folder. Save Set (R3) always saves in place. Only the chosen folder is looked at: one with no set in it is outside any project, so Save As into a project's `Samples` folder makes a new project folder there (R17), and a project's `Backup` folder, which holds sets, counts as a project folder. (S10)
- **R19.** Backups stay inside the project folder: the version a save replaces goes to the `Backup` folder of the project folder that holds the set, so nothing is written beside a project folder R17 made, and replacing a set in another project (R18) backs it up in that project. (S11)
- **R20.** If something called "<name> Project" is already in the chosen folder, the new project folder is "<name> Project 2", or the next number that's free, so a save never writes into or over a folder the person didn't choose. A save that fails leaves no new project folder behind.
- **R21.** When Save Set As puts the set in a different project folder, the paths in its media table are re-pointed from the new folder, so the set still uses the same files, in the old project until they're collected. A path that can't be re-pointed (on another drive) stays as it was, and the Status Bar says so. (S10, S11)
- **R22.** The Save Set As dialog opens in the open set's project folder and suggests the set's name, so keeping the suggestion saves into the same project (R18); for a set that has never been saved it opens where the system left it. (S10)
- **R23.** Two read-class queries, on no menu, read back what the set doesn't save. `settings.state` reports every preference the Settings window shows with a value, by page, in the form its own command takes it; tokens and API keys are never returned, only whether one is stored. `view.state` reports what the view commands switch (the main view, the browser, the Info View, full-screen mode, the zoom, the Clip View with Draw Mode, the lane and Fold, the assistant's panel, and whether plug-in windows show) without switching any of it.
