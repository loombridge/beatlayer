# Audio Unit hosting

- **Status:** partial (loading by component description, processing, parameters, state, latency, the scanner's Audio Units, the browser's units, and the unit's own editor are built and tested against Apple's built-in units; per-note expression and MPE, R19 and R20, are built and tested the same way)
- **Work packages:** WP-2.8 (this spec). The plug-in scanner and the browser's plug-ins are WP-2.9's; a unit's own editor windows, the window layer, and the plug-in device panel are WP-2.10's (the AU scanner is part of that package); delay compensation is WP-2.11's; offline renders (export, agents' previews) borrow CLAP instances (WP-2.6b) and units (WP-4.21, built) as [offline plug-in renders](offline-plugin-renders.md) say; VST3 is WP-2.7; per-note expression and MPE are WP-6.17b's (R19 and R20, with [MPE](mpe.md) R14 to R21)
- **Parity-matrix row:** Audio Units v2 and v3 (M2, macOS; built in WP-2.8)
- **Checked against:** Apple's AudioToolbox documentation (`AudioComponent`, `AUAudioUnit`, render blocks, parameter trees, `fullState`, latency), read 15 October 2026; the architecture's "Plug-in hosting" and "Real-time rules"; the CLAP hosting spec, whose rules this mirrors where the formats allow; Live 12.4.6 on macOS, 12 October 2026 (Plug-In Sources lists Use Audio Units v2 and Use Audio Units v3, both Off by default); Apple's built-in units on this machine (macOS 27, Apple silicon)

## The behaviour

An Audio Unit runs as a device in a track's chain, as any device does: in signal order, switched off and on, moved, deleted and brought back with undo, its parameters set by a person, by automation, or by an agent. It has no file: the system finds it by its *component description* — a type, a subtype, and a manufacturer, four characters each — which is the device's `plugin_id`, written `type/subtype/manufacturer` (`aufx/dely/appl` is Apple's AUDelay). `plugin.load_au` loads one by that description, as `plugin.load` loads a CLAP plug-in by path. The scanner lists the units installed on the machine under the browser's Plug-Ins label, with the format preference (WP-2.9, with WP-2.8's second part).

ARA 2 plug-ins are not hosted as Audio Units: [the ARA hosting spec](ara-hosting.md) says why and which formats are.

The unit processes the track's audio block by block: the main thread activates it for the engine's rate, channels, and block size, and its node runs it on the audio thread, with each parameter change and each note on its own frame. Its automatable parameters are the device's parameters: the generic UI, `device.parameters`, and automation see them as they see a native device's. Its own state is saved with the set and comes back when the set is opened again; it reports its latency, which delay compensation (WP-2.11) will use.

A unit's own editor window opens and closes through `plugin.show_window` (R13), and the changes it makes come back into the set as one undo step per gesture (R6), as a CLAP editor's do. Offline renders (export, agents' previews) borrow the units the engine plays (WP-4.21), as they borrow CLAP plug-ins: the unit comes back from the engine's node, is activated for the render's rate and block size, and goes back with the state it had. Audio Units are macOS only: on Windows and Linux the commands say so, and an AU device in a set opened elsewhere is unhosted and passes its input through.

## Rules

- **R1.** `plugin.load_au` finds the Audio Unit whose component description is `type`, `subtype`, and `manufacturer` — four characters each — and offers it as a device type: the description as the device's `plugin_id` (its `format` is Audio Unit), the unit's name, its vendor, and its role from its type — `aufx`, an audio effect; `aumu` or `augn`, an instrument; `aumi`, a MIDI effect — and whether it sends notes on from a MIDI output, which lets it sit in the MIDI-effect position of a MIDI track's chain (IMP-24). A type that is none of those (a format converter or a codec, say), a description no installed unit has, and a unit that won't start are each refused, and nothing changes. The unit chosen is added to the selected track (or `track`), at `index` or where its role goes, selected, as one undo step, Insert Device. On Windows and Linux the command fails, saying Audio Units are only available on macOS. (S1, S2, S5)
- **R2.** A unit device's node passes its input through until the main thread has activated the unit for it (at once when the compiler runs on the main thread, otherwise at the shell's next poll), then runs it on every block: the block's channels into the unit's main input bus (the last channel for more) and the unit's output into the block the same way, the last output channel for more. Activation gives each of the unit's main buses the engine's rate and the channels that bus offers (up to eight), the engine's block size, and allocates its render resources; a unit that refuses a format or won't activate leaves its device passing its input through. An instrument's missing input bus is fine: notes alone drive it. (S1, S2, S5)
- **R3.** A parameter change for a unit device reaches the unit on its exact frame within the block, from the document, automation, or an agent: the node renders the block in segments, split at its parameter changes, and schedules each change through the unit's `scheduleParameterBlock` for the first frame of the segment it starts. A unit may ignore the frame offset of a scheduled parameter event (Apple's AUDelay does), so the split is what puts the change on its frame. Notes and other MIDI are scheduled at their own frames within a segment. (S2, S5)
- **R4.** Notes in a block reach the unit on their frames, scheduled through its own MIDI scheduling at the segment each starts; a unit that takes no MIDI drops them and counts them. The notes a unit sends *out* are taken from the MIDI output it names, each on the frame the unit gives it within the render call, and go on from the node as its notes (IMP-24); a unit that names no MIDI output sends none, and anything but a note or channel message is dropped. (S2)
- **R5.** A unit's parameters are the device's: every parameter of its tree that is readable and writable and has a range, in its order, as a continuous value over its range — with its unit (Hz, dB, %, s, ms, cents, semitones, ratio) where Beatlayer has one — or a whole number when the unit says it's indexed. Its value when the unit was made is the parameter's default. `device.parameters`, the Device View's generic panel, and automation see them, each marked configured or not. Configure mode and the D19 panel are the CLAP hosting spec's R5, which this mirrors: the configured list saved with the device, the Configure switch, adding by moving a parameter in the unit's window, reordering, removing with the warning, the temporary chooser entries, eight knobs over the first eight entries, and `plugin.set_panel_param` remembered per plug-in. A parameter's `ParamId` is its position in the unit's parameter list, in order, because an Audio Unit's own parameter address is 64 bits. (S2, S5, clap-hosting R5)
- **R6.** A change a unit makes itself, such as from its own window, comes back into the set as one undo step per gesture: while its editor is open the host holds the unit's parameter-automation observer, collects each gesture's events, and the main thread turns its final value into one change, as the CLAP host's observer path does; a value outside a gesture is a change of its own. The unit's observer reports a change the host scheduled like any other, so the node notes each value it schedules in a lock-free ring, and the observer leaves out the events that match it: the host's own changes don't come back as the unit's. (S2, S4)
- **R7.** While a unit device is switched off, its parameter changes are kept and set on the unit just before its next block, so it comes back on with them. (S1, S2)
- **R8.** Saving the set takes each running unit's own state into it, with no file (a unit has none: `path` is empty), without an undo step; so does cutting, copying, or duplicating the device, so the copy starts from the state then. The state is `fullStateForDocument`, written as a binary property list and held in the set file in base64 (the state a unit keeps for a *document*, not a preset). A device whose unit isn't running keeps the state it had. (S2, S5)
- **R9.** When a set opens, each AU device's unit is made from its saved description and given its saved state before it's activated. A state the unit refuses leaves it at its defaults, and `plugin.info` says so. (S2, S5)
- **R10.** A unit reports its latency in frames when it's activated (`AUAudioUnit.latency` in seconds at the engine's rate): the node's latency, and `plugin.info`'s, for delay compensation (WP-2.11). A unit whose latency changes is picked up when it's next activated. (S2, S5)
- **R11.** Over a reopened unit's saved state, the set's parameter values are set before it's activated. (S2, S5)
- **R12.** A unit that fails a call doesn't stop the song. One that can't be found or loaded, or refuses to activate, leaves its device passing its input through, keeping its saved state for the next save; one that fails while processing is never called again and its device is silent (as a native device after a panic, real-time rule 6). `plugin.info` reports each. A crash inside a unit ends the app until Phase 10's sandbox. (S1, S2, S5)
- **R13.** `plugin.show_window` opens and closes a unit's own editor in a window of its own, as the CLAP spec's R13 describes: the host asks the unit for its view controller on the main thread — Apple makes it there and delivers it through the run loop, which the host's idle turns — and makes the window when it arrives. The window follows View ▸ Plug-In Windows and Auto-Hide Plug-In Windows (a hidden editor stays open), and opening and closing are not undo steps. A unit that has no editor reports `has_window` false. The window has a close button and no minimise button: when the person closes it, the host closes the editor (`plugin.info` reports `window_open` false) and the next frames don't bring it back. Deleting the device, and letting go of the unit (a new or opened set), close its editor and remove its observer. (S2, S4)
- **R14.** Audio Units are macOS only. On Windows and Linux the `au` module compiles to a stub: `plugin.load_au` fails saying so, the engine's registry offers no AU device types, and an AU device a set carries from a Mac is unhosted — its input passes through, as any device no factory makes does. (S1, S5)
- **R15.** Every unit is held a moment past its last use before its last reference is released. Apple's `AUAudioUnitV2Bridge` rebuilds its parameter tree from an asynchronous CoreAudio event (`AUEventListener`), and a unit released while that event is in flight is deallocated mid-rebuild: a SIGSEGV inside AudioToolbox's `-[AUAudioUnitV2Bridge _createParameterTree]_block_invoke`, recorded on 15 October 2026 while the tests activated and let go of Apple's units in a loop (twice in 175 lifecycles without the grace). A short grace — a quarter of a second, on a thread of the host's own — lets the event finish against a live unit. (S2)
- **R16.** `plugin.load_au`, and `plugin.info` and `plugin.show_window` for an AU device, are the registered commands agents run: `plugin.load_au` is External, like `plugin.load`; `plugin.info` is a read. (S1, S5)
- **R17.** Nothing the node does on the audio thread allocates, locks, or blocks: its buffers are made with the node, and the unit is given its parameter changes and notes through its scheduling blocks, which Apple documents as safe on a render thread; `setValue` on a parameter is called on the main thread only; the unit's own code is its own. A node that fails a call is silent and reports it. (S1, S2)
- **R18.** A control change, pitch bend or channel pressure reaches a unit through its MIDI block as the message's raw bytes (two for channel pressure), scheduled with the notes at its frame ([device framework](device-framework.md) R39). (S6)

**Per-note expression and MPE (WP-6.17b)**

- **R19.** While the device's MPE Mode is off ([MPE](mpe.md) R14, R15), a note's per-note pressure reaches the unit through its MIDI block as polyphonic key pressure on the note's key and channel, scheduled with the notes at its frame; its per-note pitch and slide don't reach it. (S7, S8)
- **R20.** While MPE Mode is on, the unit gets the notes and their expressions as MPE MIDI ([MPE](mpe.md) R17) through its MIDI block, every message scheduled at its frame in the order MPE MIDI lays them out. (S7, S8)
