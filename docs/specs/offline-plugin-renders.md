# Offline renders with plug-ins (WP-2.6b, WP-4.21)

Exports and agents' renders play a set's CLAP, VST3, Audio Unit and LV2 devices through the plug-in instances the live engine plays, so a plug-in device renders as it sounds instead of passing its input through. WP-2.6b built it for CLAP; WP-4.21 made VST3 and Audio Units render the same way, each host lending its instances as [the CLAP host](clap-hosting.md) does. "Plug-in" below means a plug-in of any of the four formats; an Audio Unit is a unit, and exists on macOS only, and an LV2 plug-in on Linux only. LV2 lends differently (R12): an instance's sample rate is fixed when it is made, and LV2 lets its state be saved while it runs, so the render plays a copy made from the engine's plug-in's state and the engine's instance is never taken back. Phase 10 adds two things: a sandboxed plug-in lends its instance through its host (WP-10.4, R13), and exports and agents' renders run on a worker pool made for the render, their output unchanged to the bit (WP-10.13, R14, R15).

## Rules

| Rule | What happens | Test |
|---|---|---|
| R1 | A render of a set with a plug-in device takes a loan of the engine's plug-ins from the host of each format the set holds (`ClapHost::lend`, `Vst3Host::lend`, `AuHost::lend`), one loan for the lot. A set without one borrows nothing and never touches a host or the engine playing. | `bl-shell::offline_plugins an_export_renders_the_plugin_as_the_engine_plays_it`, `a_set_without_a_plugin_renders_without_borrowing_from_the_host`; `bl-shell::offline_vst3_au an_export_renders_the_plugin_as_the_engine_plays_it`, `a_set_with_a_clap_a_vst3_and_an_audio_unit_device_renders_all_three_in_one_export`; `bl-cli::export_plugins bl_cli_export_renders_a_set_with_a_clap_and_a_vst3_plugin`, `bl_cli_export_renders_a_set_with_all_three_formats` |
| R2 | For each lent plug-in, the engine's node hands its processor (a VST3 plug-in's component, an Audio Unit's render block) back at its next block, waiting at most 2 s, and passes its input through until the loan ends. A plug-in not handed back in time fails the render with a clear error rather than exporting pass-through audio. | `bl-plugin-host::offline a_plugin_the_engine_doesnt_hand_back_is_a_problem_for_the_render`; `bl-plugin-host::offline_vst3 a_plugin_the_engine_doesnt_hand_back_is_a_problem_for_the_render`; `bl-plugin-host::offline_au a_unit_the_engine_doesnt_hand_back_is_a_problem_for_the_render` |
| R3 | On the main thread, a lent plug-in is deactivated, its state saved, set to the rendered set's values, and activated for the render's rate and maximum block size. A device with no instance yet (headless `bl-cli export`) gets one from its saved state. | `bl-shell::offline_plugins a_render_at_another_rate_and_block_reactivates_the_plugin_and_gives_it_back`, `bl-plugin-host::offline a_device_without_a_plugin_yet_gets_one_from_its_saved_state`; `bl-shell::offline_vst3_au a_render_at_another_rate_and_block_reactivates_the_plugin_and_gives_it_back`; `bl-plugin-host::offline_vst3 a_device_without_a_plugin_yet_gets_one_from_its_saved_state`; `bl-plugin-host::offline_au a_device_without_a_unit_yet_gets_one_from_its_saved_state`; `bl-cli::export_plugins bl_cli_export_renders_through_the_sets_vst3_plugin`, `bl_cli_export_renders_through_the_sets_audio_unit` |
| R4 | When the loan drops, which happens after the render's engine however the render ends (cancel included), each plug-in returns to the engine. Its pre-render state is reloaded and it is reactivated at the engine's settings. Parameter changes it made during the render are dropped, and an open editor reports none of the render's values as the plug-in's own. | `a_cancelled_export_gives_every_plugin_back`, `bl-plugin-host::offline a_loan_dropped_before_the_renders_node_still_gives_the_plugin_back`, `bl-engine offline::tests::a_dropped_engine_frees_its_nodes_on_the_spot`; `bl-shell::offline_vst3_au a_cancelled_export_gives_every_plugin_back`; `bl-plugin-host::offline_vst3 a_loan_dropped_before_the_renders_node_still_gives_the_plugin_back`, `a_render_node_that_never_ran_gives_the_plugin_back_too`; `bl-plugin-host::offline_au a_loan_dropped_before_the_renders_node_still_gives_the_unit_back` |
| R5 | Renders with plug-ins are exact: bit-identical to the engine's processor, and the same at any block size, run after run. Every render block runs under the allocation trap. | `renders_with_a_plugin_are_the_same_every_time_and_at_any_block_size`, `bl-cli::export_plugins bl_cli_export_renders_through_the_sets_plugin`; `bl-shell::offline_vst3_au renders_with_a_vst3_plugin_or_unit_are_the_same_every_time_and_at_any_block_size` (block sizes 64, 512 and 4,096), `an_export_renders_the_plugin_as_the_engine_plays_it`; `bl-cli::agent_export an_agent_exports_a_set_with_a_vst3_plugin_and_an_audio_unit_by_command` |
| R6 | A plug-in that fails while processing in a render is silent for the rest of the render, and the export completes. In the engine it then stays silent, with a status saying it failed in an offline render, until a state load or a new node clears it. | `a_plugin_that_fails_mid_export_goes_silent_and_the_export_completes`, `bl-plugin-host::offline a_plugin_that_fails_while_rendering_goes_silent_there_and_in_the_engine`; `bl-plugin-host::offline_vst3 a_plugin_that_fails_while_rendering_goes_silent_there_and_in_the_engine` (no Audio Unit on this machine fails on demand; its node shares the silent flag) |
| R7 | `export.audio` stops the transport first and leaves it stopped. | `a_preview_waits_for_the_song_to_stop_and_an_export_stops_it`; `bl-shell::offline_vst3_au a_preview_renders_the_plugin_and_waits_for_the_song_to_stop` |
| R8 | `perception.preview`, and `perception.analyze` over a range, are refused (`Unavailable`, telling the agent to run `transport.stop`) while the transport plays a set with a plug-in device of a format the render borrows. Without one, previews render during playback as before, off the main thread where the app host can. | `a_preview_waits_for_the_song_to_stop_and_an_export_stops_it`; `bl-shell::offline_vst3_au a_preview_renders_the_plugin_and_waits_for_the_song_to_stop` |
| R9 | `PluginStatus::active_for` reports the rate and block size a plug-in is active for, in each format's host. | `a_render_at_another_rate_and_block_reactivates_the_plugin_and_gives_it_back` in `bl-shell::offline_plugins` and `bl-shell::offline_vst3_au`; `bl-plugin-host::offline_vst3 a_lent_plugin_renders_at_the_renders_settings_and_goes_back_as_it_was`; `bl-plugin-host::offline_au a_lent_unit_renders_at_the_renders_settings_and_goes_back_as_it_was` |
| R10 | Plug-in kit plug-ins compiled in as native devices render offline through their own instances, made from the set's values; nothing is borrowed from the engine. | `an_export_renders_a_kit_device_and_stays_off_the_heap`, `renders_with_a_kit_device_are_the_same_every_time_and_at_any_block_size` |
| R11 | VST3 and Audio Unit devices render offline as CLAP devices do (R1 to R9 hold for the three formats): an export, an agent's preview or analysis, and a freeze or bounce play them through the engine's instances, not passed through. On Windows and Linux an Audio Unit device is unhosted, and passes its input through. | `bl-shell::offline_vst3_au an_export_renders_the_plugin_as_the_engine_plays_it`, `a_set_with_a_clap_a_vst3_and_an_audio_unit_device_renders_all_three_in_one_export`; `bl-cli::export_plugins bl_cli_export_renders_through_the_sets_vst3_plugin`, `bl_cli_export_renders_through_the_sets_audio_unit` |
| R12 | An LV2 device renders through a copy of the plug-in made for the render (`Lv2Host::lend`): a new instance at the render's rate and block size, started from the state the engine's plug-in has now (else the set's saved state) with the rendered set's parameter values over it. The engine's instance is not taken back, so R2's wait and R6's failure have no LV2 form: the engine keeps playing through a render, nothing the render does to the copy reaches the engine's plug-in or the set (R4), and the copy is freed once the render's node has let go of it, however the render ends. A plug-in that can't be made leaves its node passing its input through. The copy starts from the latency the engine's plug-in last reported, and a render follows the latency changes its plug-ins report as the engine does ([delay compensation](delay-compensation.md) R6). R1, R3, R5 and R9 hold. | `bl-plugin-host::offline_lv2 a_lent_plugin_renders_at_the_renders_settings_and_the_engine_never_stops`, `a_loan_dropped_before_the_renders_node_leaves_the_engine_playing`, `a_render_node_that_never_ran_gives_its_copy_back_too`, `a_device_without_a_plugin_yet_gets_one_from_its_saved_state`; `bl-shell::plugins_lv2 an_export_renders_the_lv2_plugin_and_the_engines_one_is_untouched` (blocks of 64, 512 and 4,096 are bit-identical); `bl-plugin-host::engine_lv2 a_lent_lv2_plugin_renders_with_its_latency_compensated`; `bl-engine::pdc an_offline_render_follows_a_latency_reported_after_the_first_block` |
| R13 | A plug-in that runs in a `beatlayer-host` process ([the plug-in sandbox](plugin-sandbox.md)) is lent through a request on its host's control channel: the host deactivates the instance, activates it for the render's rate and largest block, and processes the render's blocks through the instance's slot on a thread of its own, outside real time; when the loan drops, the host restores it as R4 says. R1 to R6 and R9 hold; an LV2 plug-in's copy (R12) is made in the host. A host that crashes during a render makes its plug-ins silent for the rest of the render, as R6 says of a failure, and the export completes. (WP-10.4) | to be written in WP-10.4 (an export of a set with sandboxed plug-ins equals its real-time render at three block sizes) |
| R14 | An export, a freeze, a bounce and an agent's preview or analysis render on a pool of workers made for the render (`Offline::with_workers`), sized by the machine's performance cores, and give exactly the samples the one-thread render gives, at any block size and any number of workers, plug-ins included. (WP-10.13) | to be written in WP-10.13 (the golden fixtures and the 128-track set exported with 0, 1, 3 and 7 workers) |
| R15 | A render's pool is made when the render starts and stopped when it ends, however it ends; it never shares workers with the engine playing. (WP-10.13) | to be written in WP-10.13 |
