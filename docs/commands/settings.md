### `settings.set_auto_hide_plug_in_windows`

**Auto-Hide Plug-In Windows**. Permission: `edit`. Contexts: `settings`.

Switches Auto-Hide Plug-In Windows, on the Settings window's Plug-Ins page; it's on in a new install, as Live's is. While it's on, a floating device's window or a plug-in's editor window hides while another track is selected and comes back when its own track is selected again, as Live's plug-in windows do. A hidden window's device still floats, and a hidden editor stays open: hiding isn't docking or closing, isn't an undo step, and the set saves the device as floating. `device.windows` and `plugin.info` say which windows show. The setting is kept for the next start, and isn't part of the set. The result's `on` is the setting afterwards.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `on` | boolean | yes | Whether the setting is on. |

Result: [`SwitchResult`](README.md#switchresult).

### `settings.set_auto_warp_long_samples`

**Auto-Warp Long Samples**. Permission: `edit`. Contexts: `settings`.

While it's on, a new audio clip of a long sample, one of 60 seconds or more, is warped with a warp marker on the first beat of every bar its analysis finds, and its 1.1.1 on the first beat; off, it is left unwarped. Clips already in the set keep their settings. The setting is kept for the next start, and isn't part of the set or an undo step. The result's `on` is the setting afterwards.

Result: [`SwitchResult`](README.md#switchresult).

A Session recording is unaffected. The mode is kept for the next start, and isn't part of the set or an undo step.

### `settings.set_continuous_save`

**Save Continuously**. Permission: `edit`. Contexts: `settings`.

Turns Save Continuously on or off (it starts off). When on, every finished edit of a set that has a file is saved within a second, so reopening the set shows it without asking, and each edit is a save point in the set's history since its last normal save. Turning it on saves the open set's unsaved edits that way. When off, edits are still journalled for crash recovery, and only Save keeps them. Save still writes the set file either way.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `on` | boolean | yes | Whether Save Continuously is on. |

Result: [`ContinuousSave`](README.md#continuoussave).

**Takeover Mode**. Permission: `edit`. Contexts: `settings`.

Chooses Takeover Mode on the Settings window's Tempo & MIDI page: what an absolute MIDI controller mapped to a continuous control does when its value and the control's differ. `none` (the default) sets the control to the controller's value at once, `pick_up` changes nothing until the controller reaches the control's value and then follows it, and `value_scaling` moves the control and the controller towards each other as the controller moves, so both reach the end of the range together. It applies to every mapping of every set. The setting is kept for the next start, and isn't part of the set or an undo step.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `mode` | [`TakeoverMode`](README.md#takeovermode) | yes | `none`, `pick_up` or `value_scaling`. |

Result: nothing (`null`).

### `settings.set_temporary_folder`

**Temporary Folder**. Permission: `external`. Contexts: `settings`.

Chooses the Temporary Folder on the Settings window's File & Folder page: where the files Reverse, Crop, Consolidate, Freeze and Bounce write go while the set has never been saved (the first save moves them into the project's `Samples/Processed` folders). `path` is an absolute path, made when it is first needed, or `null` for the default, a `Temporary` folder in Beatlayer's application-data folder. Files already written stay where they are. Run by a person from the Browse button without a `path`, it asks for a folder. The setting is kept for the next start, and isn't part of the set or an undo step. The result's `path` is the folder in use afterwards. Names a folder outside the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string or null | no | The folder's absolute path, or `null` for the default: a `Temporary` folder in Beatlayer's application-data folder. |

Result: [`TemporaryFolderResult`](README.md#temporaryfolderresult).

### `settings.set_theme`

The choice is kept for the next start, and a theme that can't be read is drawn as Beatlayer. Changes nothing in the set.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `theme` | string | yes | A theme's name, as `settings.state`'s `theme_colors.themes` lists it. `dark` and `light`, which earlier versions took, set the Appearance instead. |

Result: nothing (`null`).

### `settings.set_user_library`

**User Library**. Permission: `external`. Contexts: `settings`.

Chooses the User Library's folder on the Settings window's Library page. `path` is an absolute path, or `null` for the default. The folder becomes the User Library at once: its starting folders (Clips, Defaults, Grooves, Presets, Samples, Tunings) are made in it if it has none, and it is indexed in the background. Nothing is moved from the folder before. Run by a person from the Browse button without a `path`, it asks for a folder. The setting is kept for the next start, and isn't part of the set or an undo step. The result's `path` is the User Library in use afterwards. Names folders outside the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|

### `settings.set_warp_recorded_audio`

**Warp Recorded Audio**. Permission: `edit`. Contexts: `settings`.

Switches Warp recorded audio, on the Settings window's Record, Warp & Launch page, a Beatlayer addition (IMP-02); it's on in a new install, as Live warps its recordings. Clips have no warp settings yet, so for now recorded clips play at their file's own speed whether it's on or off; warping will read the setting for the clips a recording makes. The setting is kept for the next start, and isn't part of the set or an undo step. The result's `on` is the setting afterwards.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `on` | boolean | yes | Whether the setting is on. |

Result: [`SwitchResult`](README.md#switchresult).

### `settings.state`

**Settings State**. Permission: `read`. Contexts: `global`.

Reports every preference the Settings window shows with a value, by page, in the form its own command takes it: Theme & Colors (`settings.set_theme`), Display & Input (zoom, Outline View in Focus, the Tab key settings), the audio device settings with Driver Error Compensation and the test tone (`audio.configure`, `audio.set_test_tone`), the MIDI ports and computer keyboard (`midi.set_port`), Takeover Mode (`settings.set_takeover_mode`), Create Fades on Clip Edges, Warp Recorded Audio, the Launch section, the automation recording mode (`settings.set_automation_record_mode`), the File & Folder page's Temporary Folder, sample editor and Save Continuously (`settings.set_temporary_folder`, `settings.set_sample_editor` and `settings.set_continuous_save`), Auto-Hide Plug-In Windows, the plug-ins the Browser hides and prefers (`plugin.settings`), the agent server and the assistant. The server's and the agents' tokens and the assistant's API key are never reported, only whether one is stored. Preferences aren't saved with the set. Changes nothing. Use it to check a `settings.set_*` command took effect.

Default keys: none.

Arguments: none (send `{}`).

Result: [`SettingsState`](#settingsstate).
