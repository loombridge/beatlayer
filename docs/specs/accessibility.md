## The behaviour

Live 12 can be used without a mouse and with a screen reader. Each area of the window takes the keyboard focus from the Navigate menu or its Option-digit key (Alt-digit on Windows): the Control Bar, the Session and Arrangement Views, the browser, and the others. Inside an area, the arrow keys move the selection the way the area's own keys do (between tracks in the Arrangement, between labels and results in the browser). With Use Tab Key to Move Focus on (Display & Input, or the Navigate menu), Tab and Shift-Tab move between the area's controls; in the Session and Arrangement mixers they move through one track's mixer controls, and Option-Tab (Ctrl-Tab) moves to the same control on the next track, Option-Shift-Tab to the previous one; Esc goes back from a track's control to its title bar. In the Session View, Tab stays within one track's strip, from its title bar through its clip slot, In/Out, sends, and mixer controls; in the Arrangement it runs through the view, with the selected track's header in the middle. Wrap Tab Navigation, on in a new install, makes Tab go round from the last control to the first; off, Tab stays on the last. Navigate's Next Neighbor and Previous Neighbor move the focus to the same control on the next or previous track whenever there's one, leaving the selection. On Windows, Alt and a menu's letter opens the menu. Outline View in Focus, on in a new install, draws a light border round the view in focus and outlines the focused control.

Beatlayer does the same for every M1 view, through AccessKit (decision D8): each control is in the accessibility tree with a role, a name, and a value, which VoiceOver, NVDA, and Orca read; the tree's focus follows the keyboard focus, and in the Arrangement, where the arrow keys move the selection rather than the focus, the selected clip or track is the view's active descendant, so a screen reader reads it as it moves. Every command a person can run has a key, a menu item, or a control the keyboard reaches; the few that don't are listed below with the reason.

This spec covers the baseline across the M1 views: what the tree gives a screen reader for tracks, clips, and faders; how the keyboard focus moves between and inside areas; the keyboard settings on the Display & Input page; menus and context menus from the keyboard; and the keyboard path of every registered command. The keys each view reads itself are in that view's spec; the shortcuts are in [shortcuts.toml](../ui-parity/shortcuts.toml).

## Rules

- **R1.** The accessibility tree gives a screen reader, for each M1 view: the window's areas as named regions (the Control Bar a toolbar, the browser, the Info View, the Device View, and the Status Bar groups, the main view a pane named for the view in front); each track's title in the Arrangement's headers as a row header named for the track (`3 Audio`), described by its kind and number (`Audio track 3`, `, folded` when folded); each clip on screen as a list item named for the clip (`Audio Clip` or `MIDI Clip` when it has no name), its value where it plays in bars (`3.1.1 to 7.1.1`, `, deactivated` when it is) and whether it's selected; each mixer column as a group named for its track; volume as a slider named `Track Volume` whose value is the volume in dB as the Status Bar shows it while the fader moves (`0.0 dB`, `-6.0 dB`, `-inf dB`), its number the dB, with increment and decrement; pan as a slider named `Track Pan` (`Main Pan` on Main), valued `C`, `25L`, `50R`; each send named by its return track (`A Return`); the browser's search field as `Search Field`; and every switch as a button with its name and `on` or `off`. A control another package brings is disabled and says which. (S7, S8, S9; the names a control already had, from [mixer-view](mixer-view.md) R15, [arrangement-view](arrangement-view.md) R3, [arrangement-editing](arrangement-editing.md) R15, [browser](browser.md) R17, [control-bar-transport](control-bar-transport.md) R11)
- **R2.** The tree's focus is the control with the keyboard focus. While the Arrangement View itself (or a track's title bar) has it, where the arrow keys move the selection rather than the focus (S-A11Y-003, S-ARR-028), the view's active descendant is the first selected clip on screen or, with no clip selected, the selected track's title, so a screen reader reads the clip or the track's name as the keys select it. In a mixer, Navigate ▸ Mixer's focus is on the column, read as its track's name. (S1, S2, S8)
- **R3.** With Use Tab Key to Move Focus on (off in a new install), Tab and Shift-Tab (`focus.next`, `focus.previous`) move between the controls of the area with the focus, in the order they're drawn: the Control Bar's working controls (not its meters and indicators), the Status Bar's, and the browser's search field, sidebar, and content pane, moving the browser's own focus with them so each part's keys apply (`focus.browser`). With nothing focused in the area, Tab goes to its first control and Shift-Tab to its last. They do the same from a text field or a value field that takes typed values. The Settings window keeps its own order (app-shell R5). (S1, S2, S4, S9)
- **R4.** In the main view, Tab follows Live 12.4.6's orders, without the controls Beatlayer doesn't have yet:
  - **The Arrangement** runs through the view: the selected track's header (its title bar, Input Type, Input Channel, Monitoring, Output Type, Output Channel, Track Activator, Solo, Arm Recording, Track Volume, Track Pan, and the sends, since WP-2.19), then Optimize Height and Optimize Width, and with Wrap on round to the header's title bar. Live's locator and automation buttons before the header, its waveform zoom controls before Optimize Height, and the loop brace's two ends and the Clip/Device Drop Area after Optimize Width come when Beatlayer has them as controls. From the view, the first Tab goes to the first of these; from another track's header (after a neighbour move) Tab moves through that track's header. With no track selected, the first track's header.
  - **A mixer strip** (the Session View's, and the Arrangement's mixer once Navigate ▸ Mixer has put the focus there): Tab stays within the track, from its title bar (which the column stands for) through Input Type, Input Channel, Monitoring, Output Type, Output Channel, the sends, Peak Level, Track Pan, Track Activator, Solo, Arm Recording, and Track Volume (the In/Out controls and sends since WP-2.19); a MIDI track without an instrument has its title bar, its In/Out controls, and its switches. The clip slot and Clip Stop come with M3. From the Session View, the first Tab goes into the selected track's strip (the first track's) past its title bar. Esc from a Session strip's control goes to the track's title bar.
  - **The neighbour commands** (`focus.next_neighbor`, `focus.previous_neighbor`: Navigate ▸ Next Neighbor and Previous Neighbor, and Option-Tab and Option-Shift-Tab, Ctrl-Tab and Ctrl-Shift-Tab on Windows and Linux, while Tab moves the focus) move the focus to the same control on the next or previous track that has it, in the mixer's track order (the returns and Main last), skipping tracks without it, bringing the track into view if it's scrolled away, and leaving the selected track as it was; from the view itself they start at the selected track's title bar. The menu items are enabled whenever the track with the focus (or, with none, the selected track) has a neighbour that way, whatever the Tab setting.
  - **Esc** from a track's control in the Arrangement goes back to the track's title bar (`arrangement.focus_title_bar`, S-ARR-034), with the view focused and the title bar selected; from the header's volume field it does so when nothing has been typed, and drops a typed value otherwise.

  (S1, S2, S4, S9)
- **R5.** At the end of an area, the Arrangement's order, or a track's strip, Tab goes round to the first control, and Shift-Tab from the first to the last, while Wrap Tab Navigation is on, as it is in a new install (`focus.toggle_wrap_navigation`: Navigate ▸ Wrap Keyboard Navigation, ticked while on, and the Display & Input switch); while it's off, they stay where they are. Where Beatlayer draws its own menu bar (Linux), Alt and a menu's letter (S-MENU-001) opens the menu with its first item that can be chosen focused; Up and Down move through its items in order, skipping disabled ones, Enter chooses one, and Esc closes the menu; while any menu is open its keys go to it, not to shortcuts. (S1, S4, S5, S9)
- **R6.** The Settings window's Display & Input page has, after Display's Language and Zoom, the Display Options section (Outline View in Focus, Show Scroll Bars, Follow Behavior, Hide Labels) and the Navigation and Keyboard section (Use Tab Key to Move Focus, Wrap Tab Navigation, Move Clips With Arrow Keys), in L-SET-010's order and words. Outline View in Focus (On), Use Tab Key to Move Focus (Off), and Wrap Tab Navigation (On) are On/Off switches, each reached with Tab and switched with Enter. The other four keep their places, disabled, saying a later package brings them, with their controls and Live's new-install values: Show Scroll Bars a chooser showing Follow System, Follow Behavior and Hide Labels buttons showing Scroll and Show, Move Clips With Arrow Keys a switch showing On. (S3, S6, S9)
- **R7.** Outline View in Focus (`settings.set_outline_view_in_focus`) is on in a new install, as in Live 12.4.6: a border is drawn round the area with the focus (the Control Bar, the browser, the main view, the detail area, or the Status Bar), and the focused control is outlined. While it's off, nothing in the main window shows where the keyboard focus is. The look is Beatlayer's own; the setting is kept between launches. (S3, S9)
- **R8.** Every registered command has a keyboard path: a key (a bound shortcut, or a focused control's key that the keymap names with the command), a menu item, or a control the keyboard reaches with Tab and runs with Enter, the arrows, or typing; or it's one of the exceptions listed under "Commands without a keyboard path of their own", with its reason. The focused item's context menu opens from the keyboard (S-CTX-002: Shift-F10 on Windows and Linux, Ctrl-Option-Shift-M on macOS): in the Arrangement View, the selected clips' menu, or with none the time selection's, at the clip or the insert marker; in the Arrangement with the title bars selected, the selected track's menu (C-TRACK), and over the Session View and the mixers the same for the focused track's column ([the track header's context menu](track-context-menu.md), R9); in the browser's sidebar, the chosen place's; its first item that can be chosen is focused, and Up and Down move through its items as R5's menus. The Menu key can't be read through Beatlayer's toolkit yet, so on Windows and Linux only Shift-F10 opens it. (S1, S2, S4, S8, S9)
- **R9.** Options ▸ Solo in Place runs `mixer.set_solo_in_place` with the other state, ticked while it's on (on in a new set), as one undo step. Options ▸ Accessibility's five items are in Live's order and words, disabled until a package builds what they change. (S5, S9; [mixer](mixer.md) R16)
- **R10.** In the Arrangement, Tab first reaches the controls above the track headers, in Live 12.4.6's order, before the selected track's header (R4): Set Locator (named Delete Locator while a locator is selected), Previous Locator, Next Locator, then the set's locators in time order, then Automation Mode and Lock Envelopes. Enter presses a button or switches a switch ([time-editing.md](time-editing.md) R3, R4, R6; [automation.md](automation.md) R13; [automation-editing.md](automation-editing.md) R8). Tab reaching a locator selects it, Enter jumps to it and Delete deletes it ([time-editing.md](time-editing.md) R12); where the locators come in the order is Beatlayer's own. A locator added from the keyboard takes the focus ([time-editing.md](time-editing.md) R3). With Wrap Tab Navigation on, Tab from the order's last control goes round to Set Locator. This puts in place R4's controls before the header that Beatlayer didn't yet have. (S1, S9, S10)

## Commands without a keyboard path of their own

The test of R8 walks the whole registry. A command is reached by a key, a menu item, or a keyboard-reachable control, or it's listed here. The test fails for any command that is neither, and for one listed here that has since gained a path.

**Controls the keyboard reaches** (each checked by tabbing to it and pressing its key): Play, Stop, and Arrangement Loop in the Control Bar (`transport.play`, `transport.stop`, `transport.set_loop_enabled`); a track's Solo and Arm Recording (`mixer.solo_exclusive`, `mixer.arm_exclusive`); the browser's Search Field (`browser.search`); and in the Settings window Agent Server, New Token, each agent's Autonomous switch, Forget, and New Token (`agent.set_server`, `agent.new_token`, `agent.set_autonomous`, `agent.forget_client`, `agent.new_client_token`), Buffer Size and the Audio page's other choosers (`audio.configure`), Test Tone (`audio.set_test_tone`), Theme (`settings.set_theme`), Create Fades on Clip Edges, Auto-Hide Plug-In Windows (`settings.set_auto_hide_plug_in_windows`, WP-2.5b), Outline View in Focus, and Zoom; and in the assistant pane (D24), reached with Tab once the pane has the focus, Float Assistant (`assistant.toggle_floating`), Stop Assistant (`assistant.stop`, while a turn runs), the pane's width edge with Left and Right (`assistant.set_panel_width`), and the prompt field, which sends with Enter or its Send button (`assistant.send`, listed in the test as an equivalent path: sending needs a message, so no one key does it).

**The Shortcuts page's own commands** (the custom shortcuts spec, R8 and R10): `keymap.unbind` and `keymap.reset` are the page's Remove and Reset buttons, which the keyboard reaches with Tab and Enter; `keymap.bind` takes the key press that becomes the shortcut, so its keyboard path is the shortcut itself, and `keymap.state` is a query for agents.

**Queries for agents** (a person reads the same on screen): `arrangement.state`, `browser.state`, `mixer_view.state`, `transport.state`, `audio.status`, `audio.devices`, `set.list_recoverable`, `device.windows` (WP-2.5b), `keymap.state` (the custom shortcuts spec, R14).

**For agents only**, with no person's form and no Live feature behind them: agent perception's `perception.preview`, `perception.analyze`, and `perception.capture_view` (how an agent hears and sees the set).

**An agent's form of a gesture or a dialog**, whose keyboard path is another command or the system's dialog: `arrangement.move_clips` (Left and Right nudge, cut and paste), `arrangement.select_clips` (Shift with the arrows, Cmd-A), `arrangement.scroll` (the view follows the tracks the keys select and Follow; the zoom keys), `arrangement.show_range` and `arrangement.show_track` (the zoom keys; the view follows the selected track), `mixer_view.scroll` (Navigate ▸ Mixer, Left and Right, and the neighbour keys bring the focused column into view), `browser.add_to_arrangement` (Enter, `browser.load_selected`), `browser.stop_preview` (selecting a folder, or switching Browser File Preview off), `set.discard_changes` (the save-changes dialog's Don't Save), `agent.approve_client` (the Allow button of the system dialog an agent's first connection opens), `device.set_window` (moving or resizing a floating device's window, which the system's window keys and commands do; WP-2.5b), `midi.import_file` and `midi.export_clip` (the Create menu's Import Audio/MIDI File... and the File menu's Export MIDI Clip... dialogs, which the file dialogs wait on; WP-2.21), and `clip.create`, `clip.delete`, `clip.move`, `clip.move_by`, `clip.set_length`, `clip.trim_start` (run by the Arrangement's editing keys: paste, Delete, Left and Right, and Enter then Left or Right).

**Views of later milestones**: the Clip View's (`clip.set_gain`, `clip.set_loop`, `clip.set_loop_enabled`, `clip.set_region`, `clip.set_data`, and its note editor's `note.add`) and the Device View's (`device.insert`, `device.move`, `device.set_enabled`, `device.set_param`) in M2, and the automation edits (`automation.set_breakpoint`, `automation.set_curve`, `automation.move_breakpoint`, `automation.delete_breakpoint`, `automation.delete`, `automation.re_enable_for`) in the Arrangement's automation lanes, which WP-2.12's second part draws; the Control Bar's Re-Enable Automation button (`automation.re_enable`) is live since WP-2.12's first part. (The sends' knobs and the returns' Pre/Post switches, `mixer.set_send` and `mixer.set_send_tap`, and the In/Out controls, `routing.*`, are keyboard-reachable since WP-2.19, and a device's sidechain strip and section, `device.show_sidechain` and `device.set_sidechain_*`, since WP-2.19b: Enter on its buttons, Up and Down on its Source chooser and number boxes.; and a device's expand toggle, `device.expand`, since WP-5.42: Tab to Expand, Enter.)

**Live's own exception**: `clip.set_fades`. Live doesn't support editing audio clip fades with a screen reader (S2, 41.4.1.3); its fade keys, Cmd-Option-F and Cmd-Option-Delete (S-ARR-008, S-ARR-009), aren't bound yet.

**Without a key of their own**: `mixer.set_crossfader` and `mixer.set_crossfade_assign`. Their controls are reached with the pointer, and the keyboard reaches them too (Tab to an A or B button and Enter assigns or releases, and Main's crossfader is a slider) ([mixer-view](mixer-view.md) R15, R16; WP-3.17).

**The Export Audio/Video dialog** (WP-6.71): its controls (`export.set_choices`, `export.start`, `export.close_dialog`) and the export's progress window (`export.cancel`) are in the Tab order, and Return and Esc act in them ([export](export.md) R28, R45).

1. `track.move`: moving tracks with Cmd and the arrows (S-TRACK-012) isn't bound.
2. `set.recover` and `set.discard_recovery`: the app doesn't show the recovery prompt at launch yet ([crash-recovery](crash-recovery.md)).
3. `settings.set_continuous_save`: the Save Continuously switch on File & Folder isn't drawn yet ([crash-recovery](crash-recovery.md) R11).
4. `device.load_sample`: loading a sample into the sampler has no key or menu item yet ([sampler](sampler.md) R11); dropping the file on the sampler's Device View frame is the only way.

**Gaps in the multisampler** ([multisampler](multisampler.md), WP-5.13; its header buttons, layer rows and Sample tab fields are in the Device View's Tab order, so `device.set_multisampler_view`, `device.hot_swap_layer`, `device.select_layers`, `device.set_layer` and `device.set_layer_options` are reached with the keyboard):

5. `device.add_layers`: adding samples is a drop of files on the zone editor (R3); the keyboard has no way to name files yet.
6. `device.set_layer_zone`: dragging a zone's edge, body or fade has no keyboard form yet (R10).

8. `device.delete_layers`, `device.duplicate_layers`, `device.rename_layer`, `device.sort_layers`, `device.distribute_layers` and `device.normalize_layers`: the layer list's context menu isn't opened from the keyboard (R11); the Delete key deletes the selected device.
9. `device.move_layers`: no control moves layers by hand yet; the list's sorts reorder it (R11).

**Gaps in sample editing** ([multisampler](multisampler.md), WP-5.15):

10. `device.edit_sample`, `device.crop_sample` and `device.reverse_sample`: the sample display's context menu isn't opened from the keyboard (R55, R59).
11. `device.audition_sample`: a click on the sample display has no keyboard form yet (R54).

**Gaps in rack presets** ([racks](racks.md), WP-5.8):

13. `chain.save_preset`: a chain's row is saved by dragging it into the browser (R46), which has no keyboard form yet.

## Screen readers: the manual test

The tests above read the tree AccessKit hands the platform; whether each platform's screen reader reads it as intended needs a person with the reader on each platform. Run each script on a release build with a new set (the factory default set, in the Arrangement), Use Tab Key to Move Focus switched on in Settings ▸ Display & Input, and note anything read wrongly, read twice, or not read.

**Set up before each run:** drag an audio file from the browser onto 3 Audio, then rename the clip "Kick" (select it, Cmd-R or Ctrl-R, type, Return).

**VoiceOver (macOS 26):** turn VoiceOver on (Cmd-F5).

1. Press Option-2. VoiceOver reads "Arrangement View".
2. Press Down three times. It reads "1 MIDI", "2 MIDI", "3 Audio" (row headers), each with "Audio track 3" or the like as its description.
3. Press Cmd-A, which selects every clip. It reads "Kick", its bars ("3.1.1 to 7.1.1", or wherever it landed), and that it's selected.
4. Press Up, then Down, so 3 Audio is the selected track, then Tab. It reads "3 Audio" (the title bar). Tab again: "Track Activator, on", "Solo, off", "Arm Recording, off", "Track Volume, 0.0 dB, slider", "Track Pan, C, slider", then Optimize Height and Optimize Width, then round to "3 Audio".
5. On Track Volume, press Down twice. It reads "-1.0 dB", "-2.0 dB". Press Delete: "0.0 dB". Adjust it with VoiceOver's own slider commands: each step changes it by 1 dB, and VoiceOver reads the new value.
6. Press Option-Tab. It reads 4 Audio's "Track Volume", and 3 Audio stays selected. Option-Shift-Tab: back to 3 Audio's. Navigate ▸ Next Neighbor does the same.
7. Press Esc. Focus returns to the Arrangement; VoiceOver reads "3 Audio".
8. Press Option-Shift-M (Navigate ▸ Mixer). It reads "3 Audio" (the mixer column, a group). Tab: "Peak Level", "Track Pan", "Track Activator", "Solo", "Arm Recording", "Track Volume", then round to "3 Audio". Then show the Session View (its view selector, or View ▸ Toggle Arrangement/Session View), select 3 Audio's strip, and Tab: the same strip order; Esc from Track Volume reads "3 Audio".
9. Press Option-0. It reads the Control Bar's first control. Tab through it; each control is read with its name and value (Tempo "120.00", the position fields, Play, Stop, Arrangement Loop).
10. Press Cmd-F. It reads "Search Field". Type "kick": the results follow. Tab: the sidebar; Tab: the list; Down: each file's name and kind.
11. Open the menu bar (VO-M) and the Navigate menu: each item and its key is read; Next Neighbor is enabled now that Tab moves the focus.
12. With the clip selected and the Arrangement focused, press VO-Shift-M: if VoiceOver opens Beatlayer's clip menu, Up and Down read its items. (AccessKit doesn't pass VoiceOver's menu action on yet; the key Beatlayer reads, Ctrl-Option-Shift-M, works with VoiceOver off.)
13. Cmd-, then Tab through Settings ▸ Display & Input: "Outline View in Focus, On", "Use Tab Key to Move Focus, On" (switched on for the test), "Wrap Tab Navigation, On"; the pending rows read their values (Follow System, Scroll, Show, On).

**NVDA (Windows 11):** start NVDA (Ctrl-Alt-N). Repeat steps 1 to 10 and 13 with Alt for Option and Ctrl for Cmd (Alt-2, Ctrl-Tab for Option-Tab, Alt-Shift-M, Alt-0, Ctrl-F, Ctrl-,), in focus mode (NVDA-Space if browse mode turns on). In step 5, NVDA's own slider adjustment (if it offers one in focus mode) steps it by 1 dB; the arrows do too. Step 11: Alt-N opens the Navigate menu (Windows' own menu bar); NVDA reads each item. Step 12: Shift-F10 opens the clip's menu with its first item read.

**Orca (Ubuntu 24.04 or later, GNOME, X11 or Wayland):** start Orca (Super-Alt-S). Repeat the NVDA steps. Step 11: Alt-N opens Beatlayer's own menu bar's Navigate menu with "Control Bar Alt+0" read; Down skips the disabled items; Enter chooses; Esc closes. Step 12: Shift-F10.

Record the reader's version, the platform's, and Beatlayer's commit with the results.
