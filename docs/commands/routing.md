## Commands

### `routing.set_cue_out`

**Set Cue Out**. Permission: `edit`. Contexts: `session`, `arrangement`.

Sets Main's Cue Out, the audio interface's output channels the cue mix goes to, as Main's In/Out section does: `channel` is a stereo pair of the interface's outputs, counted from 1; the default is the first pair, 1/2. It carries the cue mix once cue mode is built (a later package); the choice is kept and saved with the set.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `channel` | [`Channel`](README.md#channel) | yes | The pair: its first channel, counted from 1. |

Result: [`ChangeSet`](README.md#changeset).

### `routing.set_input`

**Set Input**. Permission: `edit`. Contexts: `session`, `arrangement`.

Sets where an audio or MIDI track takes its input from, as the In/Out section's Audio From or MIDI From chooser and its channel do. An audio track can take `external` (Ext. In, the audio interface's inputs, with a `channel`: a single channel (`{ "type": "mono", "channel": 3 }`) or a stereo pair (`{ "type": "pair", "channel": 3 }`, the pair 3/4), counted from 1), `resampling` (the Main output, for recording the mix; the track's own output and sends are then silent so it can't feed back), `none`, or `track` with another audio track, a group, a return track, or Main and a `tap`: `pre_fx` (before its devices), `post_fx` (after its devices, before its mixer), or `post_mixer` (its output, the default). A MIDI track can take `all_ins` (every MIDI input whose Track switch is on in the settings, and the computer MIDI keyboard), `computer_keyboard`, `port` with the port's `name` as the MIDI settings list it, `none`, or another MIDI track (which carries MIDI once MIDI playback is built). `channel` is 1 to 16 to take only that channel, or null (the default) for All Channels; only a port input has one. The input is heard only while the track monitors it (`routing.set_monitor`). A routing may make a loop, as in Live; the engine plays the routing that closes it as silence.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `track` | [`TrackId`](README.md#trackid) | yes | The track. |
| `input` | [`Input`](README.md#input) | yes | The input. |
| `channel` | integer or null | no | The MIDI channel to take, 1 to 16, or `null` (or nothing) for All Channels. Only a MIDI port input has a channel. |

Result: [`ChangeSet`](README.md#changeset).

### `routing.set_main_out`

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `channel` | [`Channel`](README.md#channel) | yes | The pair: its first channel, counted from 1 (`{ "type": "pair", "channel": 3 }` is 3/4). |

Result: [`ChangeSet`](README.md#changeset).

### `routing.set_midi_output`

**Set MIDI Output**. Permission: `edit`. Contexts: `session`, `arrangement`.

Sets where a MIDI track's MIDI goes, as its MIDI To chooser does: another MIDI track (give its ID; it arrives at its Track In), an output port (`{ "name": "Synth", "channel": 1 }`: the port's name as `midi.ports` lists it, with its Track switch on, and the channel to send on, 1 to 16), or `null` for No Output (a new MIDI track's). A track sends to a port the notes and controller, pitch bend and pressure messages that reach the end of its device chain (a track with an instrument sends none, the instrument playing them), at the moment their frame is heard at the audio interface's output; it keeps a missing port's name and sends again when the port returns. Choosing a port takes channel 1.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `track` | [`TrackId`](README.md#trackid) | yes | The MIDI track. |
| `to` | [`MidiTo`](README.md#midito) or null | no | Another MIDI track (its ID), an output port with its channel (`{ "name": "Synth", "channel": 1 }`), or `null` (or nothing) for No Output. |

Result: [`ChangeSet`](README.md#changeset).

### `routing.set_monitor`

**Set Monitor**. Permission: `edit`. Contexts: `session`, `arrangement`.

Sets an audio or MIDI track's Monitor switch: `in` always plays the track's input through its devices and silences its clips, `auto` plays the input while the track is armed, and `off` never plays it. A new track is `auto`. Use `in` to hear another track routed into this one.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `track` | [`TrackId`](README.md#trackid) | yes | The track. |
| `monitor` | [`Monitor`](README.md#monitor) | yes | `in`, `auto`, or `off`. |

Result: [`ChangeSet`](README.md#changeset).

### `routing.set_output`

**Set Output**. Permission: `edit`. Contexts: `session`, `arrangement`.

Sets where a track's audio goes, as the In/Out section's Audio To chooser does: `default` (Main, or the group the track is in), `main` (Main, even from inside a group), `track` with another audio track (its input, heard while that track monitors it) or the track's own group, `sends_only` (only through its sends to the return tracks), or `external` (Ext. Out: the track plays on the audio interface's output channels, a single channel or a stereo pair, the first pair by default, and not into Main). Audio, group, and return tracks take any of these. A routing may make a loop, as in Live; the engine then plays the routing that closes the loop as silence.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `track` | [`TrackId`](README.md#trackid) | yes | The track. |
| `output` | [`Output`](README.md#output) | yes | The output. |

Result: [`ChangeSet`](README.md#changeset).
