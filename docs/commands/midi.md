## Commands

### `midi.capture`

**Capture MIDI**. Permission: `edit`. Contexts: `global`.

Capture MIDI (Create ▸ Capture MIDI; the Control Bar's button). Brings back the notes played on the MIDI tracks that monitor their input, since the last capture or recording, as one clip on each track that was played, with their velocities and timing. A track with a clip playing while the transport runs gets the notes added to that clip: it grows to the loop pass the last note falls in and its loop moves there, keeping its length. Any other track gets a new clip in the selected scene's slot if it is empty, else the next empty slot below, else a scene added at the end; the clip's loop is the whole bars that cover its last phrase, from the first note-on to the last. With the transport stopped the first note is on 1.1.1 and the song's tempo may change to the played tempo; with it running the tempo stays. Control changes, pitch bend and pressure are not captured yet. Refused when no note was played; `transport.state` shows `capture_midi_ready`. One undo step.

Default keys: none.

Arguments: none (send `{}`).

Result: [`Captured`](README.md#captured).

### `midi.computer_keyboard_key`

**Computer Keyboard Key**. Permission: `read`. Contexts: `global`.

Presses or releases one of the computer MIDI keyboard's note keys, as typing it does: a press sends a note-on at the keyboard's velocity on MIDI channel 1, a release the note-off of the note that key started, even if the octave moved meanwhile. The notes reach the tracks whose MIDI From is Computer Keyboard or All Ins. A press fails while the keyboard is off. Changes nothing in the set.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `key` | string | yes | The note key's letter: A W S E D F T G Y H U J K O L P, from the lowest note up. |
| `pressed` | boolean | yes | Whether the key goes down (the note starts) or comes up (it ends). |

Result: [`KeyboardKeyResult`](README.md#keyboardkeyresult).

### `midi.computer_keyboard_octave`

**Computer Keyboard Octave**. Permission: `read`. Contexts: `global`.

Moves the computer MIDI keyboard's octave by `steps`, as Z (down) and X (up) do: 12 semitones a step, from C-2 to C8 for the A key, stopping at the ends. Notes already held keep sounding until their keys come up. Works whether or not the keyboard is on. Changes nothing in the set.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `steps` | integer from -16 to 16 | yes | The steps to move: -1 for down (Z, C), 1 for up (X, V). Any number of steps is allowed; it stops at the ends of the range. |

Result: [`KeyboardInfo`](README.md#keyboardinfo).

### `midi.computer_keyboard_velocity`

**Computer Keyboard Velocity**. Permission: `read`. Contexts: `global`.

Steps the computer MIDI keyboard's velocity by `steps` through 1, 20, 40, 60, 80, 100, 120, and 127, as C (lower) and V (raise) do, stopping at the ends. It starts at 100. Works whether or not the keyboard is on. Changes nothing in the set.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `steps` | integer from -16 to 16 | yes | The steps to move: -1 for down (Z, C), 1 for up (X, V). Any number of steps is allowed; it stops at the ends of the range. |

Result: [`KeyboardInfo`](README.md#keyboardinfo).

### `midi.export_clip`

**Export MIDI Clip**. Permission: `external`. Contexts: `global`.

Writes a MIDI clip's notes as a type 1 Standard MIDI File at `path`, as the File menu's Export MIDI Clip does: its notes' pitches, starts, lengths and velocities, its tempo (the song's tempo where the clip starts) and its time signature. Fails for an audio clip, or for a file already at `path` unless `replace` is true. With no `path` the app asks where to save the file (as the clip menus' Export MIDI Clip... does), and runs this again with it; a key or the File menu's item gives no `clip` and exports the selected clip. Writes a file outside the project; changes nothing in the set.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-FILE-008 | `Cmd+Shift+E` | `Ctrl+Shift+E` | `global` | Export the selected MIDI clip as a MIDI file | runs it |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `clip` | [`ClipId`](README.md#clipid) | yes | The MIDI clip to write. |
| `path` | string or null | no | The file to write, absolute or relative to the app's working directory. Its folder must exist. `.mid` or `.midi` by convention. Left out, the app asks where to save the file, as the clip menus' Export MIDI Clip... does, and then runs this again with the path. |
| `replace` | boolean | no | Replace a file already at `path`. Without it, an existing file is left alone and the export refused. |

Result: [`MidiExportResult`](README.md#midiexportresult).

### `midi.import_file`

**Import MIDI File**. Permission: `external`. Contexts: `global`.

Reads a Standard MIDI File (type 0 or type 1) into the Arrangement, as dragging it in or the Create menu's Import MIDI File does: each of the file's tracks that has notes becomes a MIDI clip. With no `track`, each becomes a new MIDI track below the last one, named as a new track is; with a `track`, the file's one track with notes goes on that MIDI track. Clips start at `at`, or the insert marker. Each clip keeps the file's leading silence, is named after its track's name (or `Track N`), carries the file's time signature, loops its whole length, and lasts from its first note to its last note-off rounded up to a whole bar. With `import_tempo`, the file's tempo and time signature come into the song as Live's "Import tempo and time signature data into Arrangement?" answer Yes does: a single-tempo file sets the song's tempo, a file whose tempo changes writes Song Tempo automation over the clip and restores the tempo at its end, and a time-signature marker is written at the clip's start and one restoring the previous signature at its end. Off (the default), the song's tempo, automation and markers are left alone. A clip placed over part of another replaces that part, so a track never plays two clips at once; when a clip on `track` ends after `at`, it's destructive as well as external. One undo step. Reads a file outside the project.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | The Standard MIDI File to read, absolute or relative to the app's working directory. Its type 0 or type 1 tracks become clips. |
| `at` | [`Ticks`](README.md#ticks) or null | no | Where the first clip starts, in ticks (705,600 to the quarter note). Left out, the Arrangement's insert marker. |
| `import_tempo` | boolean | no | Whether to bring the file's tempo and time signature into the song, as Live's "Import tempo and time signature data into Arrangement?" asks. Off unless given, so an agent never changes the song's tempo by accident. |
| `track` | [`TrackId`](README.md#trackid) or null | no | The MIDI track to put the file's clips on. Left out, each track of the file with notes gets a new MIDI track below the last one. |

Result: [`MidiImportResult`](README.md#midiimportresult).

### `midi.ports`

**MIDI Ports**. Permission: `read`. Contexts: `global`.

Lists every MIDI input and output port the computer offers, each with its Track, Sync, Remote and MPE switches as the Settings window's Tempo & MIDI page shows them, with each port's MIDI Clock Sync Delay, MIDI Clock Type and Hardware Resync, the computer MIDI keyboard's state, and whether Show Resync Button is on. Changes nothing.

Default keys: none.

Arguments: none (send `{}`).

Result: [`MidiPortsResult`](README.md#midiportsresult).

### `midi.set_port`

**Set MIDI Port**. Permission: `external`. Contexts: `global`.

Changes a MIDI port's Track, Sync, Remote and MPE switches, as the Settings window's MIDI ports table does; switches left out stay as they are. A port is open while its Track, Sync or Remote switch is on and closed when all three are off; MPE opens nothing by itself. An input's notes and controllers reach tracks only while its Track switch is on, and as MPE, each note on a channel of its own with its own pitch, slide and pressure, while its MPE switch is on too; an input with Remote on feeds the set's MIDI mappings, and a message one takes never reaches a track (`remote.mappings`). An output with Sync on gets MIDI clock, Start, Continue, Stop and Song Position Pointer while the song plays, whatever its Track switch, stamped for the moment each is heard: `sync_delay_ms` (-100 to 100) moves them earlier or later, `clock_type` is Song (Song Position Pointer and Continue whenever the play position changes) or Pattern (only Start, at the next bar line), and `hardware_resync` is what Resync External Hardware sends it: Stop and Start, Start Only or Don't Resync. Those three are kept while Sync is off; `clock_type` and `hardware_resync` are refused on an input. An input with Sync on follows what its `sync_type` says: `midi_clock` (its Timing Clock, Start, Continue, Stop and Song Position Pointer) or `midi_timecode` (its quarter frames and full frames, which locate, start and stop the song without changing its tempo); with `midi_timecode`, `timecode_rate` (`fps_24`, `fps_25`, `fps_29_97_drop`, `fps_30` or `smpte_all`, which takes each time at the rate its message names) and `timecode_offset` (`hh:mm:ss:ff`, the time at which the Arrangement starts) apply. Those three are kept while the type is clock, and are refused on an output, which never sends timecode. An output's Remote is kept and acts when it's built. Output ports have no MPE switch, and `mpe` on one is refused. The port's switches are kept for the next start, and aren't part of the set or an undo step. Opens or closes a device outside Beatlayer. Fails if the computer doesn't offer the port now.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `direction` | [`PortDirection`](README.md#portdirection) | yes | Input or output. |
| `name` | string | yes | The port's name, as `midi.ports` lists it. |
| `clock_type` | [`ClockTypeChoice`](README.md#clocktypechoice) or null | no | An output's MIDI Clock Type. Left out, it stays as it is. |
| `hardware_resync` | [`HardwareResyncChoice`](README.md#hardwareresyncchoice) or null | no | An output's Hardware Resync. Left out, it stays as it is. |
| `mpe` | boolean or null | no | MPE on or off, for an input. Left out, it stays as it is. |
| `remote` | boolean or null | no | Remote on or off. Left out, it stays as it is. |
| `sync` | boolean or null | no | Sync on or off. Left out, it stays as it is. |
| `sync_delay_ms` | integer or null | no | MIDI Clock Sync Delay in milliseconds, from -100 to 100. Left out, it stays as it is. |
| `sync_type` | [`SyncTypeChoice`](README.md#synctypechoice) or null | no | An input's MIDI Sync Type. Left out, it stays as it is. |
| `timecode_offset` | string or null | no | An input's MIDI Timecode Offset as `hh:mm:ss:ff`: hours below 24, minutes and seconds below 60, frames below 30. Left out, it stays as it is. |
| `timecode_rate` | [`TimecodeRateChoice`](README.md#timecoderatechoice) or null | no | An input's MIDI Timecode Frame Rate. Left out, it stays as it is. |
| `track` | boolean or null | no | Track on or off. Left out, it stays as it is. |

Result: [`PortInfo`](README.md#portinfo).

### `midi.set_show_resync_button`

**Show Resync Button**. Permission: `edit`. Contexts: `global`.

Sets Show Resync Button, the switch on the second section of Settings ▸ Tempo & MIDI, to `on`, or to the other state if it's left out. While it's on, the Control Bar shows the Resync External Hardware button. It starts off, is kept for the next start, and isn't part of the set or an undo step.

Default keys: none.

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `on` | boolean or null | no | Show the button or hide it. Left out, it switches to the other state. |

Result: [`SetShowResyncButtonResult`](README.md#setshowresyncbuttonresult).

### `midi.toggle_computer_keyboard`

**Computer MIDI Keyboard**. Permission: `edit`. Contexts: `global`.

Switches the computer MIDI keyboard, as the Control Bar's switch and M do, to `on`, or to the other state if it's left out. While it's on, the letter keys play notes (A W S E D F T G Y H U J K O L P) to the tracks whose MIDI From is Computer Keyboard or All Ins; Z and X move its octave, C and V its velocity, and the letters it uses don't run their shortcuts unless Shift is held. Switching it off ends every note it holds. Whether it's on is kept for the next start, and isn't part of the set or an undo step.

Default keys:

| Shortcut | macOS | Windows | Context | Action in the reference | Binding |
|---|---|---|---|---|---|
| S-MAP-003 | `M` | `M` | `global` | Turn the computer MIDI keyboard on or off | runs it |

Arguments:

| Name | Type | Required | Description |
|---|---|---|---|
| `on` | boolean or null | no | Switch it on or off. Left out, it switches to the other state. |

Result: [`KeyboardInfo`](README.md#keyboardinfo).
