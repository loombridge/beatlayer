# 05. Improvements over Live

Beatlayer matches Live 12 first ([decision D16](02-architecture.md#decisions-log)). This page holds the improvements on top: things Live users ask for that Beatlayer can do better without making them relearn anything. Each improvement has an ID, its effect on parity, the proposed approach, and the package that builds it.

## Rules for improvements

1. **Add; don't move.** An improvement never moves something a Live user already knows. It adds a setting, a menu item beside its relatives, a wider parameter range, or a choice.
2. **A changed default is an option.** If an improvement changes a default or a placement, it ships as an option that defaults to Live's behaviour, unless it's accepted as a deliberate difference, recorded in the architecture's design rules.
3. **New things go where Live users would look.** A new setting goes in the Settings tab where Live keeps related settings. A new command goes next to the commands it relates to, in the same menus.
4. **Agents reach it too.** Every improvement is a registered command or setting, reachable through the agent API (D17).

## General rules from these proposals

Three proposals point at rules that apply everywhere, not only to the device or feature they name:

| Rule | Statement | From | Enforced in |
|---|---|---|---|
| G1 | Every gain and level parameter reaches −∞ dB (silence). | IMP-08 | The device framework's parameter descriptors (WP-2.5); a test checks every gain parameter |
| G2 | Every parameter a user can set, on devices, clips, mixers, and warp modes, can be automated and modulated. | IMP-09 | The device framework (WP-2.5) and automation (WP-2.12); a test checks every parameter has an automation target |
| G3 | Bounces and exports keep the channel count of their source unless the user chooses otherwise. | IMP-10 | Bounce and export (WP-1.12, WP-4.15) |

## Adding an improvement

Add a row with the next ID, its effect on parity, and its approach. If it changes a default or a placement, say so in its status. When it's accepted, add it to the package that builds it in [the build plan](03-build-plan.md).
